## 全局铁律（本指令最高优先级）

### 铁律 A：链接双轨制——图谱防环的根本机制

整个知识库只有**一种情况**可以使用 `[[...]]` 双括号：

> `> 📂 所属：[[父MOC名称]]`

其余所有位置——正文引用、MOC 导航、前置知识、上下游依赖、跨领域关联、表格中的链接——一律使用：

> `<a href="obsidian://open?file=文件名">显示文字</a>`

**为什么**：Obsidian 图谱视图中，`[[...]]` 产生边，`obsidian://open` 不产生边。全库只有叶子→父节点的 `📂 所属` 边，图谱天然是一棵向根汇聚的树，**物理上不可能成环**。

| 优先级 | 链接方向 | 允许格式 | 图谱可见 |
|--------|----------|----------|----------|
| **P0 强制** | 叶子 → 父 MOC（`📂 所属`） | `[[...]]` | ✅ 可见 |
| **P1 推荐** | 同 MOC 子节点间（单向，有前后置依赖） | `obsidian://open` | ❌ 不可见 |
| **P2 允许** | 跨 MOC 叶子间（单向，有实质技术依赖） | `obsidian://open` | ❌ 不可见 |
| **P3 严禁** | 同级双向环（A↔B 无上下游关系） | 任何格式都禁止 | — |

**图模式判定表**：

| 模式 | 示意 | 判定 |
|------|------|------|
| 星型拓扑 | `笔记 → MOC ← 笔记` | ✅ 核心结构 |
| 单向依赖链 | `A → B → C`（同 MOC，有前后置） | ✅ 允许（用 obsidian://open） |
| 跨学科纵深链 | `XD-0 → XD-1 → … → XD-8` | ✅ 特例（单向线性） |
| 跨域桥接 | `笔记(MOC-A) → 笔记(MOC-B)`（单向有据） | ⚠️ 受控（用 obsidian://open） |
| 团状双向环 | `A ↔ B` 或 `A→B→C→A` | ❌ 严禁 |

### 铁律 B：知识体系隔离

- 每篇笔记 YAML 中必须声明 `知识体系` 字段，严格按照 `03_Knowledge/技术划分.md` 填写（格式：`技术栈 → L? 层级名`）。
- Java/C++/前端/数据库各有自己的技术体系，不可混用。
- 跨体系关联仅放在"跨学科溯源"中，沿 XD-0~XD-8 轴追溯。

### 铁律 C：版本标注

- YAML 中必须声明 `技术版本` 字段。
- 所有代码示例必须在标注版本下可运行。
- 跨学科知识点不受版本约束。

## 执行工作流（逐文件扫描 → 逐项修复 → 输出报告）

对 `$1` 范围内的每个 `.md` 文件，按以下顺序逐项检查并自动修复：

### 第一步：链接格式扫描与修复（最高优先级）

用正则 `\[\[([^\]]+)\]\]` 搜索文件中所有 `[[...]]` 双括号链接。

**判定规则**：
- 若该行包含 `📂 所属` → **保留不动**
- 若该行**不包含** `📂 所属` → **全部替换**为 `<a href="obsidian://open?file=文件名">显示文字</a>` 格式：
  - `[[文件名]]` → `<a href="obsidian://open?file=文件名">文件名</a>`
  - `[[文件名|显示文字]]` → `<a href="obsidian://open?file=文件名">显示文字</a>`

### 第二步：图谱防环检查

检查是否存在以下成环风险：

1. **双向互链**：两篇同级笔记的 `📂 所属` 指向同一父 MOC，但它们之间互相用 `[[...]]` 引用 → 改为 `obsidian://open` 格式
2. **跨级直链**：孙子笔记的 `📂 所属` 跳过了父 MOC 直接指向祖父 → 修正为指向直接父 MOC
3. **MOC 同级互链**：两个兄弟 MOC 之间互相引用 → 拆除 `[[...]]`，改为 `obsidian://open` 或纯文本

### 第三步：YAML Frontmatter 完整性检查

检查每篇笔记是否包含以下必填字段，缺失则补充：

| 字段 | 缺失时的处理 |
|------|-------------|
| `aliases` | 根据标题自动生成 1-2 个别名 |
| `tags` | 补充 `status/进行中` 和 `type/笔记`（MOC 则补 `type/MOC`）；按内容推断领域标签 |
| `created` | 若文件有创建日期则填入，否则用当前日期 |
| `updated` | 当前日期 |
| `知识体系` | 按 `03_Knowledge/技术划分.md` 和文件所在目录推断层级，格式 `技术栈 → L? 层级名` |
| `技术版本` | 按文件内容推断（如 Java 17、Spring Boot 3.x、Vue 3.4）；无法推断则标注 `"待确认"` |

### 第四步：命名规范检查

- 文件名是否使用短横线命名法（非下划线、非驼峰、非空格）
- MOC 文件是否以 `MOC - ` 开头
- 如有不符 → 使用 `mv` 重命名，并**同步更新所有引用该文件的其他笔记中的链接**

### 第五步：标签规范检查

- 标签是否使用 YAML 列表格式（不带 `#`）
- 是否有 `status/*` 标签
- 是否有 `type/*` 标签
- 领域标签是否与 `技术划分.md` 一致
- 不符则修正

### 第六步：MOC 完整性检查

- 检查目标目录下 `.md` 笔记数量（排除 MOC 文件自身和 `技术划分.md`）
- 若 ≥ 5 且无 MOC → **自动创建 MOC**（先分子文件夹整理物理目录，再按标准格式生成）
- 若 ≥ 5 且已有 MOC → **更新 MOC**（增补新增笔记、更新标签统计、刷新目录结构树）
- MOC 必须包含：目录结构树、分板块笔记列表、推荐学习路径、跨领域关联表、标签使用统计

### 第七步：`📂 所属` 完整性检查

- 每篇叶子笔记底部必须有 `> 📂 所属：[[父MOC名称]]`
- 每个 MOC 底部必须有 `> 📂 所属：[[父MOC名称]]`（知识库总览除外）
- `📂 所属` 指向的父节点必须与当前拓扑结构一致
- 缺失或错误则修正
