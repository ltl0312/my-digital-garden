## 概述（Overview）
> 与企业内部标准化的软件开发流程不同，个人或小型团队在网上接单（外包）是一门将技术能力变现的手艺。接单的最大痛点往往不是技术实现，而是**"客户中途改需求"和"尾款收不回来"**。

本指南覆盖从"打造接单门面"到"售后维保"的完整 8 阶段实战框架，核心命题是：**如何在缺乏企业背书和法务支持的情况下，安全地完成软件交付并拿到全款**。

## 设计初衷（Motivation）

### 历史演进
- **前身模式**：威客时代（2000s 猪八戒网模式）——平台充当中间人抽成，开发者低价竞标，"几百块做个网站"的恶性竞争导致"劣币驱逐良币"
- **为什么前身被淘汰**：威客平台的低价竞标模式让专业开发者无法靠合理报价生存；平台抽成（10%-20%）进一步压缩利润；需求方和开发者之间缺乏直接信任，纠纷频发
- **本模式的突破**：垂直技术社区（V2EX/程序员客栈）+ 开源项目引流 + 熟人社群，跳过了低价竞标的恶性循环。核心突破是**从"卖时间"升级为"卖解决方案"**——客户不是为你的代码买单，而是为你的技术判断力（架构选型、需求梳理、风险预判）买单
- **为什么这个模式可持续**：软件定制市场的本质是信息不对称——客户不懂技术，真正需要的是有人帮他把模糊的想法翻译成可执行的方案。只要这个翻译能力存在，接单就不会被 AI 完全取代
- **当前阶段**：2024-2026 接单市场特点：AI 辅助编程大幅降低开发时间→报价模型需要调整；经济下行期企业外包预算收紧→筛选优质客户比以往更重要

### 设计思想
接单的本质矛盾：**客户为"结果"付费，但开发者靠"过程"赚钱**。客户只在看到可运行的产品后才愿意付钱，但开发者已经在过程中投入了大量时间。这套全流程框架的设计哲学是：

1. **信任前置**：在写一行代码前，用作品集、GitHub、Docker 部署能力证明你是正规军
2. **边界锁定**：在写一行代码前，用功能清单和白纸黑字的合同锁死需求边界
3. **现金流保护**：定金→进度款→尾款的"3-4-3"付款节奏，确保任何阶段客户跑路你都不会白干
4. **代码即筹码**：尾款到账前不交源码、不交数据库权限、不部署到客户服务器，让代码成为你收款的最后保障

## 实现（Implementation）

### 完整实例：以一个校园社交小程序接单项目为例

#### 阶段一：打造"接单门面"与能力背书
客户凭什么把项目交给你？在没有任何信任基础的互联网上，**作品就是最好的简历**。

- **沉淀线上作品集**：准备一个绑定个人专属域名的在线展示空间。将你独立开发并成功跑在云服务器上的全栈项目（如社交互动平台、个人数字知识库或健康管理系统等）展示出来
- **突出核心技术栈**：清晰标明你擅长的技术体系（如前端 Vue 3、后端 Spring Boot、数据库 MySQL/Redis）
- **展示工程化能力**：除了业务功能，向客户强调代码质量和部署规范（如提供完整的 GitHub 仓库链接、强调支持 Docker 容器化一键部署）。这会让你看起来像个正规军，而不是拼凑代码的业余玩家

#### 阶段二：寻找渠道与筛选项目
**不要什么单子都接，筛选优质客户是成功的一半。**

1. **接单渠道获取**：
   - **接单平台**：程序员客栈、码市、开源中国众包、V2EX 的外包节点、Upwork（适合英语好的开发者赚取汇率差）
   - **熟人转介绍**：通常是最靠谱的渠道，信任度高，沟通成本低
   - **开源社区引流**：维护一些高质量的开源项目，经常会有企业主主动找上门求定制
2. **避坑"毒"项目**：
   - 拒绝"需求一句话（如：做一个类似淘宝的 App），预算几千块"的客户
   - 拒绝不愿意付定金、要求"先做出来看看"的客户
   - 尽量接与你现有技术栈高度契合的项目，避免在接单过程中现学现卖，导致周期失控

#### 阶段三：需求拉齐与报价
**这是决定这个项目是赚钱还是亏本（亏时间）的关键。** 详见 <a href="obsidian://open?file=接单需求界定与报价风控">接单需求界定与报价风控</a>。

#### 阶段四：预付款（定金）机制
**绝对不要在收到定金前写一行代码！** 详见 <a href="obsidian://open?file=接单需求界定与报价风控">接单需求界定与报价风控</a>。

#### 阶段五：高效开发与阶段性汇报
孤军奋战时，效率就是金钱。

1. **利用工具提效**：充分利用 AI 辅助编程工具来快速生成样板代码、排查框架配置错误或编写测试用例
2. **定期同步进度**：每隔几天给客户发一张截图或录一段短视频，展示当前进度。这能极大缓解客户的焦虑，建立信任

> **💡 补充**：定期同步的本质是"信号传递"。客户不懂代码，看不到进度就会焦虑，焦虑就会打电话、改需求、催交付。一张截图 = "我还活着，项目在推进"，这是比代码更有效的客户管理手段。

#### 阶段六：部署演示与验收 — 防骗指南
**这是保护自己劳动成果的最后一道防线。** 详见 <a href="obsidian://open?file=接单交付安全与防骗机制">接单交付安全与防骗机制</a>。

#### 阶段七：尾款结算与交付上线
详见 <a href="obsidian://open?file=接单交付安全与防骗机制">接单交付安全与防骗机制</a>。

#### 阶段八：售后与维保
- **免费维保期**：通常合同中会约定 1 个月到 3 个月的免费维保期，仅限**修复原有功能的 Bug**
- **收费维护**：维保期结束后，如果客户需要服务器日常巡检、数据备份或开发新功能，则需要签订新的维护合同或按次收费

> **💡 补充**：维保期最容易出现的纠纷是"这个功能不好用，你帮我改一下"——但"不好用"不等于 Bug。验收时客户签字确认过的功能，维保期内只修"实际运行结果与功能清单描述不符"的问题。体验层面的"不好用"属于新需求。
