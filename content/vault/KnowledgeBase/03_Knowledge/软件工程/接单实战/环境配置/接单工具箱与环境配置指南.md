## 前置条件
- 一台云服务器（阿里云/腾讯云，最低 2C2G，¥50-100/月）
- 一个已备案域名（演示用，¥50-80/年）
- 微信/支付宝收款账户（个人收款 vs. 个体工商户对公账户）

## Step 1: 作品集搭建（接单门面）

### 方案一：GitHub Pages（免费，推荐）
```bash
# 1. 创建 GitHub 仓库：yourname.github.io
# 2. 使用 Vue 3 + Vite 搭建个人站
npm create vite@latest my-portfolio -- --template vue-ts
cd my-portfolio
npm install

# 3. 部署到 GitHub Pages
npm run build
# 将 dist/ 推送到 gh-pages 分支
npx gh-pages -d dist
# 访问：https://yourname.github.io
```

### 方案二：云服务器 + 自有域名（更专业）
```bash
# 将个人站部署到你的云服务器
scp -r dist/* root@your-server:/var/www/portfolio/
# 配合 Nginx + SSL（参考 多端部署-运维环境配置指南）
```

### 作品集必备内容清单
- [ ] 3-5 个完整项目展示（含截图 + 技术栈 + 在线 Demo 链接）
- [ ] GitHub 仓库链接（展示代码质量和提交规范）
- [ ] 技术栈清单（前端/后端/数据库/运维）
- [ ] Docker 化部署展示（不是必须但极大加分）
- [ ] 联系方式（微信/邮箱，建议用专业邮箱而非 QQ 邮箱）

## Step 2: 需求管理工具

| 工具 | 用途 | 推荐理由 |
|------|------|----------|
| **Notion** | 功能清单整理、项目文档 | 灵活的数据块，可导出 PDF 作为合同附件 |
| **Figma** | 黑白线框图绘制 | 免费版即可满足接单原型需求 |
| **Excel / Google Sheets** | 功能清单表格（最推荐） | 客户最容易理解，可逐行打勾确认 |
| **ProcessOn** | 流程图绘制 | 国内免费在线工具 |

> **💡 推荐组合**：Excel（功能清单 + 报价明细）+ Figma（关键页面的线框图）+ Notion（项目全部文档汇总）。客户不需要学新工具，Excel 谁都打得开。

## Step 4: 开发与演示环境

### 本地开发环境
与正式项目开发完全一致（前端 Vite + 后端 IDEA/Spring Boot + 数据库 Docker），不赘述。

### 测试演示服务器配置
```bash
# 为每个接单项目创建独立子域名和目录
# 示例：项目 my-client-app 的测试环境

# 1. DNS 添加 A 记录
# demo-myclient.yourdomain.com → 你的服务器 IP

# 2. Nginx 配置
server {
    server_name demo-myclient.yourdomain.com;
    location / {
        proxy_pass http://localhost:18080;  # 项目专用端口
    }
}

# 3. Docker Compose 启动项目（端口隔离）
# 每个项目用不同端口：18080, 18081, 18082...
docker-compose -p my-client-app up -d

# 4. 给客户测试 URL
# https://demo-myclient.yourdomain.com
# 只给客户浏览器访问权限，不给 SSH / 数据库权限
```

## Step 5: 交付物打包标准

```bash
# 标准交付物清单（尾款到账后执行）

# 1. 后端镜像打包
docker save myapp-backend:latest | gzip > delivery/backend.tar.gz

# 2. 前端构建产物
npm run build
cp -r dist/ delivery/frontend/

# 3. 数据库初始化脚本
mysqldump --no-data -u root -p myapp > delivery/init.sql

# 4. Docker Compose 部署文件（一键启动）
# delivery/docker-compose.yml

# 5. 操作手册
# delivery/操作手册.md（含启动/停止/备份/常见问题）

# 6. 源码（最后一步）
git archive --format=zip HEAD > delivery/source.zip

# 最终交付包结构：
# delivery/
# ├── backend.tar.gz
# ├── frontend/
# ├── init.sql
# ├── docker-compose.yml
# ├── 操作手册.md
# └── source.zip
```

## 常见安装/配置问题

1. **客户没有服务器怎么办？**
   → 你可以提供代购 + 部署服务（额外收费）。使用你自己的云服务器账号为每个客户创建独立实例，按月向客户收取服务器费用 + 运维服务费。这其实是最好的模式——你控制了服务器，后续维护收入就有了保障。

2. **客户要求部署到他们已有的服务器？**
   → 尾款到账前拒绝。到账后，如果客户服务器环境与你不同（如 Windows Server vs. Linux），Docker 化交付可以有效隔离环境差异。

3. **域名备案太慢，演示怎么办？**
   → 先用 IP:端口 方式演示（如 `http://123.456.78.9:18080`），告知客户这是临时测试地址，正式上线会使用正式域名。
