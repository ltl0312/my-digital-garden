## Step 1: 多项目隔离的测试服务器架构

接单通常同时进行 1-3 个项目。每个项目需要独立测试环境，互不干扰。

```bash
# 服务器端口规划（建议）
# 项目A: 端口 18080-18089
# 项目B: 端口 18090-18099
# 项目C: 端口 18100-18109

# 项目目录结构
/opt/demo-projects/
├── project-a/
│   ├── docker-compose.yml
│   ├── nginx.conf
│   └── data/
├── project-b/
│   ├── docker-compose.yml
│   ├── nginx.conf
│   └── data/
└── project-c/
    ├── docker-compose.yml
    ├── nginx.conf
    └── data/
```

### 为每个项目创建子域名

```bash
# DNS 添加 A 记录（通配符最方便）
# *.demo.yourdomain.com → 你的服务器 IP

# Nginx 反向代理（统一入口，自动路由）
# /etc/nginx/sites-available/demo-projects
```

```nginx
# /etc/nginx/sites-available/demo-projects
# 通配子域名反向代理，自动将 demo-xxx.yourdomain.com → 对应端口

server {
    listen 80;
    server_name ~^(?<project>[a-z0-9-]+)\.demo\.yourdomain\.com$;

    # 子域名 → 端口映射
    # demo-myshop   → 18080
    # demo-crm      → 18090
    # demo-blog     → 18100

    set $backend_port 18080;
    if ($project = "myshop") { set $backend_port 18080; }
    if ($project = "crm")    { set $backend_port 18090; }
    if ($project = "blog")   { set $backend_port 18100; }

    location / {
        proxy_pass http://127.0.0.1:$backend_port;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

## Step 2: 客户只读访问控制

```bash
# 原则：客户只能通过浏览器访问，不能接触任何底层资源

# 1. 数据库：给客户创建只读账号（可选，通常不需要）
# 2. 服务器：不给 SSH 账号
# 3. 代码：不部署到客户服务器

# 在 Nginx 中禁止访问敏感路径
location ~* \.(git|env|yml|yaml|sql|log)$ {
    deny all;
    return 403;
}
```

## Step 3: 演示环境的 Docker Compose 模板

```yaml
# docker-compose.demo.yml — 接单项目演示环境模板
version: '3.8'

services:
  # 数据库（使用 Docker Volume 持久化，但不暴露端口到外网）
  mysql:
    image: mysql:8.0
    container_name: ${PROJECT_NAME}_mysql
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_ROOT_PASSWORD}
      MYSQL_DATABASE: ${PROJECT_NAME}
    volumes:
      - mysql_data:/var/lib/mysql
    restart: unless-stopped
    networks:
      - internal
    # ⚠️ 不映射端口到宿主机，仅容器内访问

  redis:
    image: redis:7-alpine
    container_name: ${PROJECT_NAME}_redis
    restart: unless-stopped
    networks:
      - internal

  backend:
    build: ./backend
    container_name: ${PROJECT_NAME}_backend
    ports:
      - "${BACKEND_PORT}:8080"   # 仅后端端口对外
    environment:
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/${PROJECT_NAME}
      SPRING_REDIS_HOST: redis
    depends_on:
      - mysql
      - redis
    restart: unless-stopped
    networks:
      - internal

  frontend:
    build: ./frontend
    container_name: ${PROJECT_NAME}_frontend
    ports:
      - "${FRONTEND_PORT}:80"
    restart: unless-stopped
    networks:
      - internal

networks:
  internal:
    driver: bridge

volumes:
  mysql_data:
```

```bash
# .env 文件（每个项目一份）
PROJECT_NAME=myshop
BACKEND_PORT=18080
FRONTEND_PORT=18081
DB_ROOT_PASSWORD=your_secure_password

# 启动
docker-compose -f docker-compose.demo.yml --env-file .env up -d

# 验证
curl http://localhost:18080/api/health
curl http://localhost:18081
```

## Step 4: 正式交付打包脚本

```bash
#!/bin/bash
# deliver.sh — 接单项目标准交付打包脚本
# 使用方法：./deliver.sh myshop v1.0

PROJECT=$1
VERSION=$2
DELIVERY_DIR="./delivery/${PROJECT}-${VERSION}-$(date +%Y%m%d)"

echo "═══════════════════════════════════════"
echo "  项目交付打包：${PROJECT} ${VERSION}"
echo "═══════════════════════════════════════"

mkdir -p "$DELIVERY_DIR"

# 1. 打包后端 Docker 镜像
echo "[1/5] 打包后端镜像..."
cd backend
docker build -t ${PROJECT}-backend:${VERSION} .
docker save ${PROJECT}-backend:${VERSION} | gzip > "../${DELIVERY_DIR}/backend.tar.gz"
cd ..

# 2. 打包前端 Docker 镜像（或静态文件）
echo "[2/5] 打包前端..."
cd frontend
npm run build
if [ -f Dockerfile ]; then
    docker build -t ${PROJECT}-frontend:${VERSION} .
    docker save ${PROJECT}-frontend:${VERSION} | gzip > "../${DELIVERY_DIR}/frontend.tar.gz"
else
    cp -r dist "../${DELIVERY_DIR}/frontend-dist/"
fi
cd ..

# 3. 导出数据库初始化脚本
echo "[3/5] 导出数据库脚本..."
docker exec ${PROJECT}_mysql mysqldump \
    --no-data \
    --routines \
    --triggers \
    -u root -p${DB_ROOT_PASSWORD} \
    ${PROJECT} > "${DELIVERY_DIR}/init.sql"

# 4. 复制部署配置文件
echo "[4/5] 复制部署配置..."
cp docker-compose.prod.yml "${DELIVERY_DIR}/docker-compose.yml"
cp .env.example "${DELIVERY_DIR}/.env.example"

# 5. 打包源码
echo "[5/5] 打包源码..."
git archive --format=zip --output="${DELIVERY_DIR}/source-${VERSION}.zip" HEAD

# 最终交付包内容展示
echo ""
echo "═══════════════════════════════════════"
echo "  交付包已生成：${DELIVERY_DIR}/"
echo "═══════════════════════════════════════"
ls -lh "$DELIVERY_DIR"
echo ""
echo "⚠️  交付前确认："
echo "  □ 尾款已到账（金额：____）"
echo "  □ 客户已确认验收（功能清单逐项签字）"
echo "  □ 合同约定的交付时间未逾期"
echo "  □ 已准备操作手册 + 接口文档"
```

```bash
# 使用示例
chmod +x deliver.sh
./deliver.sh myshop v1.0

# 打包完成后，将整个 delivery/ 目录压缩发送
tar -czf myshop-v1.0-delivery.tar.gz -C delivery myshop-v1.0-20260717/
# 通过网盘/邮件/微信发送给客户
```

```markdown

- 操作系统：Linux (Ubuntu 20.04+ / CentOS 7+)
- Docker 24.0+
- Docker Compose v2+

## 二、部署步骤
1. 解压交付包：tar -xzf {项目名}-v1.0-delivery.tar.gz

   docker load < backend.tar.gz
   docker load < frontend.tar.gz

   docker exec -i {项目名}_mysql mysql -u root -p < init.sql
4. 启动服务：docker compose up -d

- 查看日志：docker compose logs -f --tail=100
- 重启服务：docker compose restart
- 停止服务：docker compose down
- 数据备份：docker exec {项目名}_mysql mysqldump -u root -p {库名} > backup.sql

## 四、常见问题
```

## 常见安装/配置问题

1. **客户没有 Docker 环境，不会用命令行？**
   → 在操作手册中提供"一键安装 Docker"的脚本。或者额外收费提供远程部署服务（SSH 到客户服务器代为部署，¥500-2000/次）。

2. **客户说"能不能不用 Docker，直接在我服务器上装环境"？**
   → 可以，但这属于定制部署服务，额外收费。Docker 化交付的本质是让你在交付后不变成免费运维——客户环境问题与你的代码质量无关。

3. **客户测试期间发现了之前功能清单没覆盖的 Bug？**
   → 严格按照"功能清单上承诺的功能实际运行结果与描述不符 = Bug"来判定。不在清单上的 = 新需求。温和但坚定地执行这个标准，这是你报价的边界依据。
