## 核心概念
> 反射允许程序在运行时动态操作类的字节码，是 Spring 等框架的核心基础。它通过 Class/Field/Method/Constructor 四个核心类提供了对类的完全掌控能力。

---

## 一、反射机制相关类

```
java.lang.Class           → 代表字节码文件，代表一个类型
java.lang.reflect.Method  → 代表字节码中的方法字节码
java.lang.reflect.Constructor → 代表字节码中的构造方法字节码
java.lang.reflect.Field   → 代表字节码中的属性字节码
```

包路径：`java.lang.reflect.*`

## 二、获取 Class 对象的三种方式

```java
// 方式一：Class.forName()（最常用，类路径灵活）
Class c1 = Class.forName("java.lang.String");  // 完整类名（含包名）
Class c2 = Class.forName("java.util.Date");
// 特点：会导致类加载，执行静态代码块

// 方式二：对象.getClass()
String s = "abc";
Class c = s.getClass();  // 获取运行时对象的真实类型

// 方式三：类型.class
Class c = String.class;  // 任何类型（包括基本类型）都有 .class 属性
```

> `Class.forName()` 的应用场景：只要希望某个类的**静态代码块执行**，其他代码不执行，就用 `Class.forName()`。

## 三、通过反射实例化对象

```java
Class c = Class.forName("com.example.User");

// JDK9 之前
User u = (User) c.newInstance();  // 调用无参构造，已过时

// JDK9+ 推荐
Constructor con = c.getDeclaredConstructor();  // 获取无参构造
Object obj = con.newInstance();                // 调用无参构造创建对象

// 调用有参构造
Constructor con2 = c.getDeclaredConstructor(String.class, int.class);
Object obj2 = con2.newInstance("zhangsan", 25);
```

## 四、反射的灵活性（配合配置文件）

```
反射机制灵活在哪？→ 配合属性配置文件和IO流，可以做到完全不修改代码就切换实现类
这正是 Spring / SpringMVC / MyBatis 等框架的核心思想！
```

```java
// 类路径下的配置文件
InputStream in = Thread.currentThread()
    .getContextClassLoader()
    .getResourceAsStream("classinfo.properties");
Properties pro = new Properties();
pro.load(in);
String className = pro.getProperty("className");
in.close();

// 反射创建对象 —— 类名来自配置文件，代码不用改！
Class c = Class.forName(className);
Object obj = c.newInstance();
```

## 六、类加载器与双亲委派机制

### JDK 的三层类加载器
| 加载器 | 加载路径 | 优先级 |
|--------|----------|--------|
| **启动类加载器** | `jre/lib/rt.jar` | 最高 |
| **扩展类加载器** | `jre/lib/ext/` | 中 |
| **应用类加载器** | classpath | 最低 |

### 双亲委派机制
```
请求加载 String →
  启动类加载器：找到 rt.jar 中的 String → 加载
  你的自定义 String：不会被加载！（安全机制）

"父" = 启动类加载器
"母" = 扩展类加载器
如果都加载不到，才去应用类加载器找
```
> 双亲委派机制保证了 Java 核心类的安全——你写的自定义 String 类不会被加载。

## 七、反射操作 Field（属性）

```java
Class c = Class.forName("com.example.User");
Object obj = c.newInstance();

// 获取所有 public 属性
Field[] fields = c.getFields();

// 获取所有属性（包括 private）
Field[] allFields = c.getDeclaredFields();

// 获取单个属性
Field field = c.getDeclaredField("no");

// 打破封装（操作 private 属性）
field.setAccessible(true);  // ⚠️ 破坏封装，安全风险

// 设值和取值
field.set(obj, 222);       // 给 obj 的此属性设值
Object value = field.get(obj);  // 获取 obj 的此属性值

// 获取属性名和类型
String name = field.getName();
Class type = field.getType();
String modifiers = Modifier.toString(field.getModifiers());
```

## 八、反射操作 Method（方法）—— 超级重点

### 可变长参数
```java
public static void m(int... args) {
    System.out.println("m方法执行了！");
}
// 调用：m(1), m(1,2), m(12,3,2)
// 可变长参数只能出现在参数列表的最后，一个参数列表只能有一个
// 可以把可变长参数看成数组，有 length 属性
```

### 反射调用方法
```java
Class c = Class.forName("com.example.UserService");
Object obj = c.newInstance();

// 获取方法（通过方法名 + 参数类型列表定位）
Method loginMethod = c.getDeclaredMethod("login", String.class, String.class);

// 调用方法的四要素
Object retValue = loginMethod.invoke(
    obj,       // ① 哪个对象
    "admin",   // ② 实参1
    "123"      // ③ 实参2
);               // ④ 返回值（retValue）

// 获取方法信息
Method[] methods = c.getDeclaredMethods();
for (Method m : methods) {
    m.getReturnType().getSimpleName();  // 返回值类型
    m.getName();                        // 方法名
    m.getParameterTypes();              // 参数列表
    Modifier.toString(m.getModifiers()); // 修饰符
}
```

## 十、反射的缺点

> `field.setAccessible(true)` 打破了封装，给不法分子留下机会（安全风险）。框架中大量反射也带来了性能开销。
