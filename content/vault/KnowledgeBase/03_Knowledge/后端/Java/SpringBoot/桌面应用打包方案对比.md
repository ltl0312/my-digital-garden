# SpringBoot 桌面应用打包方案对比

## 📍 知识体系定位
- **所属技术栈**：Java 后端
- **所在层级**：L3 框架层 → Spring Boot 部署与打包
- **上游依赖**：Spring Boot 基础（自动装配、MVC）、Maven/Gradle 构建工具
- **下游延伸**：GraalVM AOT 编译原理（L6 云原生）、Electron/Tauri 桌面开发
- **同级技术**：Docker 容器化部署、传统 WAR 包部署

## 概述（Overview）
> 将 Spring Boot 应用打包为 Windows `.exe` 独立可执行文件，使其脱离 IDE 和命令行，像普通桌面软件一样双击运行——无需用户安装 JDK/JRE。

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：传统做法是给用户装 JRE + 命令行 `java -jar app.jar` + 手动写 `.bat` 启动脚本。对非技术用户极不友好。
- **为什么前身被淘汰**：用户需要安装 Java 运行环境、面对黑窗口、不知道如何关闭进程——"这不是一个软件，这是一堆文件"。
- **本技术的核心突破**：GraalVM 将 Java 提前编译为原生机器码，真正脱离 JRE；Electron/Tauri 提供桌面窗口外壳，让 Web 技术栈产出原生桌面体验。
- **为什么是它活下来了**：Spring Boot 3.x 官方将 GraalVM Native Image 视为核心战略方向；Electron 已是跨平台桌面应用的事实标准。
- **当前版本**：Spring Boot 3.x（内置 GraalVM AOT 支持）/ GraalVM 22+ / Launch4j 3.5+

> ⚠️ **版本兼容性**：Spring Boot 3.x 强制 JDK 17+，Native Image 需要 GraalVM 22+ JDK（与普通 OpenJDK 不兼容）。Electron 和 Tauri 对 Node.js 版本有要求。

### 设计思想
将"服务端思维"降级为"单机思维"：Web 服务器变成 localhost 本地回路，数据库变成文件型 SQLite，对外 API 调用变成本地文件读写。本质上是对 Spring Boot 的"约束收窄"而非"能力削减"。

### 跨学科溯源（如适用）
> GraalVM Native Image 的 AOT 编译 → XD-4（编译原理：词法分析→静态分析→封闭世界假设→垃圾回收器替换）；Electron 的浏览器内核外壳 → XD-3（Chromium 渲染引擎 + Node.js 进程通信 IPC）。

## 实现（Implementation）

### 完整实例：三种打包方案对比与选型

| 方案 | GraalVM Native Image | JPackage / Launch4j | Electron/Tauri + Spring Boot |
|------|---------------------|--------------------|------------------------------|
| **是否需要 JDK/JRE** | ❌ 完全不需要（原生机器码） | ✅ 需要自带精简 JRE | ✅ 需要自带 JRE（隐藏在壳内） |
| **启动速度** | ⭐⭐⭐⭐⭐ 毫秒级 | ⭐⭐ 2-5 秒 | ⭐⭐ 2-5 秒（等 Spring Boot 启动） |
| **内存占用** | ⭐⭐⭐⭐⭐ 极低（~50MB） | ⭐⭐ 较高（~200MB+ JRE） | ⭐ 高（浏览器内核 + JRE） |
| **打包体积** | ⭐⭐⭐⭐⭐ 小 | ⭐⭐ 大（JRE ~150MB） | ⭐ 很大（Electron ~200MB+） |
| **代码兼容性** | ⭐⭐ 需额外配置反射/代理 | ⭐⭐⭐⭐⭐ 零改动 | ⭐⭐⭐⭐⭐ 零改动 |
| **UI 能力** | ❌ 无（需另配前端） | ❌ 无（需另配前端） | ⭐⭐⭐⭐⭐ 原生桌面窗口 |
| **适用场景** | 纯后台工具/CLI/微服务 | 快速迁移老项目 | 需要精美 UI 的桌面软件 |

### 方案一：GraalVM Native Image（最推荐）

```bash
// ① 安装 GraalVM JDK（不是普通 JDK！）
sdk install java 22.3.r17-grl

// ② Spring Boot 3.x 项目默认支持 AOT，直接编译
mvn -Pnative native:compile

// ③ 产出物：./target/app.exe（真正的原生 Windows 可执行文件）
// ④ 用户双击即可运行，无需任何 Java 环境
```

### 方案二：Launch4j 传统打包

```xml
<!-- pom.xml 配置 launch4j-maven-plugin -->
<plugin>
    <groupId>com.akathist.maven.plugins.launch4j</groupId>
    <artifactId>launch4j-maven-plugin</artifactId>
    <configuration>
        <headerType>gui</headerType>  <!-- gui = 无黑窗口 -->
        <jre>
            <path>./jre</path>        <!-- 自带精简 JRE -->
        </jre>
    </configuration>
</plugin>
```

### 方案三：Electron + Spring Boot

```javascript
// ① Electron main.js — 启动时拉起 Spring Boot
const { exec } = require('child_process');
const javaProcess = exec('java -jar app.jar --server.port=0', (err) => {});

// ② 窗口关闭时杀死 Java 进程（防止残留）
app.on('before-quit', () => {
    javaProcess.kill('SIGTERM');
});
```

> **💡 补充**：方案一（GraalVM）性能最优但兼容性需要调试；方案二（Launch4j）适合快速出活；方案三（Electron）适合有桌面 UI 需求的场景。作者推荐"方案三：Spring Boot + SQLite + 自动打开浏览器"作为最快的落地路径。
