# Spring Boot 3 可观测性与测试增强

## 📍 知识体系定位
- **所属技术栈**：Java 后端
- **所在层级**：L3 框架层 → 运维与测试
- **上游依赖**：<a href="obsidian://open?file=自动装配原理与MVC生命周期">SpringBoot3-自动装配原理与MVC生命周期</a>
- **下游延伸**：Prometheus + Grafana、Jaeger 分布式追踪、CI/CD 测试流水线

## 概述（Overview）
> Spring Boot 3.x 用统一的 **Micrometer Observation API** 替代了 Spring Cloud Sleuth，同时产出 Metrics（指标）、Tracing（链路追踪）和 Logging（日志）。**声明式 HTTP 客户端（HTTP Interfaces）** 用接口 + 注解的方式定义 REST 调用，无需 Feign 依赖。**Testcontainers** 深度集成让集成测试零配置启动真实数据库/Docker 容器。

## 设计初衷（Motivation）

### Micrometer Observation API 统一可观测性

旧模式（Spring Boot 2.x）：
- Metrics → Micrometer `Timer`
- Tracing → Spring Cloud Sleuth（独立团队维护）
- Logging → SLF4J + MDC

每种可观测性维度使用不同的 API → 代码中需要三套埋点逻辑 → 维护成本高。

新模式（Spring Boot 3.x）：
```java
Observation.createNotStarted("order.create", registry)
    .observe(() -> {
        // 业务逻辑
    });
// 这一行代码同时产出：Metrics 耗时 + Tracing span + Logging MDC
// 三个维度的数据，一次埋点完成
```

### HTTP Interfaces 替代 Feign

```java
// 类似 OpenFeign，但无需第三方依赖（Spring 框架原生）
public interface UserClient {
    @GetExchange("/users/{id}")
    User getUser(@PathVariable("id") String id);
}
// HttpServiceProxyFactory 生成代理实例 → 强类型 HTTP 调用
```

### Testcontainers：测试环境的 Docker

```
传统方式：手动安装 MySQL → 创建测试库 → 配置 jdbc url → 跑测试
Testcontainers：
  @Container @ServiceConnection MySQLContainer<?> mysql = ...
  → Spring Boot 自动启动 Docker MySQL 容器
  → 自动注入动态端口到 spring.datasource.url
  → 测试结束后自动销毁容器
```

| 特性 | Spring Boot 2.x | Spring Boot 3.x |
|------|----------------|-----------------|
| 链路追踪 | Spring Cloud Sleuth | **Micrometer Observation** |
| HTTP 客户端 | 需 OpenFeign/RestTemplate | **HTTP Interfaces（原生）** |
| 集成测试 | 手动配置外部服务 | **Testcontainers 零配置** |
| 虚拟线程 | 不支持 | `spring.threads.virtual.enabled=true` |

> **💡 补充**：Testcontainers 的核心价值不是"不用装数据库了"，而是"测试环境与 CI 环境完全一致"——CI 上跑的是同一个 Docker 镜像，不会有"本地 MySQL 8.0 能跑，CI MySQL 5.7 挂了"的问题。
