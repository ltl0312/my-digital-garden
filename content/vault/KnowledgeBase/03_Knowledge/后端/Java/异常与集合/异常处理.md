# Java 异常处理

## 📍 知识体系定位
（严格按 03_Knowledge/技术划分.md 填写）
- **所属技术栈**：Java 后端
- **所在层级**：Java 后端 → L0 语言基础
- **上游依赖**：📋 待补充：Java基本语法 — 掌握变量、控制流、方法定义等基础语法才能理解异常抛出和捕获的流程。
- **下游延伸**：📋 待补充：Java-IO流异常处理最佳实践 — 异常处理在 IO 资源关闭、数据库事务回滚中的落地应用。

## 核心概念
> 异常是 Java 中以类的形式存在的错误处理机制。编译时异常（受检异常）必须在编译前处理，运行时异常（非受检异常）可选择处理，但两者都发生在运行阶段。

## 一、异常继承体系

```
Object
  └── Throwable（可抛出的）
        ├── Error（错误，如 StackOverflowError，JVM 直接终止）
        └── Exception（异常）
              ├── RuntimeException（运行时异常）
              │     ├── NullPointerException
              │     ├── ArithmeticException
              │     └── ClassCastException
              └── Exception的直接子类（编译时异常/受检异常）
```

> **Error 和 Exception 都发生在运行阶段。** 异常本质是 new 出来的对象，编译阶段不可能 new 对象。

---

## 二、编译时异常 vs 运行时异常

| 维度 | 编译时异常（受检异常） | 运行时异常（非受检异常） |
|------|----------------------|-------------------------|
| 发生概率 | 较高 | 较低 |
| 处理要求 | **必须处理**，否则编译不过 | 可选处理 |
| 类比 | 看到下雨 → 带伞（预防高概率事件） | 出门被飞机砸 → 不预防（低概率事件不值得防御） |
| 典型 | IOException, SQLException | NullPointerException, ArithmeticException |

## 三、异常处理的两种方式

### 方式一：throws（声明抛出，往上抛）
```java
public void doSome() throws ClassNotFoundException {
    // 方法体
}
// 调用方必须再处理：要么继续 throws，要么 try-catch
```

### 方式二：try-catch（捕获处理，自己兜底）
```java
try {
    // 可能出异常的代码
} catch (异常类型1 e) {
    e.printStackTrace();
} catch (异常类型2 e) {
    // 可以写多个 catch，精确匹配有利于调试
}
// catch 后的代码正常执行
```

### throws vs try-catch 的选择原则
> 如果确定调用者需要知道这个异常并自己处理 → throws；否则 → try-catch。

## 四、finally 深入

### 核心特性
- `finally` 中的代码**一定会执行**（除非 `System.exit()` 退出 JVM）
- 即使 try 中有 `return`，finally 也会在 return 前执行

### 经典面试题
```java
public static int m() {
    int i = 100;
    try {
        return i;
    } finally {
        i++;
    }
}
// 结果：返回 100，不是 101！
// 原因：Java 遵循从上到下执行，return i 时先把 i 的值(100)保存到临时变量 j，
//       然后执行 finally(i++ → 101)，最后 return 的是已保存的 j(100)
//
// 反编译等价代码：
// int i = 100; int j = i; i++; return j;
```

### 实际用途
```java
FileInputStream f = null;
try {
    f = new FileInputStream("路径");
    String s = null;
    s.toString();           // 空指针异常，不执行 close
    f.close();              // 永远执行不到！
} catch (Exception e) {
    e.printStackTrace();
} finally {
    if (f != null) {
        try { f.close(); } catch (IOException e) { e.printStackTrace(); }
    }
    // 无论是否异常，流一定会被关闭
}
```

## 五、异常的核心方法
```java
String msg = exception.getMessage();   // 获取异常简单描述
exception.printStackTrace();           // 打印异常堆栈追踪（有独立线程处理打印）
```

## 六、final / finally / finalize 三者的区别

| 关键词 | 含义 | 用途 |
|--------|------|------|
| `final` | 不可变 | 修饰类（不可继承）、方法（不可覆盖）、变量（不可重新赋值） |
| `finally` | 确保执行 | 与 try 配合，finally 块中的代码一定执行 |
| `finalize` | 回收回调 | Object 方法，GC 回收对象前调用（已过时，不推荐使用） |

## 七、自定义异常

```java
// 两步创建自定义异常
public class MyException extends Exception {   // 继承 Exception → 编译时异常
                                               // 继承 RuntimeException → 运行时异常
    public MyException() {}

    public MyException(String s) {  // s 会被 getMessage() 返回
        super(s);
    }
}

// 手动抛出
if (需要抛异常的条件) {
    throw new MyException("错误描述");
}
```
