## 核心概念
> 抽象类是"不能 new 的类"，代表不完整的抽象概念（如"银行账户"）；抽象方法是只有声明没有实现的方法，强制子类去完成。

## 一、抽象类（Abstract Class）

### 为什么需要抽象类？
```
银行账户（抽象类）
  ├── 储蓄卡（具体类）
  │     ├── 小明的储蓄卡（对象）
  │     └── 小花的储蓄卡（对象）
  └── 信用卡（具体类）
        ├── 小明的信用卡（对象）
        └── 小花的信用卡（对象）
```
"银行账户"本身不是一个真正存在的实体，它被抽象出来是为了**定义共性，让子类去具体化**。

### 语法与规则
```java
[修饰符列表] abstract class 类名 {
    类体;  // 可以包含非抽象方法、实例变量、构造方法
}
```

| 规则 | 说明 |
|------|------|
| 不能实例化（不能 new） | 抽象类是不完整的 |
| 有构造方法 | 供子类构造时调用（`super()`） |
| 可以没有抽象方法 | 抽象类中可以全部是非抽象方法 |
| 可以被进一步抽象 | 抽象类可以继承抽象类 |

### final vs abstract
```
final    → 阻止继承（终结者）
abstract → 必须继承（等待被完成）
二者水火不容，不能同时修饰一个类或方法！
```

## 二、抽象方法

### 特征
```java
public abstract void doSome();
// 特点1：没有方法体，以分号结尾（连 {} 都没有）
// 特点2：修饰符列表中有 abstract 关键字
```

### 核心规则
- **抽象方法必须在抽象类中**（反过来不成立：抽象类可以没有抽象方法）
- **非抽象子类继承抽象类后，必须实现所有抽象方法！**
- 这本质上是强制子类"填坑"——父类定义契约，子类提供实现

## 三、面向抽象编程（OCP 开闭原则）

```java
// ✅ 面向抽象编程
Animal a = new Bird();  // 左边是抽象(Animal)，右边是具体(Bird)

// 设计思想：高层模块依赖抽象，不依赖具体
```

### OCP 开闭原则
> **Open for Extension, Closed for Modification**
> 对扩展开放、对修改关闭 —— 应该通过**新增**代码来应对变化，而不是修改已有代码。

抽象类是实现 OCP 的关键工具之一：
- 抽象类定义"不变"的接口契约
- 子类提供"可变"的具体实现
- 未来新增子类时，不需要修改调用方代码
