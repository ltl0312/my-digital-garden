## 核心概念
> 接口是"完全抽象的类"（Java 8 前），代表一种能力契约（"like a"）；接口 + 多态是 Java 中实现低耦合、高扩展的核心组合。

## 一、接口基础

### 语法
```java
[修饰符列表] interface 接口名 {
    // 常量（省略 public static final）
    int MAX_VALUE = 100;

    // 抽象方法（省略 public abstract）
    void doSomething();
}
```

### 接口中的省略规则
- 方法的 `public abstract` 可以省略
- 常量的 `public static final` 可以省略
- 接口中所有元素默认都是 **public** 的

### 接口的实现
```java
class 类名 implements 接口A, 接口B {  // 多实现！
    // 必须实现所有接口的抽象方法
}
```

### 与类的关系
- **类与类**之间叫**继承**（extends），只能单继承
- **类与接口**之间叫**实现**（implements），可以多实现
- **接口与接口**之间叫**继承**（extends），可以多继承

## 二、接口的核心价值：解耦合

> ==接口解的是"调用者"和"实现者"之间的耦合==

### 经典案例：餐厅点餐
```java
// ==== 接口（契约）====
interface FoodMenu {
    void xihongshichaojidan();
    void yuxiangrousi();
}

// ==== 实现者（变化）====
class ChineseCook implements FoodMenu {
    public void xihongshichaojidan() { System.out.println("中国厨师做西红柿炒蛋"); }
    public void yuxiangrousi()      { System.out.println("中国厨师做鱼香肉丝"); }
}
class AmericaCook implements FoodMenu {
    public void xihongshichaojidan() { System.out.println("美国厨师做西红柿炒蛋"); }
    public void yuxiangrousi()      { System.out.println("美国厨师做鱼香肉丝"); }
}

// ==== 调用者（稳定）====
class Customer {
    private FoodMenu foodmenu;          // 持有接口引用！
    public Customer(FoodMenu foodmenu) {
        this.foodmenu = foodmenu;
    }
    public void order() {
        foodmenu.xihongshichaojidan();  // 不关心具体是哪个厨师
        foodmenu.yuxiangrousi();
    }
}

// ==== 组装 ====
public class Test {
    public static void main(String[] args) {
        FoodMenu f = new AmericaCook(); // 换厨师只需改这一行！
        Customer c = new Customer(f);
        c.order();
    }
}
```

> **关键洞察**：`Customer` 只依赖 `FoodMenu` 接口，永远不需要因为换厨师而修改代码。这就是"可插拔"设计。

## 三、抽象类 vs 接口 对比

| 维度 | 抽象类 | 接口（Java 8 前） |
|------|--------|-------------------|
| 抽象程度 | 半抽象（可以含非抽象方法） | 完全抽象 |
| 构造方法 | 有 | 无 |
| 多继承 | ❌ 单继承 | ✅ 接口之间多继承 |
| 多实现 | ❌ 只能继承一个抽象类 | ✅ 一个类可实现多个接口 |
| 设计意图 | is a（是什么）| like a（像什么/能做什么） |
| 成员 | 可以包含实例变量、实例方法 | 只能包含常量和抽象方法 |

## 四、接口的强制类型转换（特殊规则）

类和类之间：没有继承关系强转 → 编译报错。
接口和接口之间：没有继承关系强转 → **编译通过**！但运行可能 `ClassCastException`。

```java
interface K {}
interface M {}
class E implements M {}

M a = new E();
K b = (K) a;  // 编译通过（接口之间宽容），但运行可能抛 ClassCastException
```

## 关联上下文
- **横向对比**：📋 待补充：Java-抽象类 — 抽象类更适合有共同状态/行为的场景（模板模式），接口更适合纯粹的能力契约；选择接口而非抽象类的关键考量是是否需要多继承能力以及是否需要保持纯抽象契约
- **实际应用**：📋 待补充：设计模式-策略模式、📋 待补充：设计模式-工厂模式、📋 待补充：Spring-依赖注入 — 接口是低耦合架构的基石，广泛应用于框架设计、插件系统、依赖注入等场景
- **进阶方向**：📋 待补充：Java-函数式接口与Lambda、📋 待补充：Java-默认方法与静态方法 — Java 8+ 接口增强（default/static 方法）让接口从完全抽象走向部分实现，进一步演化出函数式编程范式
- **易混淆概念**：接口 vs 📋 待补充：Java-注解 — 接口定义行为契约，注解定义元数据标记，二者在语法上相似但语义完全不同
