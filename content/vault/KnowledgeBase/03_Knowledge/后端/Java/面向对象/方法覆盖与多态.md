## 核心概念
> 方法覆盖（Override）让子类用自定义逻辑替代父类方法；多态让父类引用指向子类对象，编译看左边，运行看右边，是降低耦合度的核心机制。

## 一、方法覆盖（Override / Overwrite）

≠ 方法重载（Overload）！

### 什么时候需要方法覆盖？
子类继承父类后，继承来的方法**无法满足子类的业务需求**时，需要重写。

### 覆盖的必要条件
- 方法名相同
- 参数列表相同
- 返回值类型相同

### 覆盖的注意事项
| 规则 | 说明 |
|------|------|
| 访问权限只能更高 | 不能降低（如 public → private ❌） |
| 不能抛出更多异常 | 重写后的异常范围不能扩大 |
| 只针对方法 | 和属性无关 |
| 私有方法无法覆盖 | `private` 方法对子类不可见 |
| 构造方法不能覆盖 | 构造方法不继承，自然也谈不上覆盖 |
| 静态方法覆盖无意义 | 静态方法属于类，不参与动态绑定 |

> **实际效果**：子类重写后，JVM 只认重写后的方法，父类原方法被"标记忽略"。

## 二、多态

### 核心机制
```java
Animal a = new Cat();    // 向上转型（子类→父类，自动）
a.move();
// 编译阶段：只看到 a 是 Animal，去 Animal.class 找 move 方法 → 编译通过
// 运行阶段：a 实际指向 Cat 对象，调用 Cat 的 move 方法 → 动态绑定
```

> **编译看左边（父类），运行看右边（子类）**

### 向上转型（Upcasting）
- 子类对象赋值给父类引用：`Animal a = new Cat();`
- 自动发生，安全
- 只能调用父类中**已有定义**的方法（子类特有方法无法直接调用）

### 向下转型（Downcasting）
- 当需要调用**子类特有方法**时必须向下转型
- **有风险**！需要 `instanceof` 判断

```java
Animal a = new Bird();
// Cat c = (Cat) a;  // ClassCastException! Bird 不能强转为 Cat

// 安全的做法：
if (a instanceof Cat) {
    Cat c = (Cat) a;
    c.catchMouse();
}
```

`instanceof` 返回 boolean，在**运行阶段**动态判断真实类型。

### 多态在开发中的核心价值
> **降低程序的耦合度，提高扩展力**（符合 OCP 开闭原则）

```java
// 不使用多态（耦合度极高）
public void feed(Dog d) { d.eat(); }
public void feed(Cat c) { c.eat(); }
// 每新加一种动物都要新写一个 feed 方法！

// 使用多态（面向父类编程）
public void feed(Animal a) { a.eat(); }
// 以后新加任何 Animal 子类，这个方法不用改！
```

## 三、Override vs Overload 对比

| 维度 | Override（方法覆盖） | Overload（方法重载） |
|------|---------------------|---------------------|
| 位置 | 父子类之间 | 同一个类中 |
| 方法名 | 必须相同 | 必须相同 |
| 参数列表 | 必须相同 | 必须不同 |
| 返回值 | 必须相同 | 可以不同 |
| 访问权限 | 只能更高 | 无限制 |
