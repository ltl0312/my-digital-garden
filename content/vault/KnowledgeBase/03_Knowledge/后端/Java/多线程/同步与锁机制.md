## 核心概念
> 多线程并发 + 共享数据 + 修改行为 = 线程安全问题。synchronized 通过对象锁让线程排队执行同步代码块，以效率换安全。

## 一、线程安全问题的三个条件

1. **多线程并发**
2. **有共享数据**
3. **共享数据有修改行为**

三个条件**同时满足**才会出问题。

---

## 二、Java 中的三大变量：谁安全谁不安全？

| 变量类型 | 存储位置 | 线程安全性 |
|----------|----------|-----------|
| 局部变量 | 栈（每个线程独立） | ✅ 永远安全 |
| 实例变量 | 堆（所有线程共享） | ❌ 可能不安全 |
| 静态变量 | 方法区（所有线程共享） | ❌ 可能不安全 |

> **局部变量永远不存在线程安全问题**——因为每个线程拥有独立栈空间。

## 三、synchronized 同步机制

### 银行取款案例（未同步 → 出问题）
```java
// 两个线程各取 5000，余额 10000 → 正常结果应该一个 5000 一个 0
// 但未同步时两个线程都看到了 10000，结果都扣成 5000！
t2 从 10000 取出 5000 元，余额：5000 元
t1 从 10000 取出 5000 元，余额：5000 元  // ← 错了，应该为 0
```

### 加同步后的正确写法
```java
public void withDraw(int num) {
    synchronized (this) {  // 锁住共享对象
        int balanceBefore = this.getBalance();
        Thread.sleep(1000);
        this.setBalance(getBalance() - num);
    }
}
// 结果：
// t1 从 10000 取出 5000 元，余额：5000 元
// t2 从 5000 取出 5000 元，余额：0 元    ← 正确了
```

### synchronized 的锁机制解释
```
Java 中每个对象都有一把"锁"（一个标记位）。

t1 先到达 synchronized(this) → 找到 this 对象的锁 → 上锁 → 执行代码块
  t2 到达 synchronized(this) → 发现锁被占用 → 等待
t1 代码块执行完毕 → 释放锁
  t2 获得锁 → 上锁 → 执行代码块 → 释放锁
```

**括号中必须放"多个线程的共享对象"！**

```java
synchronized("abc") {}  // "abc" 在字符串常量池，全局唯一 → 所有线程都同步
```

## 四、synchronized 的三种用法

### 1. 同步代码块（最灵活）
```java
synchronized (共享对象) {
    // 只锁需要同步的代码
}
```

### 2. 实例方法上使用（锁 this）
```java
public synchronized void doSome() {
    // 等价于 synchronized(this) { 整个方法体 }
}
```
- **优点**：代码简洁
- **缺点**：锁范围大，不够灵活

### 3. 静态方法上使用（锁类锁）
```java
public static synchronized void doSome() {
    // 锁的是 类.class，类锁只有一把
}
```
- 用于保护**静态变量**的安全
- 类锁与对象实例个数无关，全局唯一

## 五、synchronized 经典面试题

### 题目1：对象锁互不影响
```java
class MyClass {
    public synchronized void doSome() {  // 锁 this
        Thread.sleep(10000);
    }
    public void doOther() {              // 没有锁！
        System.out.println("doOther");
    }
}
// t1 执行 doSome 时，t2 可以执行 doOther（因为 doOther 没锁）
// 如果 doOther 也加 synchronized → t2 必须等 t1 释放 this 锁
```

### 题目2：多个对象，锁互不影响
```java
MyClass m1 = new MyClass();
MyClass m2 = new MyClass();
// t1 对 m1 加锁 → t2 对 m2 加锁 → 互不影响（两个不同的 this 对象）
```

### 题目3：类锁互斥
```java
class MyClass {
    public synchronized static void doSome() {}  // 锁 MyClass.class
    public synchronized static void doOther() {}  // 锁 MyClass.class
}
// t1 和 t2 无论操作哪个对象，都必须互相等待（类锁只有一把）
```

## 六、死锁

```java
// 死锁示例（面试要求会写）
Object o1 = new Object();
Object o2 = new Object();

// 线程1：先锁 o1 再锁 o2
class MyThread1 extends Thread {
    public void run() {
        synchronized (o1) {
            Thread.sleep(1000);
            synchronized (o2) { /* 永远等待 */ }
        }
    }
}
// 线程2：先锁 o2 再锁 o1
class MyThread2 extends Thread {
    public void run() {
        synchronized (o2) {
            Thread.sleep(1000);
            synchronized (o1) { /* 永远等待 */ }
        }
    }
}
// 线程1 持有 o1 等 o2，线程2 持有 o2 等 o1 → 死锁！
```

> **实际开发中，synchronized 最好不要嵌套使用。**

## 七、解决线程安全的三级策略

| 优先级 | 策略 | 具体做法 |
|--------|------|----------|
| ⭐⭐⭐ | 用局部变量 | 避免共享数据 |
| ⭐⭐ | 创建多对象 | 每个线程操作独立对象 |
| ⭐ | synchronized | 前两者都不行时，只能用同步（牺牲效率） |

## 八、StringBuilder vs StringBuffer

| 类 | 线程安全 | 效率 | 适用场景 |
|----|----------|------|----------|
| `StringBuilder` | ❌ 非线程安全 | 高 | 局部变量拼接（推荐） |
| `StringBuffer` | ✅ 线程安全（sync） | 低 | 多线程共享拼接 |

> 不存在线程安全问题（局部变量）时，用 StringBuilder，效率更高。
