# NestJS 核心架构与项目初始化

## 📍 知识体系定位
- **所属技术栈**：后端（Node.js 生态）
- **所在层级**：NestJS 框架核心层（对标 Java Spring Boot 的 L3 框架层）
- **上游依赖**：<a href="obsidian://open?file=基础与特殊类型">TypeScript 基础与特殊类型</a> — NestJS 使用 TypeScript 装饰器作为核心语法；<a href="obsidian://open?file=类与高级类型">TypeScript 类与高级类型</a> — 依赖注入基于类的类型系统
- **下游延伸**：<a href="obsidian://open?file=控制器与路由">NestJS 控制器与路由</a> — 核心架构之后进入路由层
- **同级技术**：<a href="obsidian://open?file=MOC - Java后端">Spring Boot</a>（Java 生态的 IoC/DI 框架），Express（Node.js 最简 HTTP 框架）

## 概述（Overview）
> 一句话定义：Nest (NestJS) 是一个用于构建高效、可扩展的 **Node.js 服务端应用**的框架。它使用渐进式 JavaScript，完全支持 TypeScript，结合了 OOP（面向对象编程）、FP（函数式编程）和 FRP（函数式反应式编程）的元素。

在底层，Nest 构建在强大的 HTTP 服务器框架上，例如 **Express**（默认），还可以通过配置切换到 **Fastify**——这意味着你可以无障碍使用 Express/Fastify 的成熟 API 和中间件生态。

## 为什么选择 Nest.js

- **架构严谨**：严格模块分类（Module/Controller/Service），和 Java Spring 很像，后端开发者上手容易
- **TypeScript 原生支持**：类型安全、装饰器语法、编译时错误检查
- **开发效率**：热更新是增量更新（HMR），reload 速度快
- **学习资源丰富**：社区活跃，文档完善
- **对标 Java 后端的 Node.js 方案**：如果你熟悉 Java 的 IoC/DI/AOP，NestJS 的思维模型几乎照搬

> **💡 补充**：NestJS 常被称为"Node.js 界的 Spring Boot"——它借鉴了 Spring 的模块化、依赖注入、AOP 拦截等设计模式，但运行在 Node.js 的单线程事件循环之上。

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：在 NestJS 出现之前，Node.js 后端的主流选择是 **Express**（极简路由框架）和 **Koa**（洋葱模型中间件）。它们自由度高但缺乏架构约束——项目变大后代码组织混乱，每个团队都要自己发明"分层规范"。
- **为什么前身被淘汰**：Express/Koa 不提供架构引导。Controller、Service、Module 的概念需要开发者自己建立，导致不同项目结构千差万别，新成员上手成本高。
- **本技术的核心突破**：NestJS 将 Java Spring Boot 的成熟架构模式移植到 Node.js 生态——@Module（模块）、@Injectable（依赖注入）、@Controller（路由）、@Guard/@Interceptor/@Pipe（AOP 切面），让 TypeScript 后端开发有了经过验证的架构范式。
- **为什么是它活下来了**：同类框架（AdonisJS、FoalTS、Ts.ED）中，NestJS 以最接近 Angular/Spring 的编程模型、完整的 TypeScript 装饰器支持、以及最大的社区生态胜出。GitHub Stars 远超竞争对手。
- **当前版本**：NestJS 10.x（2024 年），基于 Node.js >= 16。

### 设计思想
NestJS 的核心设计哲学是 **"架构收敛"**——不限制你用什么库（Express 还是 Fastify，TypeORM 还是 Prisma），但强制你用 Module/Controller/Provider 的三层结构来组织代码。这与 Spring 的"IoC 容器 + 注解驱动"一脉相承：框架负责生命周期管理，开发者专注业务逻辑。

## 实现（Implementation）

### 创建第一个 NestJS 项目

```bash
# ① 场景：使用 Nest CLI 创建新项目
# ② 前置条件：Node.js >= 16
# ② 全局安装 Nest CLI
npm i -g @nestjs/cli
# ② 创建项目（project-name 替换为你的项目名）
nest new project-name
# ③ CLI 会询问包管理器（npm/yarn/pnpm），选择后自动安装依赖
```

### 项目文件介绍

除去常见的配置文件之外，在 `src` 目录下是 NestJS 标准的文件规范：

```
src
 ├── app.controller.spec.ts   # 控制器的单元测试
 ├── app.controller.ts        # 处理 HTTP 请求，路由管理
 ├── app.module.ts            # 根模块，组织应用结构
 ├── app.service.ts           # 业务逻辑封装、数据层交互
 └── main.ts                  # 应用入口文件
```

| 文件名 | 职责 |
|--------|------|
| `app.controller.spec.ts` | app.controller 的单元测试 |
| `app.controller.ts` | 处理 HTTP 请求，调用 Service 层，路由管理 |
| `app.module.ts` | 根模块，组织其他类的引用与共享 |
| `app.service.ts` | 封装通用业务逻辑、数据库交互、第三方请求 |
| `main.ts` | 入口文件，使用 `NestFactory` 创建 Nest 应用实例 |

### 项目运行

```bash
# ① 场景：启动开发服务器
npm run start
# ③ 默认监听 http://localhost:3000

# ① 场景：启动开发服务器（热更新模式，推荐！）
npm run start:dev
# ② 此命令监视文件变化，自动重新编译并重新加载服务器——增量热更新
```

### 入口文件剖析：main.ts

```typescript
import { NestFactory } from '@nestjs/core';
import { AppModule } from './app.module';

async function bootstrap() {
    // ② NestFactory.create() 根据 AppModule 创建 IoC 容器
    const app = await NestFactory.create(AppModule);
    // ② app.listen() 启动 HTTP 服务器，默认端口 3000
    await app.listen(process.env.PORT ?? 3000);
}
bootstrap();
```

> 监听的端口号可以自定义。如果 3000 端口被占用，可以在 `main.ts` 修改默认端口号，或创建 `.env` 文件配置环境变量。

### 根模块剖析：app.module.ts

```typescript
import { Module } from '@nestjs/common';
import { AppController } from './app.controller';
import { AppService } from './app.service';

@Module({
    imports: [],                              // 导入其他模块
    controllers: [AppController],             // 注册控制器
    providers: [AppService],                  // 注册服务提供者
})
export class AppModule {}
```

`AppModule` 是应用程序的**根模块**，它提供了启动的引导机制。`@Module()` 装饰器接收四个属性：

| 属性 | 作用 |
|------|------|
| `providers` | 由 Nest 注入器实例化的服务，可在模块内共享 |
| `controllers` | 必须实例化的控制器集合 |
| `imports` | 导入其他模块，获得其导出的 providers |
| `exports` | 本模块 providers 的子集，供其他导入本模块的模块使用 |

### 快速生成代码：Nest CLI

```bash
# ① 场景：快速生成 CRUD 模块
nest g resource user    # 生成完整 CRUD 模块（推荐）
nest g mo user          # 生成模块 (Module)
nest g co user          # 生成控制器 (Controller)
nest g s user           # 生成服务 (Service)

# ① 场景：禁用自动生成 .spec.ts 测试文件
# 在根目录 nest-cli.json 中添加：
{
    "generateOptions": {
        "spec": false
    }
}
```
