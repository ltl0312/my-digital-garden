# NestJS 模块系统

## 📍 知识体系定位
- **所属技术栈**：后端（Node.js 生态）
- **所在层级**：NestJS 框架 → 模块与依赖注入层
- **上游依赖**：<a href="obsidian://open?file=核心架构与项目初始化">NestJS 核心架构与项目初始化</a> — 根模块是模块系统的起点
- **下游延伸**：<a href="obsidian://open?file=请求生命周期">NestJS 请求生命周期</a> — 模块是全局守卫、全局管道注册的载体
- **同级技术**：Spring 的 `@Configuration` + `@ComponentScan`（Java IoC 容器）

## 概述（Overview）
> 一句话定义：模块是用 `@Module()` 装饰器注释的类，提供 Nest 用于**组织应用结构**的元数据。每个应用至少有一个根模块。Nest 通过模块树来解析 Provider 依赖关系——这就是 NestJS 的 **依赖注入（DI）容器**。

## 设计初衷（Motivation）

### 设计思想
NestJS 的模块系统是 Spring IoC 容器思想在 TypeScript 中的实现。核心原理：
1. **依赖注入（DI）**：Provider 的实例化由框架负责，开发者只需声明类型依赖
2. **模块隔离**：每个功能域有自己的模块，`imports`/`exports` 控制可见性
3. **单例作用域**：默认情况下模块中的 Provider 是单例，导入同一模块的所有消费者共享同一个实例

## 实现（Implementation）

### @Module() 装饰器

```typescript
@Module({
    providers: [],      // ② 由 Nest 注入器实例化的服务
    controllers: [],    // ② 必须实例化的控制器集
    imports: [],        // ② 导入其他模块（获得其 exports）
    exports: [],        // ② 导出本模块的 providers 供其他模块使用
})
export class AppModule {}
```

### 功能模块示例：nest g resource

输入 `nest g resource user` 生成一个基础的 CRUD 功能，目录结构为：

```
src
 ├── user
 |    ├── dto
 |    |   ├── create-user.dto.ts     # 创建用户的 DTO
 |    |   └── update-user.dto.ts     # 更新用户的 DTO
 |    |
 |    ├── entities
 |    |   └── user.entity.ts          # 用户实体定义
 |    |
 |    ├── user.controller.spec.ts     # 控制器单元测试
 |    ├── user.controller.ts          # 用户路由处理
 |    ├── user.module.ts              # 用户模块定义
 |    └── user.service.ts             # 用户业务逻辑
 |
 ├── app.module.ts                    # 根模块
 └── main.ts                          # 入口文件
```

### 共享模块

在 Nest 中，默认情况下模块是**单例**的。要共享 Provider，需要将其放入 `exports` 数组：

```typescript
import { Module } from '@nestjs/common';
import { UserService } from './user.service';
import { UserController } from './user.controller';

@Module({
    controllers: [UserController],
    providers: [UserService],
    exports: [UserService],   // ② 导出 UserService，其他模块导入本模块后可使用
})
export class UserModule {}
// ③ 任何导入 UserModule 的模块都能访问 UserService 的同一实例
```

### 模块重新导出

模块不仅可以导出自己的 Provider，还可以重新导出导入的模块：

```typescript
@Module({
    imports: [CommonModule],
    exports: [CommonModule],   // ② 重新导出 CommonModule
})
export class CoreModule {}
// ③ 导入 CoreModule 的模块自动获得 CommonModule 中的所有导出
```

### 全局模块（@Global）

当某个模块需要在所有地方使用时（如数据库连接、工具类），可以用 `@Global()` 使其全局化：

```typescript
import { Module, Global } from '@nestjs/common';

@Global()                     // ② 声明为全局模块
@Module({
  controllers: [UserController],
  providers: [UserService],
  exports: [UserService],
})
export class UserModule {}
// ③ 全局模块只注册一次（通常由根模块注册），之后所有模块无需 imports 即可使用其导出
```

### 动态模块（forRoot 模式）

动态模块能够动态注册和配置 Provider，典型的场景如数据库连接模块：

```typescript
import { Module, DynamicModule } from '@nestjs/common';

@Module({
    providers: [Connection],
    exports: [Connection],
})
export class DatabaseModule {
    // ② forRoot 静态方法返回动态模块定义
    static forRoot(entities = [], options?): DynamicModule {
        const providers = createDatabaseProviders(options, entities);
        return {
            module: DatabaseModule,       // ② 基础模块
            providers: providers,         // ② 动态生成的额外 providers
            exports: providers,           // ② 导出动态 providers
            global: true,                 // ② 可选：设为全局模块
        };
    }
}
// ② 动态模块返回的属性扩展（而非覆盖）@Module() 中的基础元数据
```

导入并配置动态模块：

```typescript
@Module({
    imports: [DatabaseModule.forRoot([User])],   // ② 调用 forRoot 传入实体列表
    exports: [DatabaseModule],                    // ② 重新导出动态模块时可省略 forRoot()
})
export class AppModule {}
```
