# NestJS 控制器与路由

## 📍 知识体系定位
- **所属技术栈**：后端（Node.js 生态）
- **所在层级**：NestJS 框架 → 控制器层（路由 + 请求处理）
- **上游依赖**：<a href="obsidian://open?file=核心架构与项目初始化">NestJS 核心架构与项目初始化</a> — 必须先理解模块体系和 main.ts 启动流程
- **下游延伸**：<a href="obsidian://open?file=模块系统">NestJS 模块系统</a> — 控制器在模块的 controllers 数组中注册
- **同级技术**：Express Router（函数式路由），Spring @RestController（Java 注解路由）

## 概述（Overview）
> 一句话定义：控制器负责**处理传入的 HTTP 请求**并向客户端**返回响应**。`@Controller()` 装饰器将类标记为控制器，路由机制决定哪个控制器接收哪些请求。每个控制器可以有多条路由，不同的路由执行不同的操作。

## 设计初衷（Motivation）

### 设计思想
NestJS 的控制器设计直接借鉴了 **Angular** 的组件模式——用装饰器声明式地绑定路由路径和 HTTP 方法，而非 Express 的 `app.get('/path', handler)` 函数式注册。这种方式将路由信息内聚在类中，IDE 可跳转、可重构、可类型提示，解决了 Express 项目中路由散落各处难以维护的问题。

## 实现（Implementation）

### @Controller() 装饰器

`@Controller()` 装饰器可以传入一个路径参数作为访问该控制器的主路径：

```typescript
import { Controller, Get } from '@nestjs/common';

@Controller('user')       // ② 所有路由以 /user 开头
export class UserController {
    @Get()                // ② 匹配 GET /user
    getHello(): string {
        return 'Hello Nest.js!';
    }
}
// ③ 浏览器访问 http://localhost:3000/user → 返回 "Hello Nest.js!"
```

### 请求对象

通过将 `@Req()` 装饰器添加到处理程序的签名来注入请求对象：

```typescript
import { Controller, Get, Req } from '@nestjs/common';
import { Request } from 'express';

@Controller('user')
export class UserController {
    @Get()
    getHello(@Req() request: Request): string {
        console.log(request);       // ② 访问完整的 Express 请求对象
        return 'Hello Nest.js!';
    }
}
```

> **💡 补充**：在大多数情况下无需手动获取完整的 `request` 对象。NestJS 提供了专用的参数装饰器：

| 装饰器 | 对应 Express 对象 | 用途 |
|--------|------------------|------|
| `@Request()`, `@Req()` | `req` | 完整请求对象 |
| `@Response()`, `@Res()` | `res` | 完整响应对象 |
| `@Next()` | `next` | 下一个中间件 |
| `@Session()` | `req.session` | Session 对象 |
| `@Param(key?: string)` | `req.params` | 路由参数 |
| `@Body(key?: string)` | `req.body` | 请求体 |
| `@Query(key?: string)` | `req.query` | 查询字符串 |
| `@Headers(name?: string)` | `req.headers` | 请求头 |
| `@Ip()` | `req.ip` | 客户端 IP |
| `@HostParam()` | `req.hosts` | 主机参数 |

### HTTP 方法装饰器

Nest 为所有标准 HTTP 方法提供了装饰器：

```typescript
import { Controller, Delete, Get, Patch, Post, Put } from '@nestjs/common';
import { AppService } from './app.service';

@Controller()
export class AppController {
    constructor(private readonly appService: AppService) {}

    // ② 匹配 GET http://localhost:3000
    @Get()
    getHello(): string {
        return this.appService.getHello();
    }

    // ② 匹配 GET http://localhost:3000/list
    @Get('/list')
    getHelloList(): string {
        return '这是list页面';
    }

    // ② 匹配 POST http://localhost:3000/list
    @Post('/list')
    create(): string {
        return 'post请求页面';
    }

    // ② 匹配 PUT http://localhost:3000/list
    @Put('/list')
    update(): string {
        return 'put请求页面';
    }

    // ② 匹配 DELETE http://localhost:3000/list
    @Delete('/list')
    delete(): string {
        return 'delete请求页面';
    }

    // ② 匹配 PATCH http://localhost:3000/list
    @Patch('/list')
    patch(): string {
        return 'patch请求页面';
    }
}
```

可用的装饰器：`@Get()`、`@Post()`、`@Put()`、`@Delete()`、`@Patch()`、`@Options()`、`@Head()`、`@All()`。

### 路由参数（@Param）

接受 URL 中的动态参数（如 `GET /user/1`）：

```typescript
// ① 场景：获取指定 ID 的用户
@Get(':id')
findOne(@Param() params: any): string {
    console.log(params.id);
    return `This action returns a #${params.id} cat`;
}
// ② :id 是路由参数标记，@Param() 捕获 URL 中该位置的值
// ③ GET /user/5 → 返回 "This action returns a #5 cat"
```

### 请求负载（@Body + DTO）

使用 `@Body()` 接收客户端 POST/PUT 的数据，配合 DTO 定义类型：

```typescript
// ② DTO（Data Transfer Object）定义数据格式
export class CreateCatDto {
    name: string;
    age: number;
    breed: string;
}

// ② 在控制器中使用 DTO 约束请求体
@Post()
async create(@Body() createCatDto: CreateCatDto) {
    return 'This action adds a new cat';
}
// ③ POST /cat { "name": "Tom", "age": 2, "breed": "Persian" }
```
