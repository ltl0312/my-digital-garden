# HTML5 语义化结构标签

## 📍 知识体系定位
- **所属技术栈**：前端 Vue 3
- **所在层级**：L0 三件套 → HTML5 → 语义标签
- **上游依赖**：<a href="obsidian://open?file=基础语法与文档结构">HTML5-基础语法与文档结构</a>
- **下游延伸**：CSS Flexbox/Grid 布局、无障碍访问（ARIA）
- **同级技术**：CSS3 布局模块（决定这些语义标签的视觉排列方式）

## 概述（Overview）
> HTML5 语义化标签是一组自带含义的结构元素（如 `<header>`、`<nav>`、`<main>`、`<article>`），它们的功能与 `<div>` 相同，但标签名本身就描述了内容类型，有助于搜索引擎优化（SEO）和无障碍访问（屏幕阅读器）。

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：HTML 4 时代，页面结构完全依赖 `<div>` + `id`/`class` 命名约定（如 `<div id="header">`、`<div class="nav">`）。搜索引擎和屏幕阅读器把整个页面视为一大堆无差别的 `<div>`。
- **为什么前身被淘汰**：`<div>` 无语义——机器（搜索引擎爬虫、屏幕阅读器）无法理解页面结构。一个博客文章和一个广告横幅在机器眼中都是 `<div>`。
- **本技术的核心突破**：HTML5 引入了 `header`、`nav`、`main`、`article`、`section`、`aside`、`footer` 等语义标签，让机器可以"读懂"页面结构。搜索引擎能识别 `<article>` 是主要内容，`<nav>` 是导航。
- **为什么是它活下来了**：语义化同时服务于 SEO（Google 更理解页面结构）、无障碍访问（屏幕阅读器提供导航快捷键）和开发者体验（代码更可读）。三赢。

### 设计思想
语义化标签体现了"约定优于命名"的思想——与其让每个开发者用 `<div class="header">` 这样的命名约定，不如直接提供 `<header>` 标签作为标准约定。这降低了搜索引擎和辅助技术理解页面结构的成本。

## 实现（Implementation）

### 完整实例：一个典型的博客页面结构
> 这是使用语义标签构建的页面布局，替代了传统的 `<div id="...">` 命名法。

```html
<!-- ① header：页面头部，通常包含 Logo、主导航、标题 -->
<header>
    <h1>我的博客</h1>
    <!-- ② nav：主导航菜单，告诉屏幕阅读器"这里是导航区域" -->
    <nav>
        <a href="/">首页</a>
        <a href="/about">关于</a>
        <a href="/contact">联系</a>
    </nav>
</header>

<!-- ③ main：页面唯一的主要内容区域，一个页面只能有一个 main -->
<main>
    <!-- ④ article：独立的、可分发的内容块（如一篇博客文章） -->
    <article>
        <h2>HTML5 学习指南</h2>
        <p>文章内容...</p>
        <!-- ⑤ figure + figcaption：图文组合，figcaption 为图片提供标题 -->
        <figure>
            <img src="logo.png" alt="HTML5 Logo">
            <figcaption>图 1: HTML5 Logo</figcaption>
        </figure>
    </article>

    <!-- ⑥ aside：侧边栏，与主要内容相关但可独立存在 -->
    <aside>
        <h3>相关文章推荐</h3>
        <ul>
            <li><a href="#">CSS3 入门</a></li>
            <li><a href="#">JavaScript 基础</a></li>
        </ul>
    </aside>
</main>

<!-- ⑦ footer：页面底部，通常包含版权信息、联系方式 -->
<footer>
    <p>版权所有 &copy; 2026</p>
</footer>
```

> **💡 补充**：`<article>` vs `<section>` 的区分原则：如果一个内容块适合被 RSS 阅读器单独抓取或分享到社交媒体，用 `<article>`；如果只是页面内部的一个章节分区，用 `<section>`。

### 语义标签速查表

| 标签 | 用途 | 注意事项 |
|------|------|---------|
| `<header>` | 页面/区块头部 | 可多次使用（页面 header + 每个 article 的 header） |
| `<nav>` | 主导航链接 | 仅用于主要导航，不是所有链接组都用 nav |
| `<main>` | 文档唯一主要内容 | 一个页面只用一个，不能是 header/nav/article 的子元素 |
| `<article>` | 独立可分发内容块 | 博客文章、新闻报道、论坛帖子 |
| `<section>` | 文档独立章节 | 通常包含标题；可独立分发用 article 优先 |
| `<aside>` | 侧边栏/附加信息 | 广告、相关推荐、侧边导航 |
| `<footer>` | 页面/区块底部 | 版权、联系方式、备案号 |
| `<figure>` | 独立流内容容器 | 图像、图表、代码块等 |
| `<figcaption>` | figure 的标题 | 必须是 figure 的第一个或最后一个子元素 |
