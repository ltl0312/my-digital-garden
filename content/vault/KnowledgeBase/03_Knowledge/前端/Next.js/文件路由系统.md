# Next.js 文件路由系统（Pages Router）

## 📍 知识体系定位
- **所属技术栈**：前端（React 生态）
- **所在层级**：Next.js → 路由层
- **上游依赖**：<a href="obsidian://open?file=框架概述与核心特性">Next.js 框架概述与核心特性</a> — 理解 Next.js 的项目结构
- **下游延伸**：App Router（React Server Components 新路由）、API Routes（BFF 接口层）
- **同级技术**：Vue Router（配置式路由）、React Router（组件式路由）

## 概述（Overview）
> 一句话定义：Next.js 采用**文件系统路由**——`pages/` 目录下的每个 JS/TS 文件自动成为对应 URL 路径的页面。不需要手动写路由配置表，文件路径即路由路径。

```
pages/
├── index.js          →  /
├── about.js          →  /about
├── blog/
│   └── index.js      →  /blog
│   └── [slug].js     →  /blog/:slug（动态路由）
├── api/
│   └── hello.js      →  /api/hello（API 路由）
├── _app.js           →  自定义 App（所有页面的公共外壳）
└── _document.js      →  自定义 HTML 文档结构
```

> ⚠️ **注意**：Next.js 13+ 同时支持 Pages Router（`pages/`）和 App Router（`app/`）。本文基于 Pages Router，它是历史最久、社区资源最多的路由方式。App Router 是 React Server Components 时代的新方案，仍在快速迭代中。

## 设计初衷（Motivation）

### 设计思想
**"约定优于配置"（Convention over Configuration）**。传统 React 项目需要手动安装和配置 React Router，定义路由映射表。Next.js 消除了这种样板代码——放文件即创建路由。这带来的不仅是减少代码量，更重要的是**规范化了项目结构**，团队成员无需争论"路由应该放在哪个文件夹"。

## 实现（Implementation）

### 基础页面

```bash
# ① 场景：在 pages/ 目录下创建文件即创建路由
touch pages/about.js
```

```js
// pages/about.js
// ② 文件名 about → 对应路由 /about
export default function About() {
    return (
        <div>
            <h1>关于页面</h1>
            <p>Next.js 的路由系统让创建新页面变得非常简单。</p>
        </div>
    );
}
// ③ 浏览器访问 http://localhost:3000/about
```

### Link 导航组件

使用 `next/link` 的 `<Link>` 组件实现**客户端路由跳转**（不刷新整个页面）：

```js
// pages/index.js
import Link from 'next/link';

export default function Home() {
    return (
        <div>
            <h1>欢迎来到我的 Next.js 应用</h1>
            {/* ② Link 组件自动预加载目标页面的 JS，实现秒切换 */}
            <Link href="/about">前往关于页面</Link>
        </div>
    );
}
// ③ 点击链接 → 客户端路由切换，浏览器不刷新，页面瞬间展示
```

### 动态路由

```bash
# [slug].js 方括号表示动态路由参数
touch pages/blog/[slug].js
```

```js
// pages/blog/[slug].js
import { useRouter } from 'next/router';

export default function BlogPost() {
    const router = useRouter();
    const { slug } = router.query;   // ② 获取 URL 中的动态参数

    return <h1>博客文章：{slug}</h1>;
}
// ③ 访问 /blog/hello-world → 页面显示"博客文章：hello-world"
```

### 自定义 App（_app.js）

`pages/_app.js` 是所有页面的**公共外壳**——用于注入全局样式、全局状态（Redux Provider）、全局布局：

```js
// pages/_app.js
import '../styles/globals.css';  // ② 全局 CSS 只能在这里导入

export default function MyApp({ Component, pageProps }) {
    // ② Component 是当前页面组件，pageProps 是页面 props
    return <Component {...pageProps} />;
}
```

### 自定义 Document（_document.js）

`pages/_document.js` 用于自定义 HTML 文档结构——如添加 Google Analytics 脚本、自定义 `<html lang>` 等：

```js
import { Html, Head, Main, NextScript } from 'next/document';

export default function Document() {
    return (
        <Html lang="zh-CN">
            <Head />
            <body>
                <Main />
                <NextScript />
            </body>
        </Html>
    );
}
```

### API Routes

`pages/api/` 目录下的文件生成 API 端点（服务端代码，不会打包到客户端）：

```js
// pages/api/hello.js
export default function handler(req, res) {
    res.status(200).json({ message: 'Hello from Next.js!' });
}
// ③ 访问 http://localhost:3000/api/hello → {"message":"Hello from Next.js!"}
```

> **💡 补充**：API Routes 不能在同项目的 `getStaticProps`/`getStaticPaths` 中调用（构建时服务器未启动）。应直接写数据库查询或调用外部 API。
