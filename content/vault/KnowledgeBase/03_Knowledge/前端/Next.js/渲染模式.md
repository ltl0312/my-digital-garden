# Next.js 渲染模式（SSR / SSG / ISR / CSR）

## 📍 知识体系定位
- **所属技术栈**：前端（React 生态）
- **所在层级**：Next.js → 渲染策略层（框架核心差异化能力）
- **上游依赖**：<a href="obsidian://open?file=框架概述与核心特性">Next.js 框架概述与核心特性</a> — 理解 Next.js 的基本定位
- **下游延伸**：<a href="obsidian://open?file=文件路由系统">Next.js 文件路由系统</a> — 渲染模式通过 `getServerSideProps`/`getStaticProps` 等 API 在页面文件中配置
- **同级技术**：Nuxt.js 渲染模式（`useFetch`/`useAsyncData`），传统 SPA 的纯 CSR

## 概述（Overview）
> 一句话定义：Next.js 的核心竞争力在于**按页面粒度选择渲染模式**——同一个项目中，首页可以 SSG（构建时生成）、详情页可以 SSR（请求时渲染）、用户后台可以 CSR（纯客户端渲染）。这四种模式决定了页面的首屏性能和 SEO 表现。

## 四种渲染模式对比

```text
        构建时 (Build)          请求时 (Request)         客户端 (Browser)
            │                       │                       │
    ┌───────┴───────┐       ┌───────┴───────┐       ┌───────┴───────┐
    │     SSG       │       │     SSR       │       │     CSR       │
    │  getStaticProps│       │getServerSide  │       │  React.useEffect│
    │  (纯静态)      │       │Props (动态)   │       │  (客户端获取)   │
    └───────────────┘       └───────────────┘       └───────────────┘
            │                       │
            └───────────┬───────────┘
                        │
                ┌───────┴───────┐
                │     ISR       │
                │  revalidate   │
                │ (定时再生)     │
                └───────────────┘
```

| 渲染模式 | 数据获取时机 | 首屏速度 | SEO 友好 | 适用场景 |
|---------|------------|---------|---------|---------|
| **SSG** 静态生成 | 构建时 | ⚡ 最快（CDN） | ✅ | 博客、文档、营销页（内容不常变） |
| **SSR** 服务端渲染 | 每次请求 | 🔶 中等 | ✅ | 电商商品页、个性化首页（实时数据） |
| **ISR** 增量静态再生 | 构建时 + 定时更新 | ⚡ 快（CDN + 后台更新） | ✅ | 博客（内容偶尔更新）、CMS 页面 |
| **CSR** 客户端渲染 | 浏览器端 | 🐢 慢（白屏） | ❌ | 管理后台、登录后页面（无需 SEO） |

### 关键公式

```
SSG + revalidate = ISR
（静态生成后，每 N 秒在后台重新生成一次）
```

## 设计初衷（Motivation）

### 历史演进

传统 React 应用（CRA）只有 CSR 一种模式：浏览器下载空 HTML + JS bundle，然后 JS 执行渲染。这导致两个致命问题：
1. **首屏白屏时间长**：用户看到内容前必须等待 JS 下载、解析、执行
2. **SEO 不友好**：搜索引擎爬虫看到的是空 `<div id="root">`

Next.js 的解决方案依次演进：
- **SSR**（最早）：每次请求在服务端渲染 HTML，解决了 SEO 和白屏，但服务器压力大
- **SSG**：构建时预渲染，HTML 直接放 CDN，性能极致但内容不实时
- **ISR**：SSG + revalidate，兼顾性能和内容新鲜度——是当前最推荐的混合方案

### 设计思想

**按页面粒度选择策略**：Next.js 不强制全局统一模式。首页用 SSG（CDN 秒开），商品详情用 SSR（实时库存），后台管理用 CSR（无需 SEO）。这种"混合渲染"是 Next.js 区别于传统 SSR 框架（如 Express + EJS）的核心差异。

## 实现（Implementation）

### SSG：静态生成

```js
// pages/index.js
// ② getStaticProps 在构建时运行，返回的 props 注入页面组件
export async function getStaticProps() {
    const posts = await fetch('https://api.example.com/posts').then(r => r.json());
    return { props: { posts } };
}

export default function Home({ posts }) {
    return <ul>{posts.map(p => <li key={p.id}>{p.title}</li>)}</ul>;
}
// ③ 构建后生成纯 HTML 文件，可部署到 CDN
```

### SSR：服务端渲染

```js
// pages/product/[id].js
// ② getServerSideProps 在每次请求时运行，context 包含 req/res 和路由参数
export async function getServerSideProps(context) {
    const { id } = context.params;
    const product = await fetch(`https://api.example.com/product/${id}`).then(r => r.json());
    return { props: { product } };
}

export default function Product({ product }) {
    return <div>{product.name}: ¥{product.price}</div>;
}
// ③ 每次访问 /product/123 时，服务端实时获取数据并渲染 HTML
```

### ISR：增量静态再生

```js
// pages/blog/[slug].js
export async function getStaticProps({ params }) {
    const post = await fetch(`https://api.example.com/post/${params.slug}`).then(r => r.json());
    return {
        props: { post },
        revalidate: 60,  // ② 每 60 秒在后台重新生成此页面
    };
}

export async function getStaticPaths() {
    const posts = await fetch('https://api.example.com/posts').then(r => r.json());
    return {
        paths: posts.map(p => ({ params: { slug: p.slug } })),
        fallback: 'blocking',  // ② 未预生成的页面首次请求时 SSR 生成并缓存
    };
}
// ③ 首次访问 → SSG 返回缓存页面 → 60 秒后后台重新生成 → 下次访问拿到新页面
```

### CSR：纯客户端渲染

不定义 `getServerSideProps` 或 `getStaticProps` 的页面默认为静态页面（SSG），如果页面包含客户端数据获取（如 `useEffect` + `fetch`），则数据获取部分退化为 CSR：

```js
import { useEffect, useState } from 'react';

export default function Dashboard() {
    const [data, setData] = useState(null);
    useEffect(() => {
        fetch('/api/dashboard').then(r => r.json()).then(setData);
    }, []);
    if (!data) return <div>Loading...</div>;
    return <div>{data.content}</div>;
}
// ③ 页面 HTML 先返回 Loading 状态，JS 执行后客户端获取真实数据
```
