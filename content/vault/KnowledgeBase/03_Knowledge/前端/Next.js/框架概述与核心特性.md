# Next.js 框架概述与核心特性

## 📍 知识体系定位
- **所属技术栈**：前端（React 生态）
- **所在层级**：Next.js → L4 全栈与 SSR（对标 Vue 技术划分中 Nuxt.js 的 L4 层级）
- **上游依赖**：React 基础（JSX、组件、Hooks）、<a href="obsidian://open?file=基础与特殊类型">TypeScript 基础</a> — Next.js 对 TypeScript 有一流支持
- **下游延伸**：Next.js App Router（React Server Components）、API Routes（BFF 层）
- **同级技术**：<a href="obsidian://open?file=MOC - Vue3">Nuxt.js</a>（Vue 生态的 SSR 框架）、Gatsby（React 静态站点生成器）、Remix（React 全栈框架）

## 概述（Overview）
> 一句话定义：Next.js 是一个基于 React 的 **web 应用框架**，提供开箱即用的工程化机制、智能文件路由系统、多种渲染模式（SSR/SSG/ISR/CSR），让 React 开发者无需手动配置 webpack 即可构建生产级全栈应用。

Next.js 主要做的事情：
1. **完善的工程化机制**：内置 babel、postcss、TypeScript、eslint、CSS Modules，自带 tree shaking、代码压缩、按需打包
2. **良好的开发和构建性能**：使用 turbopack 编译（Rust 实现），开发模式秒启动，增量编译
3. **智能文件路由系统**：`pages/` 或 `app/` 目录下的文件自动成为路由
4. **多种渲染模式**：SSR（服务端渲染）、SSG（静态生成）、ISR（增量静态再生成）、CSR（客户端渲染）
5. **可扩展配置**：暴露 webpack 实例、支持自定义 server/middleware/babel/postcss
6. **性能优化方案**：图片优化（next/image）、字体优化（next/font）
7. **性能数据**：`reportWebVitals` API 获取 Core Web Vitals
8. **扩展能力**：API Routes、MDX 支持、AMP 支持

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：React 官方的 **Create React App (CRA)** 脚手架，提供零配置的 React 单页应用搭建。但 CRA 只做 CSR（客户端渲染），不支持 SSR/SSG，且暴露 webpack 配置需要 `eject`。
- **为什么前身被淘汰**：CRA 已近两年没有新版本（最后更新 2022 年 4 月），社区公认其已被放弃。React 官方文档现在推荐 Next.js 和 Gatsby 作为替代方案。CRA 无法支持 React 18 的 Server Component、Client Component 等新范式。
- **本技术的核心突破**：Next.js 将 React 从"纯客户端渲染库"升级为"全栈应用框架"——同一个项目中可以混合使用 SSR、SSG、ISR、CSR 四种渲染策略，按页面粒度选择最优方案。
- **为什么是它活下来了**：Gatsby 专注于 SSG（静态站点），Remix 起步较晚。Next.js 由 Vercel 公司持续投入（turbopack、App Router、React Server Components），社区最大、生态最全，且 SSR/SSG/ISR 覆盖了从内容站到 SaaS 的全场景。
- **当前版本**：Next.js 15.x（2024-2025），基于 React 19，turbopack 已稳定。

### 设计思想
Next.js 的核心理念是 **"渐进式复杂度"**——默认配置就能用，但几乎所有配置都可以完全控制。它不强迫你选择 Pages Router 还是 App Router，不强迫你用 SSG 还是 SSR，而是提供选项让开发者按页面粒度决定。这与 React 的"渐进式采用"哲学一脉相承。
