# JavaScript 事件处理机制

## 📍 知识体系定位
- **所属技术栈**：前端 Vue 3
- **所在层级**：L0 三件套 → JavaScript → 事件编程
- **上游依赖**：<a href="obsidian://open?file=函数与参数">JavaScript-函数与参数</a>、<a href="obsidian://open?file=DOM与BOM操作">JavaScript-DOM与BOM操作</a>
- **下游延伸**：Vue 3 事件处理（`@click`、`$emit`）、RxJS 响应式编程
- **同级技术**：HTML 行内事件（`onclick="..."`）、jQuery 事件（`.on()`）

## 概述（Overview）
> JavaScript 事件机制基于**观察者模式**——通过 `addEventListener` 注册监听器，当用户交互（click/keydown/submit）或浏览器状态变化（load/scroll/resize）时触发回调。核心概念包括：**事件冒泡**（从目标元素向上传播）、**事件捕获**（从根元素向下捕获）、**事件委托**（利用冒泡在父元素统一处理子元素事件）。

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：DOM0 级事件 `element.onclick = fn` — 简单但每个事件只能绑定一个处理函数（后绑定的覆盖前面的）。DOM2 级 `addEventListener` 支持多个监听器。
- **为什么前身被淘汰**：单函数绑定的限制使组件化开发几乎不可能——两个独立的脚本都想处理同一个按钮的 click 事件，后者会覆盖前者。
- **本技术的核心突破**：`addEventListener` 支持同一元素同一事件的多个监听器；事件委托利用冒泡机制在父元素统一处理，大幅减少监听器数量。
- **当前版本**：DOM Level 3 Events

### 设计思想
事件冒泡是 JS 事件模型最巧妙的设计——它允许"委托"模式：在包含 1000 个 `<li>` 的 `<ul>` 上绑一个监听器，就能处理所有 `<li>` 的点击，而非在每个 `<li>` 上绑 1000 个监听器。Netscape 的捕获模型（从外到内）和 IE 的冒泡模型（从内到外）曾是浏览器大战的核心分歧，W3C 最终采纳了两者——`addEventListener` 的第三个参数控制捕获/冒泡。

### 跨学科溯源
- 事件委托 → <a href="obsidian://open?file=XD-5 数据结构与算法">XD-5 数据结构与算法</a>（DOM 树的冒泡向上传播 = 叶子到根的路径遍历）

## 实现（Implementation）

### 绑定与解绑事件

```javascript
const btn = document.getElementById('myBtn');

// ① DOM2 级（推荐）：addEventListener(事件名, 回调, 是否捕获)
btn.addEventListener('click', function(e) {
    console.log('按钮被点击', e);
}, false); // false=冒泡阶段（默认），true=捕获阶段

// ② 移除监听器（必须是具名函数，匿名函数无法移除）
function handler(e) { }
btn.addEventListener('click', handler);
btn.removeEventListener('click', handler); // 移除

// ③ 一次性事件（{ once: true } 选项）
btn.addEventListener('click', () => {}, { once: true });
```

### Event 对象核心属性

```javascript
btn.addEventListener('click', function(e) {
    e.type;            // "click" — 事件类型
    e.target;          // ★ 触发事件的最底层源头元素（点击的实际元素）
    e.currentTarget;   // ★ 绑定事件的当前元素（等同于 this）
    e.clientX;         // 鼠标相对于视口的 X 坐标
    e.clientY;         // Y 坐标
    e.key;             // 键盘事件：按下的键名（如 "Enter"）

    e.preventDefault();    // 阻止默认行为（如阻止链接跳转、表单提交）
    e.stopPropagation();   // 阻止事件向上冒泡
    // e.stopImmediatePropagation(); // 阻止冒泡且阻止同一元素上的其他监听器
});
```

### 事件委托（核心模式）

```javascript
// ❌ 低效：每个 li 绑定一个监听器（1000 个 li = 1000 个监听器）
document.querySelectorAll('li').forEach(li => {
    li.addEventListener('click', handleClick);
});

// ✅ 高效：在父元素 ul 上绑定一个监听器
document.getElementById('parent-ul').addEventListener('click', function(e) {
    // 判断实际点击的是否为 li 标签
    if (e.target.tagName.toLowerCase() === 'li') {
        console.log('Clicked on:', e.target.textContent);
    }
    // 或用 closest 查找最近的匹配祖先
    const li = e.target.closest('li');
    if (li && this.contains(li)) {
        console.log('Clicked on:', li.dataset.id);
    }
});
```

### 常见事件类型速查

```javascript
// 鼠标事件
click, dblclick, mousedown, mouseup, mousemove,
mouseenter, mouseleave, // 不会冒泡
mouseover, mouseout,    // 会冒泡（含子元素触发）
contextmenu             // 右键菜单

// 键盘事件
keydown, keyup, keypress // (keypress 已废弃)
// 常用：e.key === "Enter" / "Escape" / "ArrowUp"

// 表单事件
submit, change, input, focus, blur, reset

// 窗口/文档事件（性能关键）
DOMContentLoaded,    // ★ DOM 树解析完就触发（早于 load）
load,                // 所有资源（图片/CSS）加载完才触发
resize, scroll,      // ★ 高频触发，必须节流/防抖
beforeunload         // 页面即将卸载
```

> **💡 补充**：`scroll` 和 `resize` 事件每秒可能触发数十次——直接在回调中执行重操作会导致卡顿。使用 `requestAnimationFrame` 节流或 `debounce` 防抖处理。
