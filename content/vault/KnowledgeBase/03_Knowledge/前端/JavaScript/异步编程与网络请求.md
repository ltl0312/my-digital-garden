# JavaScript 异步编程与网络请求

## 📍 知识体系定位
- **所属技术栈**：前端 Vue 3
- **所在层级**：L0 三件套 → JavaScript → 异步编程
- **上游依赖**：<a href="obsidian://open?file=函数与参数">JavaScript-函数与参数</a>（回调函数）、<a href="obsidian://open?file=面向对象与ES6+">JavaScript-面向对象与ES6+</a>（Promise 是 ES6 class）
- **下游延伸**：Axios HTTP 库、Vue 3 `watchEffect`、React Suspense
- **同级技术**：Python asyncio、Java CompletableFuture

## 概述（Overview）
> JavaScript 是单线程语言，通过**事件循环（Event Loop）**实现异步非阻塞。ES6 引入 **Promise** 解决回调地狱，ES8 引入 **async/await** 让异步代码以同步风格编写。**Fetch API** 是现代浏览器原生的 HTTP 请求接口，替代了老旧的 XMLHttpRequest。

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：ES5 时代，异步编程只能靠回调函数嵌套。多个依赖操作导致"回调地狱"——层层嵌套的 `})` 金字塔，不可读、不可维护、不可调试。
- **本技术的核心突破**：Promise（ES6）将异步操作对象化——`.then()` 链式调用替代嵌套；async/await（ES8）让异步代码读起来像同步代码——`try/catch` 替代 `.catch()`，线性代码流替代链式调用。
- **为什么是它活下来了**：async/await 是 JS 异步编程的终局方案，几乎所有现代 JS 代码都用它。Fetch API 以 Promise 为基础，API 比 XMLHttpRequest 简洁一个数量级。
- **当前版本**：ES8+（async/await），ES11（Promise.allSettled）

### 设计思想
JS 的异步模型基于"事件循环（Event Loop）"——主线程执行同步代码，异步任务（定时器、网络请求、事件）完成后将回调推入任务队列，主线程空闲时取队列中的任务执行。Promise 的 `.then()` 回调进入**微任务队列**（优先级高于宏任务），这是 `setTimeout(0)` 不精确的根本原因。

### 跨学科溯源
- 事件循环 → <a href="obsidian://open?file=XD-2 操作系统">XD-2 操作系统</a>（单线程进程通过事件循环实现 I/O 多路复用，类似 Node.js libuv 的 epoll/kqueue）
- Promise 状态机 → <a href="obsidian://open?file=XD-5 数据结构与算法">XD-5 数据结构与算法</a>（有限状态机 FSM：pending → fulfilled/rejected，状态不可逆）
- Fetch API → <a href="obsidian://open?file=XD-3 计算机网络">XD-3 计算机网络</a>（HTTP/1.1 请求-响应模型，Content-Type 头，CORS 跨域策略）

## 实现（Implementation）

### Promise 核心用法

```javascript
// ① 创建 Promise
const myPromise = new Promise((resolve, reject) => {
    setTimeout(() => {
        const success = true;
        if (success) {
            resolve("操作成功的数据"); // pending → fulfilled
        } else {
            reject("发生错误");        // pending → rejected
        }
    }, 1000);
});

// ② 消费 Promise
myPromise
    .then(data => console.log(data))   // 捕获 resolve
    .catch(error => console.error(error)) // 捕获 reject
    .finally(() => console.log("总会执行"));

// ③ Promise 静态方法
Promise.all([p1, p2, p3]);         // 全部成功 → then，任一失败 → catch
Promise.allSettled([p1, p2, p3]);  // 等全部完成（无论成败），返回状态数组（ES11）
Promise.race([p1, p2, p3]);        // 第一个完成就返回（无论成败）
Promise.any([p1, p2, p3]);         // 第一个成功就返回，全失败才 reject（ES12）
Promise.resolve(value);            // 创建已解决的 Promise
Promise.reject(error);             // 创建已拒绝的 Promise
```

### async / await（终极方案）

```javascript
// async 函数自动返回 Promise
async function fetchUserData() {
    try {
        // await 暂停执行直到 Promise settled
        const response = await fetch('https://api.example.com/user/1');

        if (!response.ok) {
            throw new Error(`HTTP error! status: ${response.status}`);
        }

        const data = await response.json(); // 解析 JSON
        console.log(data.name);
        return data; // 自动包装为 Promise.resolve(data)
    } catch (error) {
        console.error("获取失败:", error.message);
    }
}

// 调用
fetchUserData().then(data => console.log("Done:", data));

// ★ 常见错误：忘记 await
async function bugDemo() {
    const data = fetch('/api'); // ❌ data 是 Promise，不是响应数据
    const data = await fetch('/api'); // ✅ 等到的才是数据
}
```

### Fetch API 完整示例

```javascript
// GET 请求
const response = await fetch('https://api.example.com/data');
const data = await response.json(); // .json() 也返回 Promise！
console.log(data);

// POST 请求（配置 method, headers, body）
const response = await fetch('https://api.example.com/data', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json', // 告诉服务器发送的是 JSON
    },
    body: JSON.stringify({ name: "Alice", age: 25 }), // 对象 → JSON 字符串
});
const result = await response.json();

// 错误处理完整模式
async function safeFetch(url, options = {}) {
    try {
        const res = await fetch(url, options);
        if (!res.ok) throw new Error(`HTTP ${res.status}: ${res.statusText}`);
        return await res.json();
    } catch (err) {
        if (err.name === 'TypeError') {
            // 网络错误（断网、DNS 解析失败、CORS 阻断）
            console.error('网络请求失败', err);
        } else {
            console.error('请求错误', err);
        }
        throw err; // 向上传播
    }
}
```

> **💡 补充**：`Promise.all()` vs `Promise.allSettled()` — all 是"一票否决"（任一失败即整体失败），适合必须全部成功的场景；allSettled 是"全量统计"（等全部完成无论成败），适合需要知道每个操作各自结果的场景。
