## 一、中间件（Middleware）：路由守卫

中间件是在**页面渲染前**执行的代码，用于身份验证、权限控制、日志记录。

### 创建中间件

```javascript
// middleware/auth.js
export default function ({ redirect, store }) {
  // ② 假设 Pinia 存储用户登录状态
  if (!store.auth.isLoggedIn) {
    return redirect('/login')  // ② 未登录 → 重定向到登录页
  }
}
```

### 应用中间件

```javascript
// nuxt.config.js — ② 全局生效（所有路由）
export default {
  router: { middleware: ['auth'] }
}
```

```vue
<!-- ② 页面级生效（仅当前页面） -->
<script>
export default {
  middleware: 'auth'
}
</script>
```

## 二、插件（Plugins）：扩展 Nuxt 能力

插件在 Vue 根实例化之前运行，用于注册全局组件、注入全局方法、封装第三方库。

### Axios 拦截器插件

```javascript
// plugins/axios.js
export default function ({ $axios, store }) {
  // ② 请求拦截：自动添加鉴权 Token
  $axios.onRequest(config => {
    config.headers['Authorization'] = `Bearer ${store.auth.token}`
    return config
  })

  // ② 错误拦截：Token 过期 → 跳转登录
  $axios.onError(error => {
    if (error.response?.status === 401) {
      window.location.href = '/login?expired=1'
    }
    return Promise.reject(error)
  })
}

// nuxt.config.js
export default {
  plugins: ['@/plugins/axios']
}
```

### 全局方法注入

```javascript
// plugins/ctx-inject.js — ② 为 context 注入全局错误处理方法
export default (ctx, inject) => {
  ctx.$errorHandler = err => {
    try {
      ctx.error({ statusCode: 500, message: err.message })
    } catch {
      ctx.error({ statusCode: 500, message: '服务器开小差了~' })
    }
  }
}
```

### ElementUI 集成

```bash
npm i element-ui -S
```

```javascript
// plugins/element-ui.js
import Vue from 'vue'
import ElementUI from 'element-ui'
Vue.use(ElementUI)

// nuxt.config.js
export default {
  css: ['element-ui/lib/theme-chalk/index.css'],
  plugins: ['@/plugins/element-ui']
}
```

> **💡 补充**：插件中可通过 `ssr: false` 控制是否在服务端运行。纯浏览器端插件（如微信 JS-SDK、高德地图）需要关闭 SSR。

## 三、部署方案

### SSG 部署（静态站点）

```javascript
// nuxt.config.js
export default { target: 'static' }
```

```bash
npm run generate  # ② 生成静态文件到 dist/ 目录
# ③ 将 dist/ 上传到阿里云 OSS、腾讯云 COS、Gitee Pages 等静态托管平台
```

**适用场景**：博客、企业官网、文档站（内容不常变）

### SSR 部署（服务端渲染）

```bash
npm run build           # ② 构建生产包
npm run start           # ② 启动 Node.js 服务（默认 :3000）
```

**使用 PM2 守护进程**：

```bash
npm install pm2 -g
pm2 start "npm run start" --name nuxt-app
# ③ PM2 自动重启崩溃的进程，支持集群模式
```

**Docker 部署**：

```dockerfile
FROM node:16-alpine
WORKDIR /app
COPY . .
RUN npm install --production
RUN npm run build
EXPOSE 3000
CMD ["npm", "start"]
```

**适用场景**：电商、社交平台（实时数据 + SEO）

### 国内性能优化

| 优化项 | 方案 |
|--------|------|
| **CDN 加速** | 阿里云 CDN / 腾讯云 CDN，静态资源托管到 CDN |
| **图片优化** | `<NuxtImg loading="lazy" :modifiers="{ format: 'webp' }" />` |
| **代码压缩** | `build: { compress: { brotli: true, gzip: true } }` |
| **SSR 缓存** | 页面级缓存 + Redis 热点数据缓存 |
| **监控** | 阿里云 ARMS（应用监控）+ Sentry 国内版（错误追踪） |

## 四、Nuxt 生命周期

Nuxt 扩展了 Vue 的生命周期，服务端特有的钩子如下：

```javascript
export default {
  middleware () {},   // ② 服务端：中间件
  validate () {},     // ② 服务端：路由参数校验
  asyncData () {},    // ② 服务端：数据预获取（Nuxt 2）
  fetch () {},        // ② 服务端/客户端：store 数据加载
  beforeCreate () {}, // ② 服务端和客户端都会执行
  created () {},      // ② 服务端和客户端都会执行
  mounted () {}       // ② 仅客户端执行
}
```

> ⚠️ `mounted` 仅在客户端运行，这里的代码不会影响 SEO。涉及 `window`、`document` 等浏览器 API 的代码应放在 `mounted` 中。
