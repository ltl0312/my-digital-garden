# TypeScript 基础与特殊类型

## 📍 知识体系定位
- **所属技术栈**：前端 Vue 3
- **所在层级**：L3 工程化 → TypeScript
- **上游依赖**：<a href="obsidian://open?file=基础语法与数据类型">JavaScript-基础语法与数据类型</a>（TS 是 JS 的超集）
- **下游延伸**：Vue 3 + TS 组件开发、Angular、NestJS
- **同级技术**：ESLint（代码规范）、Prettier（格式化）

## 概述（Overview）
> TypeScript 是 JavaScript 的**静态类型超集**——所有合法的 JS 代码都是合法的 TS 代码。TS 在 JS 基础上增加了静态类型系统，在编译阶段捕获类型错误。`any`/`unknown`/`void`/`never` 四种特殊类型覆盖了"放弃检查""安全未知""无返回值""永不返回"四种场景。

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：JavaScript 是动态弱类型语言，类型错误只能在运行时暴露（`undefined is not a function`）。大型项目中重构一段代码，不知道哪些地方会受影响。
- **本技术的核心突破**：TypeScript（微软 2012 发布）为 JS 增加了可选的静态类型系统。编译时类型检查 + IDE 智能提示 + 重构安全 = 大型 JS 项目的最佳实践。
- **为什么是它活下来了**：TS 是 JS 超集（而非新语言），渐进式采用（先 `.js` 再 `.ts`），微软 + Google（Angular 用 TS）的双重背书，VS Code 对 TS 的一流支持。
- **当前版本**：TypeScript 5.x

> ⚠️ **版本兼容性**：TS 编译为任意 ES 版本的 JS（通过 tsconfig.json 的 target 配置，如 ES5/ES6/ESNext）。

### 设计思想
`unknown` 是 TS 类型系统安全哲学的集中体现——"如果你不知道类型，我会阻止你随意操作它，直到你证明你知道"。`any` 是逃生舱（完全放弃检查），`unknown` 是安全版本（先检查再用）。`never` 用于穷尽性检查——switch 的 default 分支中，如果所有 case 已覆盖，剩余值被推断为 `never`。

### 跨学科溯源
- TS 类型检查 → <a href="obsidian://open?file=XD-4 编程语言与编译">XD-4 编程语言与编译</a>（静态类型系统的 Hindley-Milner 类型推导算法的工程化实现）
- `never` 穷尽检查 → <a href="obsidian://open?file=XD-5 数据结构与算法">XD-5 数据结构与算法</a>（集合论：空集 never 是其他类型的子类型）

## 实现（Implementation）

### 基础类型

```typescript
let isDone: boolean = false;
let age: number = 20;              // 支持十进制、十六进制、二进制、八进制
let firstName: string = "Tom";
let sym: symbol = Symbol("key");
let big: bigint = 100n;           // BigInt（ES2020+）
```

类型注解——: number等，是添加类型约束的
### any vs unknown

```typescript
// ❌ any：完全放弃类型检查（危险）
let risky: any = 4;
risky.toFixed();       // 编译通过，但运行时如果 risky 不是 number 就报错
risky.anyMethod();     // 编译通过（TS 不检查 any 上的任何操作）

// ✅ unknown：安全的"不知道类型"
let safe: unknown = 4;
// safe.toFixed();     // ❌ 编译错误：类型 unknown 上不存在属性 toFixed
if (typeof safe === "number") {
    safe.toFixed(2);   // ✅ 类型缩窄（Type Narrowing）后才可操作
}
```

### void 与 never

```typescript
// void：函数无返回值（隐式返回 undefined）
function logMessage(msg: string): void {
    console.log(msg);
}

// never：函数永不正常返回（抛出异常或死循环）
function throwError(message: string): never {
    throw new Error(message);
}
function infiniteLoop(): never {
    while (true) {}
}

// ★ never 的实用场景：穷尽检查
type Shape = "circle" | "square";
function getArea(shape: Shape) {
    switch (shape) {
        case "circle": return Math.PI;
        case "square": return 4;
        default:
            // shape 此时类型为 never（所有可能已被覆盖）
            const _exhaustive: never = shape;  // 如果 Shape 新增了类型，这里会编译报错
            return _exhaustive;
    }
}
```

> **💡 补充**：`any` vs `unknown` 的选择原则——永远优先用 `unknown`。只有在两种情况下用 `any`：① 渐进式迁移 JS 项目时的临时方案 ② 确实需要动态特性（如第三方库无类型定义且暂时无时间写 `.d.ts`）。

> **💡 补充**（隐式 any）：除了显式声明 `any`，还有两种"隐式 any"场景——声明变量不提供类型也不提供默认值（`let x;` → x 是隐式 any）；函数参数不加类型（`function f(a) {}` → a 是隐式 any）。因为不推荐使用 any，这两种情况下都应该提供类型。开启 `strict: true` 后，TS 会对隐式 any 直接报错（noImplicitAny），强制显式标注。
