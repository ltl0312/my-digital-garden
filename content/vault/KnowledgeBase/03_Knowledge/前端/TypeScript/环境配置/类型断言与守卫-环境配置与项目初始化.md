# TypeScript 类型断言与守卫 — 环境配置

## 前置条件
- TS 开发环境（参考 <a href="obsidian://open?file=基础语法-环境配置与项目初始化">TypeScript-基础语法-环境配置与项目初始化</a>）

## Step 1: 类型守卫验证

```typescript
// VS Code 中观察类型缩窄
function process(val: string | number) {
    console.log(val);         // 悬停：string | number
    if (typeof val === "string") {
        console.log(val);     // 悬停：string（已缩窄）
    }
}

// 自定义守卫
type Cat = { meow: () => void };
type Dog = { bark: () => void };
function isDog(animal: Cat | Dog): animal is Dog {
    return "bark" in animal;
}
```

## Step 2: 断言 vs 守卫选择原则

| 场景 | 方案 |
|------|------|
| 你确定类型且运行时一定是 | `as` 断言 |
| 类型在运行时可能变化 | 类型守卫（typeof/instanceof/in） |
| 复杂的自定义判断 | `pet is Fish` 类型谓词 |

## 常见问题

1. **`as` 断言后仍报错**：TS 会检查断言是否有交集——`"hello" as number` 报错（完全不重叠的类型不能断言），用 `as unknown as number` 绕过（危险）。
2. **自定义守卫误用**：`pet is Fish` 返回 true 时 TS 相信类型是 Fish，但守卫函数内的逻辑可能有 bug。守卫的运行时正确性由你负责。
