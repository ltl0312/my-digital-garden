## Step 1: 开启 strict 模式

类型兼容性的许多"坑"由 strict 族配置控制，项目初始化时优先开启：

```json
// tsconfig.json
{
  "compilerOptions": {
    "strict": true
  }
}
```

`strict: true` 一次性开启 `strictNullChecks`、`strictFunctionTypes`、`noImplicitAny`、`strictPropertyInitialization` 等全部严格检查 [来源: TS 官方 tsconfig 文档]。

## Step 2: 验证 strictFunctionTypes 对兼容性的影响

```typescript
// strictFunctionTypes: true 时，函数类型参数走严格逆变检查
interface Event { timestamp: number }
interface MouseEvent extends Event { x: number; y: number }

// 方法（method）写法保持双变，属性（property）写法严格逆变
type HandlerProp = (event: Event) => void;
const propHandler: HandlerProp = (e: MouseEvent) => {};   // ❌ strict 下报错（属性写法）
```

**预期**：取消注释后 `tsc` 报参数逆变错误；将写法改为 method 形式则不报。

## Step 4: 最小可运行示例

```typescript
// src/compat.ts
class Point { x: number; y: number; constructor(x: number, y: number) { this.x = x; this.y = y; } }
class Point3D { x: number; y: number; z: number; constructor(x: number, y: number, z: number) { this.x = x; this.y = y; this.z = z; } }

const p: Point = new Point3D(1, 2, 3);   // ✅ 成员多赋给成员少
console.log(p.x + p.y);                  // 输出: 3
```

## Step 5: 核心配置项说明

| 配置项 | 默认值 | 推荐值 | 原因 |
|--------|--------|--------|------|
| `strict` | `false` | `true` | 一次性开启全部严格检查，兼容性错误尽早暴露 |
| `strictFunctionTypes` | `false`（随 strict 变 true） | `true` | 函数参数逆变检查，防止不安全赋值 |
| `strictNullChecks` | `false`（随 strict 变 true） | `true` | null/undefined 不可隐式赋值，兼容性判定更严格 |
| `strictPropertyInitialization` | `false`（随 strict 变 true） | `true` | 类属性必须初始化，与结构化检查配合 |

## 常见安装/配置问题

1. **strict 开启后大量旧代码报错**：迁移项目可先开 `strictNullChecks` 之外的分项，逐步收紧。结构兼容错误多为"成员少的赋给成员多的"或函数参数方向写反。
2. **方法 vs 属性写法报错不一致**：同一函数签名，method 写法兼容、property 写法报错，是 `strictFunctionTypes` 的正常行为——接口函数属性（`handler: (e: T) => void`）用属性写法即可获得严格检查。
3. **`tsc --noEmit` 无输出但 IDE 报红**：确保 IDE 使用项目内 TS 版本（VS Code 状态栏选择 "Use Workspace Version"）。
