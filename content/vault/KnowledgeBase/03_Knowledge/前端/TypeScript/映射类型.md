# TypeScript 映射类型

## 📍 知识体系定位
- **所属技术栈**：前端 Vue 3
- **所在层级**：L3 工程化 → TypeScript → 类型操作
- **上游依赖**：<a href="obsidian://open?file=索引签名与索引访问类型">TypeScript-索引签名与索引访问类型</a>（映射类型基于索引签名语法）、<a href="obsidian://open?file=泛型">TypeScript-泛型</a>（`keyof` 提供键集合）
- **下游延伸**：<a href="obsidian://open?file=工具类型与装饰器">TypeScript-工具类型与装饰器</a>（Partial/Readonly 等的源码就是映射类型）、条件类型
- **同级技术**：Java 的泛型变换（无等价物，TS 映射类型在类型层面独一无二）

## 概述（Overview）
> **映射类型（Mapped Types）**基于旧类型创建新类型——用 `[Key in 联合类型]` 遍历一组键，逐键生成新属性，从而"批量变换"对象的形状。一句话：**基于旧类型创建新类型（对象类型），减少重复，提高开发效率**。

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：手工复制粘贴——要为 `Todo` 写一个"全部属性可选"的版本，只能新建一个 interface 把每个属性重新声明一遍加 `?`；属性一多，重复声明即灾难。
- **为什么前身被淘汰**：重复 = 脆弱。Todo 增加一个属性，PartialTodo 就要同步改，漏改即产生与实际结构不一致的"僵尸类型"。
- **本技术的核心突破**：映射类型在类型层面实现了"遍历 + 变换"——`{ [K in keyof Todo]?: Todo[K] }` 一行代码派生出完整的新类型，新属性自动跟随旧类型演变。
- **为什么是它活下来了**：它是 TS 所有内置工具类型（Partial/Readonly/Pick/Record...）的**底层实现机制**——工具类型都是基于映射类型实现的。没有映射类型，工具类型就只能逐个手写，TS 的类型元编程大厦将崩塌。
- **当前版本**：TypeScript 5.x。TS 4.1+ 支持 `as` 重映射键（`[K in Keys as NewKey]`）。

### 设计思想
映射类型体现了"类型元编程"——类型不是死的定义，而是可以被**遍历、变换、组合**的一等公民。语法上它基于索引签名类型（同样使用 `[]`），但语义相反：索引签名是"接受任意键"，映射类型是"枚举已知键"（Key in ProKeys 表示 Key 可以是 ProKeys 联合类型中的任意一个）。它只能在 type 别名中使用，**不能在 interface 中使用**——因为 interface 要求静态可声明合并，而映射类型是计算产物。

## 实现（Implementation）

### 完整实例：从联合类型和对象类型创建新类型

```typescript
// ① 场景：把一组键全部映射为同一类型 → 与手写结构完全等价
type ProKeys = 'x' | 'y' | 'z';
type Type1 = { x: number; y: number; z: number };   // 手写版本
type Type2 = { [Key in ProKeys]: number };          // 映射版本
// Key in ProKeys 表示 Key 可以是 ProKeys 联合类型中的任意一个
// Type1 和 Type2 结构完全相同 —— 输入 3 个键 → 输出 3 个 number 属性

// ② 基于对象类型创建：keyof 取出键集合再映射
type Props = { x: number; y: string; z: boolean };
type Type3 = { [key in keyof Props]: number };
// keyof Props = 'x' | 'y' | 'z'，所以 Type3 = { x: number; y: number; z: number }
// 值类型统一替换为 number，键集合自动跟随 Props 演变

// ③ 修饰符与索引访问配合：这就是内置工具类型 Partial 的源码
type MyPartial<T> = { [K in keyof T]?: T[K] };
// ? 添加可选修饰符；T[K] 索引访问保留原值类型（映射类型的招牌用法）

type MyReadonly<T> = { readonly [K in keyof T]: T[K] };
// readonly 添加只读修饰符 —— 内置 Readonly<T> 的实现

// ④ TS 4.1+ 键重映射：过滤或改名键
type Getters<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] };
// as 重写键名：{ x: number } → { getX: () => number }
```

> **💡 补充**：映射类型借用了索引签名类型的 `[]` 语法，语法结构相似，但两者目标相反——索引签名声明"对象可以有任意键"，映射类型声明"对象恰好有这些键，且逐个变换"。使用建议：需要"批量统一变换"时优先考虑映射类型而不是逐个手写；自定义工具类型（如 API 响应包装、状态机的类型化映射）是映射类型的高频场景。
