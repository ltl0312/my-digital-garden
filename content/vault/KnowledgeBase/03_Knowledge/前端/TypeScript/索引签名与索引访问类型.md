# TypeScript 索引签名与索引访问类型

## 📍 知识体系定位
- **所属技术栈**：前端 Vue 3
- **所在层级**：L3 工程化 → TypeScript → 类型操作
- **上游依赖**：<a href="obsidian://open?file=接口与函数类型">TypeScript-接口与函数类型</a>（接口是索引签名的宿主）、<a href="obsidian://open?file=泛型">TypeScript-泛型</a>（`keyof` 与索引访问常配合使用）
- **下游延伸**：<a href="obsidian://open?file=映射类型">TypeScript-映射类型</a>（映射类型基于索引签名语法）、工具类型实现原理
- **同级技术**：JS 的 `Object.keys`/动态属性访问（无类型约束的版本）

## 概述（Overview）
> **索引签名（Index Signature）**用于描述"对象中可以有任意多个、但类型统一的属性"——当无法确定对象中有哪些属性时，用 `[key: string]: number` 约定"只要是 string 类型的属性名，值都必须是 number"。**索引访问（查询）类型**用 `T[P]` 语法查询某个属性的类型，是类型层面的"属性取值"。

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：JS 中对象本身就是"任意键的动态字典"（`obj[anyKey] = anyValue`），键永远被隐式转换为 string，数组是键为数值的"特殊对象"。
- **为什么前身被淘汰**：JS 的动态字典没有任何类型约束——拼错键名不报错、取值类型不可预期，迁移到 TS 后编译器无法理解这类"自由形状"对象。
- **本技术的核心突破**：索引签名给"自由字典"加上了类型边界（键的类型 + 值的类型），让 TS 能够检查动态对象的读写；索引访问类型让"查询某个属性类型"成为一等操作。
- **为什么是它活下来了**：它是 TS 类型系统与 JS 对象模型之间唯一忠实的中介——既尊重 JS "对象键都是 string" 的底层事实（隐藏前缀知识：JS 中对象的键是 string 类型），又赋予其可检查性。
- **当前版本**：TypeScript 5.x。TS 4.1+ 提供 `noUncheckedIndexedAccess` 开关，索引访问自动包含 `undefined`。

### 设计思想
索引签名表达的是"无限但同质"——属性名不可枚举（无法预知），但属性值必须同型。它牺牲了"每个属性精确类型"的精细度，换来了"任意属性都可安全读写"的包容性。数组是索引签名的特例：JS 数组的键（索引）是数值类型，且元素可以任意多，所以 `[n: number]: T` 恰好描述数组。

## 实现（Implementation）

### 完整实例：动态配置字典 + 任意长度数组

```typescript
// ① 场景：接口用于约束"任意数量、统一类型"的属性（如环境变量配置）
interface AnyObject {
    [key: string]: number;   // key 是占位符，可替换为任意合法变量名
}

let obj: AnyObject = {
    a: 1,
    b: 2,
};
// 输入：任意多个 string 键 → 输出：全部通过检查（值必须为 number）
// obj.c = "str";           // ❌ Error: 类型 string 不能赋给 number

// ② 数组的索引签名：JS 中数组是键为数值的特殊对象
interface MyArray<T> {
    [n: number]: T;          // 索引（键）是数值类型，元素可以有任意多个
}

let arr: MyArray<number> = [1, 2, 3];
// 输入：任意多个元素 → 输出：全部为 number

// ③ 索引访问类型 T[P]：查询属性的类型
interface User {
    name: string;
    age: number;
}
type NameType = User["name"];        // string（查询 name 属性的类型）
type AgeType = User["age"];          // number
// 同时查询多个索引：用联合类型或 keyof
type AllKeys = keyof User;           // "name" | "age"
type ValuesType = User[AllKeys];     // string | number（索引访问联合类型）

// ④ 索引访问 + 泛型：K extends keyof T 保证 key 一定存在
function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];                 // 返回值类型 = 该属性值的类型
}
const user: User = { name: "jack", age: 18 };
const n = getProp(user, "name");     // n: string
const a = getProp(user, "age");      // a: number
```

> **💡 补充**：索引签名类型和接口"普通属性"可以共存，但普通属性的值类型必须是索引签名值类型的子集（`[key: string]: number` 的接口不能再声明 `name: string`，否则编译报错）。另外，`[key: string]` 允许的键类型包括 string、number、symbol；`[n: number]` 描述的是"以数字为键"。开启 `noUncheckedIndexedAccess`（TS 4.1+）后，索引访问的返回类型会加上 `| undefined`——更安全，代价是每次访问都要判空。
