# 中央处理器（CPU）

## 📍 知识体系定位
- **所属技术栈**：跨学科纵深
- **所在层级**：XD-1 数字系统与体系结构 → CPU 设计
- **上游依赖**：<a href="obsidian://open?file=指令系统">计算机组成原理-指令系统</a>、<a href="obsidian://open?file=运算方法与运算器">计算机组成原理-运算方法与运算器</a>
- **下游延伸**：XD-2 操作系统（进程调度依赖中断和上下文切换）
- **同级技术**：GPU 架构、NPU 架构

## 概述（Overview）
> CPU 由**数据通路（Datapath）**和**控制器（Controller）**两大部分组成。数据通路包含 ALU、寄存器堆、总线——负责执行运算和传输数据。控制器根据指令生成控制信号序列——硬布线控制器（速度快）或微程序控制器（灵活性高）。**流水线**将指令执行拆分为多级并行处理，大幅提升吞吐量。

## 设计初衷（Motivation）

### 指令周期的五阶段

```
取指(IF) → 译码(ID) → 执行(EX) → 访存(MEM) → 写回(WB)
└─── 每条指令的必经之路 ────┘
```

### 流水线的核心思想

```
非流水线（单周期）：取指 → 译码 → 执行 → 访存 → 写回 → 取下一条
                     |──── 1条指令需要5个周期 ────|
流水线（五级）：      时刻1: IF1 | ID1 | EX1 | MEM1 | WB1
　　　　　　　　　   时刻2: IF2 | ID2 | EX2 | MEM2 | WB2
　　　　　　　　　   时刻3: IF3 | ID3 | EX3 | MEM3 | WB3
                    每个周期完成一条指令（理想情况）
```

### 流水线冲突（三大冒险）

| 冲突类型 | 原因 | 解决方案 |
|---------|------|---------|
| **结构冲突** | 硬件资源竞争（如单端口存储器同时用于 IF 和 MEM） | 分离指令Cache和数据Cache |
| **数据冲突** | 后一条指令需要前一条指令的结果 | 数据旁路（Forwarding）、流水线暂停（Stall） |
| **控制冲突** | 分支指令导致预取的指令可能无效 | 分支预测（静态/动态）、延迟分支 |

### 跨学科溯源
- 流水线 → XD-0（工厂流水线的类比：每个工人完成一个步骤，产品在传送带上流动）
- 分支预测 → XD-7（简单的预测器用 2-bit 饱和计数器，复杂的分支预测类似机器学习中的模式识别）
- 数据旁路 → XD-5（图论：数据依赖图 DAG，旁路路径是最短依赖路径）

## 实现（Implementation）

### 数据通路核心组件

| 组件 | 功能 |
|------|------|
| PC（程序计数器） | 存放下一条指令地址 |
| IR（指令寄存器） | 存放当前执行的指令 |
| 寄存器堆 | 32/16 个通用寄存器 |
| ALU | 执行算术/逻辑运算 |
| MAR/MDR | 存储器地址/数据寄存器 |
| CU（控制单元） | 产生控制信号序列 |

### 硬布线 vs 微程序控制器

| 维度 | 硬布线 | 微程序 |
|------|--------|--------|
| 实现方式 | 组合逻辑门电路 | 微指令存储在控制存储器中 |
| 速度 | 快（无额外存储器访问） | 慢（需读取控制存储器） |
| 灵活性 | 低（修改需重新设计电路） | 高（修改微程序即可） |
| 适用 | RISC 处理器 | CISC 处理器 |

> **💡 补充**：现代高性能 CPU（Intel/AMD/Apple Silicon）同时使用两者——复杂指令通过微码 ROM 翻译为 μop，再经乱序执行的流水线处理。这是 RISC 思想与 CISC 兼容性的终极融合。
