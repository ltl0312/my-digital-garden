# 总线与 I/O 系统

## 📍 知识体系定位
- **所属技术栈**：跨学科纵深
- **所在层级**：XD-1 数字系统与体系结构 → 总线与 I/O
- **上游依赖**：<a href="obsidian://open?file=CPU">计算机组成原理-CPU</a>
- **下游延伸**：XD-2 操作系统（设备驱动、中断处理）、XD-3 计算机网络（PCIe 网卡）
- **同级技术**：SoC 片上互连（ARM AXI）、现代总线标准（PCIe 5.0）

## 概述（Overview）
> **总线**是连接 CPU、存储器和 I/O 设备的共享通信通道，包含数据线、地址线和控制线。**I/O 系统**管理 CPU 与外部设备（磁盘、键盘、网卡）的数据交换，三种控制方式——**程序查询**（CPU 轮询）、**中断**（设备主动通知）、**DMA**（设备直接访问内存，CPU 解放）。

## 设计初衷（Motivation）

### 总线仲裁

当多个设备同时请求总线时，需要仲裁决定谁先用：

| 方式 | 原理 | 特点 |
|------|------|------|
| 链式查询 | 设备按优先级串联，靠近控制器的优先 | 简单但灵活性差 |
| 计数器定时查询 | 控制器轮询设备地址 | 公平，可通过改变计数起点改变优先级 |
| 独立请求 | 每个设备有独立的请求/应答线 | 响应快，灵活性最好 |

### I/O 三种控制方式对比

| 方式 | CPU 参与度 | 数据传输率 | 适用场景 |
|------|-----------|-----------|---------|
| 程序查询 | CPU 全程轮询等待 | 低 | 简单设备（LED、按键） |
| 中断 | CPU 响应中断后传输 | 中 | 键盘、鼠标（低频 I/O） |
| DMA | CPU 只做初始化，DMA 控制器负责传输 | 高 | 磁盘读写、网卡（高频大数据量） |

### 中断处理流程

```
1. 设备发出中断请求 → 中断控制器汇总
2. CPU 执行完当前指令后检查中断信号
3. 关中断 → 保护现场（PC、寄存器入栈）
4. 根据中断向量号跳转到中断服务程序 ISR
5. 执行 ISR（处理设备请求）
6. 恢复现场 → 开中断 → 返回原程序
```

> **💡 补充**：DMA 是现代计算机高性能 I/O 的基石——拷贝 1GB 文件时，如果没有 DMA，CPU 需要执行百万次 `MOV` 指令；有了 DMA，CPU 只需发一条"从磁盘地址 A 拷贝 N 字节到内存地址 B"的命令，然后可以去做其他事。

### 跨学科溯源
- 中断机制 → XD-2（操作系统：进程切换依赖时钟中断；系统调用通过软中断 trap 实现）
- DMA → XD-6（设计模式：代理模式——DMA 控制器代理 CPU 完成数据传输）
- 总线仲裁 → XD-5（分布式系统共识算法简化版：确定共享资源的访问顺序）
