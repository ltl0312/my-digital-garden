## 概述（Overview）
> 操作系统体系结构描述了 OS 内核的组成方式——哪些功能放在内核态、哪些放在用户态，以及各模块之间的调用关系。常见架构包括大内核、微内核、分层结构、模块化、外核五种。

## 设计初衷（Motivation）

### 六种体系结构对比

| 体系结构 | 核心思想 | 优点 | 缺点 | 代表系统 |
|----------|----------|------|------|----------|
| **大内核（宏内核）** | 所有系统功能都放在内核里 | 性能高，内核内部功能直接相互调用 | 内核庞大、结构混乱、难以维护；一个模块出错可能导致整个系统崩溃 | Linux、UNIX |
| **微内核** | 只把中断、原语、进程通信等核心功能放内核，其余以用户进程形式运行 | 内核小、易于维护、可靠性高；内核外模块出错不会导致系统崩溃 | 性能低，需频繁切换用户态/核心态；用户态下各功能通过内核"消息传递"间接通信 | Windows NT、Minix |
| **分层结构** | 内核分多层，每层可单向调用更低一层提供的接口 | 便于调试和验证，自底向上逐层调试验证；易扩充易维护 | 难以合理定义各层边界；效率低，不可跨层调用 | MULTICS |
| **模块化** | 内核=主模块+可加载内核模块，各模块间通过接口通信 | 模块间逻辑清晰易于维护；支持动态加载新模块（如设备驱动） | 模块间接口定义未必合理；模块间相互依赖，更难调试 | Linux（也采用模块化） |
| **外核** | 内核负责进程调度/通信，外核负责为用户进程分配未经抽象的物理硬件资源 | 用户进程可更灵活地使用硬件资源；减少虚拟映射层，提升效率 | 降低了系统一致性；系统变得更复杂 | Exokernel（学术研究） |

### 设计思想
本质上是**性能 vs 可维护性**的权衡：
- 大内核追求极致性能，把所有东西塞进内核空间，避免上下文切换开销
- 微内核追求极致稳定性和可维护性，最小化内核代码量
- 模块化/分层是工程上的折中——在"全部在内核"和"大部分在用户"之间寻找平衡

### 操作系统引导（Boot）流程

```
CPU 上电 → 执行 ROM 引导程序（硬件自检）
        → 读入 MBR（磁盘第一块，含磁盘引导程序+分区表）
        → 扫描分区表，找到活动分区（C盘）
        → 读入 PBR（分区引导记录）
        → 找到并执行启动管理器（如 Windows Boot Manager、GRUB）
        → 加载 OS 内核到内存 → OS 开始运行
```

### 两类虚拟机管理程序（VMM）

| 对比项 | 第一类 VMM（裸机型） | 第二类 VMM（宿主型） |
|--------|---------------------|---------------------|
| 运行位置 | 直接运行在硬件上 | 运行在宿主 OS 上 |
| 性能 | 更好 | 更差（需 Host OS 中介） |
| 可迁移性 | 更差 | 更好（导出镜像文件即可迁移） |
| 代表 | VMware ESXi、Xen | VMware Workstation、VirtualBox |
