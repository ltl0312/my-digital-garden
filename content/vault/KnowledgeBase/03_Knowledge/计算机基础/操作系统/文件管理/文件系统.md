# 第一部分：文件基本概念

## 概述（Overview）
> 文件：一组有意义的信息/数据集合。OS 以"块"为基本单位在外存中为文件分配存储空间。

### 文件的属性

| 属性 | 说明 |
|------|------|
| 文件名 | 同一目录下不允许重名 |
| 标识符 | 系统内部唯一 ID，对用户不可见 |
| 类型、大小、位置 | 基本元信息 |
| 时间戳 | 创建时间、最后修改时间 |
| 所有者、保护信息 | 访问控制 |

### 文件的逻辑结构

| 类型 | 说明 | 特点 |
|------|------|------|
| **无结构文件**（流式文件） | 二进制/字符流组成 | 如 .txt 文本文件 |
| **有结构文件**（记录式文件） | 一组相似记录组成 | 如数据库表 |

**有结构文件的组织方式**：

| 类型 | 结构 | 能否随机存取 |
|------|------|-------------|
| 顺序文件 | 记录一个接一个排列 | 定长+顺序存储 ✅；变长/链式存储 ❌ |
| 索引文件 | 每个记录对应一个索引表项 | ✅（通过索引表快速定位） |
| 索引顺序文件 | 一组记录对应一个索引表项 | ✅（多级索引进一步提高效率） |

# 第二部分：文件目录（FCB）

## 概述（Overview）
> 文件控制块（FCB）：包含文件基本信息（文件名、物理地址、逻辑/物理结构等）、存取控制信息、使用信息。FCB 的有序集合就是"文件目录"，实现了文件名→文件的映射（按名存取）。

### 目录结构的演进

```
单级目录 ──→ 两级目录 ──→ 多级目录（树形）──→ 无环图目录
  不重名     不同用户可重名   层次分类清晰      支持文件共享
  缺灵活性   缺乏灵活性      不便于共享         需共享计数器
```

### 索引结点（inode）——目录瘦身

```
传统 FCB：文件名 + 文件描述信息
              ↓ 瘦身
索引结点方案：
  · 目录项仅保留：文件名 + 索引结点指针（大幅缩小目录项）
  · 索引结点存储：文件描述信息（外存地址、权限、大小等）
  · 查找时只需文件名 → 找到索引结点指针 → 调入索引结点
```

# 第三部分：文件的物理结构（重点）

## 概述（Overview）
> 文件分配方式决定文件数据在磁盘上的存放方式，类似内存管理的"连续分配 vs 非连续分配"。

### 三种分配方式对比

| 方式 | 原理 | 随机访问 | 碎片 | 扩展 |
|------|------|----------|------|------|
| **连续分配** | 文件占据连续磁盘块 | ✅ | 有（外部碎片） | ❌ 不方便 |
| **隐式链接** | 每个磁盘块存下一个块指针 | ❌ | 无 | ✅ |
| **显式链接**（FAT） | 指针集中存于 FAT 表 | ✅（FAT 在内存） | 无 | ✅ |
| **索引分配** | 每个文件一张索引表 | ✅ | 无 | ✅ |

### 索引分配的三种方案

```
① 链接方案：多个索引块链接起来
   ┌───┐   ┌───┐   ┌───┐
   │索引│→→→│索引│→→→│索引│→ ...
   │块1 │   │块2 │   │块3 │
   └───┘   └───┘   └───┘
   缺点：找 i 号索引块需依次读入前 i-1 块，IO 次数多

② 多层索引：类似多级页表
   ┌────────┐
   │一级索引│→ 二级索引块 → 数据块
   │  块    │→ 二级索引块 → 数据块
   └────────┘
   K 层索引访问数据块需 K+1 次读磁盘
   缺点：小文件也要 K+1 次读

③ 混合索引（如 Unix inode）：
   ┌───────────┐
   │ 直接地址  │ → 直接指向数据块（小文件快速访问）
   │ 一级间接  │ → 指向单层索引表
   │ 二级间接  │ → 指向两层索引表
   │ 三级间接  │ → 指向三层索引表
   └───────────┘
   优点：小文件只需直接地址（快），大文件用多级间接（容量大）
```

# 第四部分：文件存储空间管理

### 四种管理方式

| 方式 | 原理 | 适用分配方式 |
|------|------|-------------|
| **空闲表法** | 记录空闲盘块号+块数，类似动态分区 | 连续分配 |
| **空闲链表法** | 空闲盘块链/空闲盘区链 | 离散/连续 |
| **位示图法** | 每个二进制位对应一个盘块（0=空闲，1=已占） | 均可 |
| **成组链接法** | UNIX 方案，超级块记录空闲块 | 大型文件系统 |

```
位示图计算（字号、位号从0开始）：
  盘块号 b = n × i + j    （n=字长, i=字号, j=位号）
  字号 i = b / n
  位号 j = b % n
```

# 第五部分：文件共享与保护

### 硬链接 vs 软链接

| 维度 | 硬链接（基于索引结点） | 软链接（符号链） |
|------|----------------------|-------------------|
| 原理 | 多目录项指向同一 inode | 新建 Link 型文件，存目标路径 |
| 计数 | inode 中有 link count | 无计数，源删除即失效 |
| 跨文件系统 | ❌ 不能 | ✅ 能 |
| 访问速度 | 快（直接找到 inode） | 慢（需逐级解析路径） |

### 三种文件保护方式

| 方式 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **口令保护** | 口令存于 FCB，访问前验证 | 空间和时间开销小 | 口令存在系统内，不够安全 |
| **加密保护** | 密码加密文件，访问需解密 | 保密性强，不存密码 | 编解码耗时 |
| **访问控制** | ACL 记录各用户权限（读/写/执行等） | 灵活复杂 | 用户多时 ACL 很大 |

# 第六部分：文件系统层次结构

```
用户接口     ── read/write/open/close 系统调用
文件目录系统 ── 根据路径找到 FCB/索引结点
存取控制     ── 验证访问权限
逻辑文件系统 ── 记录号→逻辑地址
物理文件系统 ── 逻辑地址→物理地址
辅助分配     ── 存储空间分配与回收
设备管理     ── 直接与硬件交互
```

### 虚拟文件系统（VFS）
> VFS 向上提供统一接口，屏蔽底层不同文件系统（ext4/NTFS/FAT）的实现差异。每打开一个文件，VFS 在主存中创建 vnode（统一的数据结构），vnode 的函数指针指向具体文件系统的实现。
