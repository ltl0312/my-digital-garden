- **同级技术**：管程（高级同步机制）、条件变量

## 概述（Overview）
> 信号量（Semaphore）是一个变量，用来表示系统中某种资源的数量。用户可以通过一对原语——P 操作（wait）和 V 操作（signal）——来对信号量进行操作，从而实现进程互斥和进程同步。

**核心思想**：信号量 S 代表某种资源数量。P 操作申请资源（S--），V 操作释放资源（S++）。

## 设计初衷（Motivation）

### 从整型到记录型——解决"让权等待"

```cpp
// 整型信号量：不满足让权等待
int S = 1;
void wait(int S) {
    while (S <= 0);     // ❌ 忙等待！违反让权等待
    S = S - 1;
}
void signal(int S) {
    S = S + 1;
}

// 记录型信号量：满足让权等待 ✅
typedef struct {
    int value;              // 剩余资源数
    struct process *L;      // 等待队列（阻塞队列）
} semaphore;

void wait(semaphore S) {   // P 操作
    S.value--;
    if (S.value < 0) {
        block(S.L);         // 资源不够→进程自我阻塞，让出 CPU
    }
}

void signal(semaphore S) {  // V 操作
    S.value++;
    if (S.value <= 0) {
        wakeup(S.L);        // 释放资源后唤醒等待队列中的一个进程
    }
}

// 信号量值的含义：
// S.value > 0  →  还有 S.value 个可用资源
// S.value = 0  →  资源刚好用完，无等待进程
// S.value < 0  →  |S.value| 个进程在等待队列中
```

### 设计思想
记录型信号量的关键是"等待队列"——资源不够时不是忙等（while 循环），而是主动调用 block 原语让自己阻塞、释放 CPU。这完美满足"让权等待"原则。

## 实现（Implementation）

### 信号量的两种用法

#### 用法一：实现互斥
```cpp
semaphore mutex = 1;   // 互斥信号量，初值 1

P() {
    ...
    P(mutex);          // 进入区：申请资源（相当于加锁）
    临界区;
    V(mutex);          // 退出区：释放资源（相当于解锁）
    ...
}
// 规则：P、V 操作成对出现在同一进程中
// 不同临界资源需设置不同的互斥信号量
```

#### 用法二：实现同步
```cpp
semaphore S = 0;       // 同步信号量，初值 0（表示"该资源"一开始没有）

P1() {                 // "前操作"的进程
    ...
    V(S);              // 前 V：产生资源（告诉 P2 "可以做了"）
    ...
}
P2() {                 // "后操作"的进程
    ...
    P(S);              // 后 P：等待资源（等 P1 通知）
    ...
}
// 规则：P、V 操作成对出现在不同进程中
// 口诀：前 V 后 P
```

### 经典问题一：生产者-消费者问题

```cpp
semaphore mutex = 1;       // 互斥信号量，保护缓冲区
semaphore empty = n;       // 同步信号量，空闲缓冲区数量（初值 n）
semaphore full = 0;        // 同步信号量，产品数量（初值 0）

producer() {
    while (1) {
        生产一个产品;
        P(empty);          // ① 消耗一个空闲缓冲区（没有空闲则阻塞）
        P(mutex);          // ② 互斥上锁（⚠️ 必须在 P(empty) 之后！）
        把产品放入缓冲区;
        V(mutex);          // ③ 互斥解锁
        V(full);           // ④ 增加一个产品
    }
}

consumer() {
    while (1) {
        P(full);           // ① 消耗一个产品（没有产品则阻塞）
        P(mutex);          // ② 互斥上锁
        从缓冲区取出一个产品;
        V(mutex);          // ③ 互斥解锁
        V(empty);          // ④ 增加一个空闲缓冲区
        使用产品;
    }
}
```

> ⚠️ **关键**：实现互斥的 P 操作一定要在实现同步的 P 操作之后，否则会发生死锁。V 操作顺序可互换。

### 经典问题二：读者-写者问题

```cpp
semaphore rw = 1;           // 保护共享文件的互斥访问
int count = 0;              // 当前读进程数
semaphore mutex = 1;        // 保护 count 变量的互斥访问
semaphore w = 1;            // 实现读写公平（防止读进程源源不断导致写饥饿）

writer() {
    while (1) {
        P(w);               // 申请写权限
        P(rw);              // 写之前加锁
        写文件;
        V(rw);              // 写完后解锁
        V(w);
    }
}

reader() {
    while (1) {
        P(w);               // 如果有写进程在等待，读进程排队
        P(mutex);           // 互斥访问 count
        if (count == 0)
            P(rw);          // 第一个读进程加锁（阻止写进程）
        count++;
        V(mutex);
        V(w);
        读文件;
        P(mutex);
        count--;
        if (count == 0)
            V(rw);          // 最后一个读进程解锁（允许写进程）
        V(mutex);
    }
}
```

> **核心策略**：count 计数器判断当前进入的进程是否为第一个（需要加锁）或最后一个（需要解锁）读进程。

### 经典问题三：哲学家进餐问题

五种解决死锁的方案：
1. 最多允许四个哲学家同时进餐（保证至少一人能拿到两根筷子）
2. 奇数号先拿左边再拿右边，偶数号先拿右边再拿左边
3. 仅当左右两根筷子都可用时才允许抓起

### PV 解题通用思路

1. **关系分析**：找出各进程间的同步、互斥关系
2. **整理思路**：根据操作流程确定 P、V 大顺序
3. **设置信号量**：互斥信号量初值一般为 1，同步信号量初值取决于对应资源初值
