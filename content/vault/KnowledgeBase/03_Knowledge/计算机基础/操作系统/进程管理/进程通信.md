# 进程通信

## 📍 知识体系定位
- **所属技术栈**：计算机基础 / 操作系统
- **所在层级**：XD-2 操作系统 → 进程管理 → 进程通信
- **上游依赖**：<a href="obsidian://open?file=进程的概念、组成与状态">进程的概念、组成与状态</a> — 进程地址空间独立是通信需要 OS 介入的根本原因
- **下游延伸**：<a href="obsidian://open?file=基础概念与实现">Java 多线程</a> — 线程间共享进程地址空间，通信无需 OS 介入（但需要同步机制）
- **同级技术**：线程同步（同一进程内线程共享内存，通信更简单但需要互斥保护）

## 概述（Overview）
> 进程间通信（IPC，Inter-Process Communication）：两个进程之间产生数据交互的机制。由于各进程拥有独立的内存地址空间，一个进程不能直接访问另一个进程的地址空间，因此需要 OS 提供的 IPC 机制。

三种主要通信方式：
1. **共享存储**：OS 在内存中开辟共享区域，多个进程映射到自己的地址空间
2. **消息传递**：进程通过 OS 提供的发送/接收原语交换格式化消息
3. **管道通信**：基于共享文件的半双工通信

## 设计初衷（Motivation）

### 设计思想
根本矛盾：**进程安全隔离 vs 进程需要协作**。为了让相互隔离的进程能够安全地交换数据，OS 作为"中间人"提供通信管道。三种方式代表三种不同的设计哲学：
- 共享存储 → 最小 OS 干预，最大灵活性（类似"开放一块公共黑板"）
- 消息传递 → OS 全程托管，最安全但开销大（类似"邮局递信"）
- 管道通信 → 基于文件的流式通信，简单但受限（类似"水管传输"）

## 实现（Implementation）

### 三种通信方式对比

| 维度 | 共享存储 | 消息传递 | 管道通信 |
|------|----------|----------|----------|
| 通信单位 | 任意数据 | 格式化消息（消息头+消息体） | 字节流 |
| 通信方向 | 双向（需互斥控制） | 双向 | 半双工（单时段单向） |
| OS 介入 | 仅建立时（shm_open/mmap） | 每次通信（send/receive 原语） | 读写时（read/write） |
| 速度 | 最快（无数据拷贝） | 较慢（消息复制） | 中等（缓冲区复制） |
| 灵活性 | 最高 | 中等 | 受限于管道大小 |

### 共享存储（Linux 实现）

```c
// Linux 共享存储示例（伪代码）
// ① 创建共享内存区
int fd = shm_open("/my_shm", O_CREAT | O_RDWR, 0666);
// ② 设置共享内存大小
ftruncate(fd, 4096);
// ③ 将共享内存映射到进程地址空间
void *ptr = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
// ④ 进程间通过 ptr 指针直接读写共享内存
// ⑤ 需要 P/V 操作等互斥机制保证数据一致性
```

### 消息传递的两种方式

**直接通信**：发送进程指明接收进程 ID
```
send(P_receiver, message);   // 发送原语：消息挂到接收进程 PCB 消息队列
receive(P_sender, &message); // 接收原语：从自己的消息队列取出消息
```

**间接通信（信箱通信）**：通过"信箱"作为中间实体
```
send(mailbox_A, message);    // 多个进程可往同一信箱发送
receive(mailbox_A, &message); // 多个进程可从同一信箱接收
```

### 管道通信的特性

```
管道（pipe）
├── 本质：内存中大小固定的缓冲区（循环队列）
├── 通信方向：半双工（双向需两个管道）
├── 互斥：OS 保证各进程互斥访问
├── 同步：
│   ├── 写满时 → 写进程阻塞，直到读进程取走数据
│   └── 读空时 → 读进程阻塞，直到写进程写入数据
├── 数据特性：一旦读出就彻底消失
└── 读者数量：通常一个管道允许多写进程、一个读进程
```
