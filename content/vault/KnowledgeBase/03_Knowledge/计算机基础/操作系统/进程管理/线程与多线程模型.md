# 线程与多线程模型

## 📍 知识体系定位
- **所属技术栈**：计算机基础 / 操作系统
- **所在层级**：XD-2 操作系统 → 进程管理 → 线程
- **上游依赖**：<a href="obsidian://open?file=进程的概念、组成与状态">进程的概念、组成与状态</a> — 线程是进程内部更细粒度的执行单元
- **下游延伸**：<a href="obsidian://open?file=基础概念与实现">Java 多线程</a> — JVM 将 Java 线程映射到 OS 内核级线程
- **同级技术**：进程 — 进程是资源分配的基本单位，线程是 CPU 调度的基本单位

## 概述（Overview）
> 线程（Thread）是 CPU 执行的基本单元，也是程序执行流的最小单位。引入线程是为了提高系统的并发度——让一个进程内部也能"同时"做多件事。

**引入线程后的核心变化**：

| 维度 | 传统进程机制 | 引入线程后 |
|------|-------------|-----------|
| 执行流最小单位 | 进程 | **线程** |
| 资源分配基本单位 | 进程 | **进程**（不变） |
| 调度基本单位 | 进程 | **线程** |
| 并发粒度 | 仅进程间并发 | 进程间 + **线程间** |
| 切换开销 | 进程间切换开销大 | 同进程线程切换开销小 |

## 设计初衷（Motivation）

### 线程的两种实现方式

#### 用户级线程（ULT）

```
用户级线程 — 由线程库实现，OS "看不到"线程
┌─────────────────────────────────┐
│         用户进程                  │
│  ┌──────┐ ┌──────┐ ┌──────┐     │
│  │线程A  │ │线程B  │ │线程C  │     │  ← 线程库管理
│  └──┬───┘ └──┬───┘ └──┬───┘     │
│     └────────┼────────┘         │
│         ┌────▼────┐             │
│         │ 内核进程  │             │  ← OS 只看到一个进程
│         └─────────┘             │
└─────────────────────────────────┘
```

- **优点**：线程切换在用户空间完成，无需切换到核心态，系统开销小、效率高
- **缺点**：一个线程阻塞 → 整个进程阻塞；多线程无法在多核上真正并行

#### 内核级线程（KLT）

```
内核级线程 — OS 管理线程，OS "看得见"每个线程
┌─────────────────┐
│     用户进程      │
│  ┌──────┐ ┌──────┐│
│  │线程A  │ │线程B  ││
│  └──┬───┘ └──┬───┘│
└─────┼────────┼────┘
      │        │
┌─────▼───┐┌──▼──────┐
│内核线程A ││内核线程B │  ← OS 调度内核线程
│  (TCB)  ││  (TCB)  │
└─────────┘└─────────┘
```

- **优点**：一个线程阻塞后其他线程可继续执行；多线程可在多核上并行
- **缺点**：线程切换需核心态，管理成本高、开销大

### 三种多线程模型

| 模型 | 映射关系 | 优点 | 缺点 |
|------|----------|------|------|
| **一对一** | 1 ULT ↔ 1 KLT | 并发能力强，支持多核并行 | 占用多个内核线程，切换开销大 |
| **多对一** | 多 ULT → 1 KLT | 切换开销小，效率高 | 一个阻塞全体阻塞，不支持多核并行 |
| **多对多** | n ULT ↔ m KLT (n≥m) | 集二者所长：开销适中 + 并发度好 | 实现复杂 |

> **多对多的哲学**：用户级线程是"代码逻辑"的载体，内核级线程是"运行机会"的载体。一段代码逻辑只有获得运行机会才能被执行。

### 线程的 TCB 组成

| 字段 | 说明 |
|------|------|
| 线程标识符（TID） | 唯一标识，类似 PID |
| 程序计数器（PC） | 线程当前执行位置 |
| 其他寄存器 | 线程运行的中间结果 |
| 堆栈指针 | 函数调用信息、局部变量 |
| 线程运行状态 | 运行/阻塞/就绪 |
| 优先级 | 调度参考 |

> ⚠️ **线程切换时需要保存/恢复的**：PC、其他寄存器、堆栈指针。这些是线程"运行现场"的核心。
