# 进程的概念、组成与状态

## 📍 知识体系定位
- **所属技术栈**：计算机基础 / 操作系统
- **所在层级**：XD-2 操作系统 → 进程管理 → 进程基础
- **上游依赖**：<a href="obsidian://open?file=操作系统运行机制-中断与系统调用">操作系统运行机制-中断与系统调用</a> — 时钟中断驱动进程切换，系统调用实现进程创建/终止
- **下游延伸**：<a href="obsidian://open?file=线程与多线程模型">线程与多线程模型</a> — 线程是进程内部更细粒度的执行单元
- **同级技术**：线程 — 进程是资源分配的基本单位，线程是调度的基本单位

## 概述（Overview）
> 进程（Process）是进程实体的运行过程，是系统进行资源分配和调度的一个独立单位。程序是静态的指令集合，进程是动态的程序执行过程。

**进程实体（进程映像）的组成**：

```
进程实体（进程映像）
├── PCB（进程控制块）—— 给 OS 用的
│   ├── PID：进程唯一标识
│   ├── UID：进程所属用户
│   ├── 资源分配记录：内存/IO/文件
│   ├── 运行情况：CPU 使用时间、磁盘/网络使用
│   └── 处理机信息：PSW、PC 等寄存器的值（用于进程切换）
│
├── 程序段 —— 包含程序指令（指令序列）
│
└── 数据段 —— 运行过程中产生的数据（变量等）
```

> ⚠️ **关键结论**：PCB 是进程存在的唯一标志。OS 管理进程所需的所有信息都在 PCB 中。同一程序执行多次，PCB 和数据段各不相同，但程序段内容相同。

## 设计初衷（Motivation）

### 设计思想
根本矛盾：**CPU 需要高效执行程序 vs 多个程序需要"同时"运行**。解决方案是将程序执行抽象为进程——一个可被暂停、恢复、切换的执行实体。PCB 是关键的抽象层，让 OS 可以在任何时刻"快照"一个进程的全部状态，从而实现进程切换。

### 进程的五大特征

| 特征 | 说明 | 关键理解 |
|------|------|----------|
| **动态性**（最基本） | 进程是程序的一次执行过程，动态地产生、变化和消亡 | 程序 + 数据 + PCB = 静态；进程 = 动态运行 |
| 并发性 | 内存中多个进程实体可并发执行 | 宏观同时，微观交替 |
| 独立性 | 进程是独立运行、独立获取资源、独立接受调度的基本单位 | 每个进程拥有独立的地址空间 |
| 异步性 | 各进程以独立、不可预知的速度推进 | OS 需提供进程同步机制解决 |
| 结构性 | 每个进程配置 PCB，由 PCB + 程序段 + 数据段组成 | 结构化的执行实体 |

## 实现（Implementation）

### 进程的五种状态与转换

```
                    ┌──────────────────────────────┐
                    │         创建态 (New)           │
                    │  正在创建：分配资源、初始化PCB  │
                    └──────────────┬───────────────┘
                                   │ 创建完成
                    ┌──────────────▼───────────────┐
         ┌─────────│        就绪态 (Ready)          │◄─────────┐
         │          │  具备运行条件，等待CPU分配      │          │
         │          └──────────────┬───────────────┘          │
         │                         │ 被调度                    │ 时间片到 / 被抢占
         │          ┌──────────────▼───────────────┐          │
         │          │        运行态 (Running)        │──────────┘
         │          │    占有CPU，正在执行指令        │
         │          └──────────────┬───────────────┘
         │                         │ 等待事件（系统调用/主动阻塞）
         │          ┌──────────────▼───────────────┐
         │          │      阻塞态 (Waiting/Blocked) │
         │          │  等待某事件发生，暂停运行      │
         │          └──────────────┬───────────────┘
         │                         │ 等待的事件发生
         │          ┌──────────────▼───────────────┐
         │          │        终止态 (Terminated)    │
         └──────────│  正在撤销：回收资源、删除PCB   │
                    └──────────────────────────────┘
```

> ⚠️ **重要限制**：不能由阻塞态直接转换为运行态，也不能由就绪态直接转换为阻塞态。因为进入阻塞态是进程在运行时主动请求的。

### 进程控制——五种原语

| 原语 | 状态转换 | 关键步骤 |
|------|----------|----------|
| **创建原语** | 创建态→就绪态 | 申请空白PCB → 分配资源 → 初始化PCB → 插入就绪队列 |
| **撤销原语** | 任意→终止态→无 | 找到PCB → 剥夺CPU → 终止子进程 → 归还资源 → 删除PCB |
| **阻塞原语** | 运行态→阻塞态 | 找到PCB → 保存现场 → 设状态为阻塞 → 插入等待队列 |
| **唤醒原语** | 阻塞态→就绪态 | 找到PCB → 移出等待队列 → 设状态为就绪 → 插入就绪队列 |
| **切换原语** | 运行态↔就绪态 | 保存运行环境→移入相应队列→选择新进程→恢复运行环境 |

> **原语的原子性**通过"关中断指令"和"开中断指令"实现：关中断→执行原语逻辑→开中断，中间的指令序列不可被中断。

### 进程的组织

- **链接方式**：按状态将 PCB 分为多个队列（运行队列、就绪队列、阻塞队列），OS 持有指向各队列的指针
- **索引方式**：根据状态建立多张索引表，OS 持有指向各索引表的指针
