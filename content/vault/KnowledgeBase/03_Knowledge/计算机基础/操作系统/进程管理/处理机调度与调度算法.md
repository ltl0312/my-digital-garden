# 处理机调度与调度算法

## 📍 知识体系定位
- **所属技术栈**：计算机基础 / 操作系统
- **所在层级**：XD-2 操作系统 → 进程管理 → 处理机调度
- **上游依赖**：<a href="obsidian://open?file=进程的概念、组成与状态">进程的概念、组成与状态</a> — 进程的就绪态/运行态/阻塞态是调度的基础
- **下游延伸**：<a href="obsidian://open?file=信号量机制与经典同步问题">信号量机制与经典同步问题</a> — 调度算法影响并发程序的执行顺序和效率
- **同级技术**：磁盘调度算法（FCFS/SSTF/SCAN 等同名不同域）

## 概述（Overview）
> 处理机调度：按某种规则从就绪队列中选择一个进程（或线程），将处理机分配给它。调度是 OS 最核心的功能之一，直接影响系统的响应速度和吞吐量。

### 调度的三个层次

| 层次 | 做什么 | 发生位置 | 频率 | 状态影响 |
|------|--------|----------|------|----------|
| **高级调度**（作业调度） | 从后备队列选作业调入内存，创建进程 | 外存→内存 | 最低 | 无→创建态→就绪态 |
| **中级调度**（内存调度） | 从挂起队列选进程数据调回内存 | 外存→内存 | 中等 | 挂起态→就绪态 |
| **低级调度**（进程调度） | 从就绪队列选进程分配 CPU | 内存→CPU | 最高（几十ms一次） | 就绪态→运行态 |

## 设计初衷（Motivation）

### 调度算法评价指标

| 指标 | 公式 / 含义 | 评价方向 |
|------|------------|----------|
| CPU 利用率 | 忙碌时间 / 总时间 | 越高越好 |
| 系统吞吐量 | 完成作业数 / 总时间 | 越高越好 |
| 周转时间 | 完成时间 - 提交时间 | 越小越好 |
| 带权周转时间 | 周转时间 / 实际运行时间 | 越小越好 |
| 等待时间 | 等待处理机的时间之和 | 越小越好 |
| 响应时间 | 提交请求到首次响应的时间 | 越小越好 |

### 五种算法的调度时机

- **非抢占式**（进程主动放弃 CPU 才调度）：进程正常终止、异常终止、主动阻塞（等待 IO）
- **抢占式**（OS 可强行剥夺 CPU）：时间片到、更高优先级进程到达、IO 中断唤醒更高优先级进程
- **不能调度的情况**：处理中断过程中、在临界区中、在原子操作（原语）中

## 实现（Implementation）

### 六种调度算法详解

#### 1. 先来先服务（FCFS）

> 选择等待时间最长的作业/进程优先服务。

| 维度 | 说明 |
|------|------|
| 算法规则 | 按到达先后顺序服务 |
| 是否可抢占 | 非抢占式 |
| 优点 | 公平、实现简单 |
| 缺点 | 对短作业不利——排长作业后面的短作业需长时间等待，带权周转时间大 |
| 饥饿 | 不会 |

#### 2. 短作业优先（SJF / SPF / SRTN）

> 选择执行时间最短的作业优先服务。

| 维度 | 说明 |
|------|------|
| 算法规则 | 服务时间最短的优先 |
| 非抢占版本 | SJF（作业调度）/ SPF（进程调度） |
| 抢占版本 | SRTN（最短剩余时间优先）— 平均等待时间、平均周转时间最少 |
| 缺点 | 对长作业不利，长作业可能饿死 |
| 饥饿 | 会 |

> ⚠️ 在所有进程几乎同时到达时，SJF 的平均等待时间和平均周转时间最少。

#### 3. 最高响应比优先（HRRN）

> 综合等待时间 + 要求服务时间，选择响应比最高的。

```
响应比 = (等待时间 + 要求服务时间) / 要求服务时间
```

| 维度 | 说明 |
|------|------|
| 算法规则 | 每次调度时计算各进程响应比，选最高的 |
| 是否可抢占 | 非抢占式 |
| 优点 | 兼顾 FCFS 公平性（等得久优先）+ SJF 效率（短作业优先），避免长作业饥饿 |
| 饥饿 | 不会 |

#### 4. 时间片轮转（RR）

> 公平轮流地为每个进程分配一个时间片。

| 维度 | 说明 |
|------|------|
| 算法规则 | 到就绪队列排队，轮流执行一个时间片；未完成则移到队尾 |
| 是否可抢占 | 抢占式（时钟中断触发） |
| 时间片太大 | 退化为 FCFS |
| 时间片太小 | 进程切换过于频繁，系统开销大 |
| 饥饿 | 不会 |

#### 5. 优先级调度

> 选择优先级最高的进程优先服务。

| 维度 | 说明 |
|------|------|
| 静态优先级 | 创建时确定，之后不变 |
| 动态优先级 | 初始值 + 动态调整（等太久↑、运行太久↓、频繁 IO↑） |
| 优先级合理设置 | 系统进程 > 用户进程；前台 > 后台；IO 型 > 计算型 |
| 饥饿 | 会（源源不断的高优先级进程到达） |

#### 6. 多级反馈队列（最重要的综合算法）

```
        ┌─────────────┐
  新进程→│ 第1级队列    │ 优先级最高，时间片最小
        │ (FCFS+RR)   │
        └──────┬──────┘
               │ 未完成 → 降级
        ┌──────▼──────┐
        │ 第2级队列    │
        │ (FCFS+RR)   │
        └──────┬──────┘
               │ 未完成 → 降级
        ┌──────▼──────┐
        │ 第k级队列    │ 优先级最低，时间片最大
        │ (FCFS+RR)   │
        └─────────────┘

规则：
1. 高优先级队列非空时，不调度低优先级队列
2. 高优先级队列有新进程到达时，抢占当前运行的低优先级进程
3. IO 阻塞的进程被唤醒后可放回原队列，保持高优先级
```

| 优点 | 说明 |
|------|------|
| 对各类型进程相对公平 | FCFS 优点 |
| 新进程快速得到响应 | RR 优点 |
| 短进程只用较少时间完成 | SPF 优点 |
| 不必估计运行时间 | 避免用户作假 |
| 灵活调整偏好 | IO 型进程保持较高优先级 |
