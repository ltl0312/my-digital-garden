# 第一部分：IO 设备与控制器

## 概述（Overview）
> IO 设备 = 机械部件（执行具体 IO 操作）+ 电子部件（IO 控制器/设备控制器）。IO 控制器是 CPU 和设备机械部件之间的"中介"，CPU 通过控制器间接控制设备。

### IO 控制器的四大功能

| 功能 | 实现方式 |
|------|----------|
| 接受和识别 CPU 命令 | 控制寄存器存放命令和参数 |
| 向 CPU 报告设备状态 | 状态寄存器（1=空闲，0=忙碌） |
| 数据交换 | 数据寄存器暂存输入/输出数据 |
| 地址识别 | 各寄存器有特定地址供 CPU 寻址 |

### 设备分类

| 分类维度 | 类型 | 示例 |
|----------|------|------|
| 按使用特性 | 人机交互/存储/网络通信 | 键盘/磁盘/网卡 |
| 按传输速率 | 低速/中速/高速 | 鼠标/打印机/磁盘 |
| 按信息交换单位 | **块设备**（可寻址）/ **字符设备**（不可寻址） | 磁盘/键盘 |

# 第二部分：IO 控制方式（重点）

## 设计初衷（Motivation）

### 四种控制方式的演进——核心驱动是"减少 CPU 对 IO 的干预"

| 方式 | CPU 干预频率 | 数据传输单位 | 数据流向 | 关键思想 |
|------|-------------|-------------|----------|----------|
| **程序直接控制** | 极高（不断轮询） | 字 | 设备↔CPU↔内存 | CPU 全程控制，"忙等"轮询 |
| **中断驱动** | 高（每字中断一次） | 字 | 设备↔CPU↔内存 | IO 完成后用中断通知 CPU，等待期间 CPU 可做其他事 |
| **DMA** | 中（每块中断一次） | 块 | **设备↔内存** | 数据不再经过 CPU，DMA 控制器直接传输 |
| **通道控制** | 低（每组块中断一次） | 一组块 | 设备↔内存 | "阉割版 CPU"执行通道程序，CPU 只需发出 IO 指令 |

```
DMA 控制器的组成：
  DR   ── 数据寄存器（暂存数据）
  MAR  ── 内存地址寄存器（数据在内存中的目标地址）
  DC   ── 数据计数器（还剩多少数据要传）
  CR   ── 命令/状态寄存器
```

### 跨学科溯源
> - DMA → <a href="obsidian://open?file=总线与IO系统">计算机组成原理-总线与IO系统</a>（DMA 控制器挂载在系统总线上，通过总线仲裁获取总线控制权）
> - 通道 → <a href="obsidian://open?file=CPU">计算机组成原理-CPU</a>（通道本质是简化的专用处理器，有自己的指令集）

# 第三部分：IO 软件层次结构

```
┌──────────────────┐
│   用户层软件       │ ← SPOOLing 技术、库函数（如 printf）
├──────────────────┤
│ 设备独立性软件     │ ← IO 调度、设备保护、缓冲区管理、LUT
├──────────────────┤   逻辑设备名→物理设备名映射
│   设备驱动程序     │ ← 将通用命令转为设备特定操作
├──────────────────┤
│  中断处理程序      │ ← IO 完成时处理中断信号
├──────────────────┤
│   硬件（控制器）   │
└──────────────────┘
```

### 逻辑设备表（LUT）

```
逻辑设备名 ──LUT──→ 物理设备名 ──→ 设备驱动程序入口

LUT 管理方式：
  ① 整个系统一张 LUT → 各用户逻辑设备名不能重复
  ② 每个用户一张 LUT → 可用于多用户系统（存于用户进程 PCB）
```

# 第四部分：SPOOLing 技术

## 概述（Overview）
> 假脱机技术（SPOOLing）：用软件方式模拟脱机输入/输出，将独占式设备（如打印机）虚拟化为共享设备。

### 核心组件

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│ 输入设备  │ →→→ │输入缓冲区│ →→→ │  输入井   │  （磁盘）
└──────────┘     └──────────┘     └──────────┘
                 （内存）             │
                                 输入进程读取

┌──────────┐     ┌──────────┐     ┌──────────┐
│ 输出设备  │ ←←← │输出缓冲区│ ←←← │  输出井   │  （磁盘）
└──────────┘     └──────────┘     └──────────┘
                 （内存）             │
                                 输出进程写入
```

### 共享打印机原理
> 多个用户请求打印 → 假脱机管理进程为每个用户：①在输出井申请空闲缓冲区存打印数据 ②创建打印请求表挂到队列 → 打印机空闲时，输出进程按队列顺序逐一打印。

# 第五部分：缓冲区管理

### 单缓冲 vs 双缓冲 vs 循环缓冲 vs 缓冲池

| 策略 | 处理一块数据平均耗时 | 特点 |
|------|---------------------|------|
| **单缓冲** | Max(C, T) + M | 单时刻只能单向传输 |
| **双缓冲** | Max(T, C + M) | 可实现双向同时传输 |
| **循环缓冲** | — | 多个缓冲区组成循环队列，in/out 指针管理 |
| **缓冲池** | — | 系统共用缓冲区，四种工作缓冲区（hin/sin/hout/sout） |

> T = 设备→缓冲区时间，C = CPU 处理时间，M = 缓冲区→工作区时间

# 第六部分：磁盘调度算法

### 一次磁盘读/写的时间组成

```
总时间 = 寻道时间(Ts) + 延迟时间(Tr) + 传输时间(Tt)

寻道时间：移动磁头到目标磁道（可被调度算法优化）
延迟时间：目标扇区转到磁头下（由转速决定，无法优化）
传输时间：实际读写数据（由转速和数据量决定）

物理地址 = (柱面号, 盘面号, 扇区号)
```

### 六种磁盘调度算法

| 算法 | 策略 | 寻道特点 | 饥饿 |
|------|------|----------|------|
| **FCFS** | 按请求顺序 | 公平但寻道长 | 不会 |
| **SSTF** | 优先处理最近磁道 | 贪心，平均寻道短 | **会** |
| **SCAN**（电梯） | 单向移动到最边再反向 | 较公平 | 不会 |
| **LOOK** | SCAN 改进——移动方向无请求就反向 | 比 SCAN 更快 | 不会 |
| **C-SCAN** | 单向处理+快速返回不处理 | 各位置响应频率均匀 | 不会 |
| **C-LOOK** | C-SCAN 改进——到有请求处就返回 | 比 C-SCAN 更快 | 不会 |

### 减少延迟时间的技巧
- **交替编号**：逻辑相邻扇区在物理上有间隔
- **错位命名**：相邻盘面扇区编号错位
- **地址结构**：用（柱面号, 盘面号, 扇区号）连续读取时不需要移动磁头

# 第七部分：固态硬盘 SSD

| 对比维度 | SSD | 机械硬盘 HDD |
|----------|-----|-------------|
| 读写单位 | 页（page）读/写 | 扇区读/写 |
| 擦除单位 | 块（block）擦除 | 无擦除概念 |
| 访问方式 | 电路寻址（随机访问快） | 机械移动（有寻道+旋转延迟） |
| 写前处理 | 写入有数据的页需先擦除整个块 | 直接覆盖 |
| 寿命问题 | 有（擦除次数有限） | 无 |
| 磨损均衡 | 动态+静态磨损均衡 | 无需 |
