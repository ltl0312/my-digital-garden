# 第一部分：基本分页存储管理

## 概述（Overview）
> 分页：将内存空间分为大小相等的页框（物理块），将进程的逻辑地址空间分为同样大小的页（页面），以页框为单位为进程分配内存。页面可以不连续存放。

### 逻辑地址结构

```
逻辑地址 A 的结构：
┌──────────────┬──────────────────┐
│   页号 P      │  页内偏移量 W     │
│  (M 位)       │  (K 位)          │
└──────────────┴──────────────────┘

页面大小 = 2^K B
进程最多有 2^M 个页面

物理地址 E = 内存块号 b × 页面大小 L + 页内偏移量 W
```

### 页表——核心数据结构

```
进程的页表（每个进程一张）：
┌──────┬──────────┐
│ 页号 │ 内存块号  │  ← 每个页表项 = 页号 + 块号
├──────┼──────────┤     （页号不占存储空间，可隐含）
│  0   │    3     │
│  1   │    7     │
│  2   │    12    │
│ ...  │   ...    │
└──────┴──────────┘
```

### 地址变换机构（基本 vs 快表 vs 两级）

```
【基本地址变换机构】—— 每次访存需要 2 次内存访问
  CPU 发出逻辑地址 A →
  ① P=A/L, W=A%L（计算页号和偏移量）
  ② 比较 P 与页表长度 M（越界检查）
  ③ 查页表：页表项地址 = F + P × 页表项长度 → 得块号 b
  ④ 物理地址 E = b × L + W → 访存

【具有快表（TLB）的地址变换机构】
  高速缓存 TLB 存放最近访问的页表项副本
  · 快表命中 → 仅需 1 次访存（不用查内存中的慢表）
  · 快表未命中 → 2 次访存 + 将新页表项存入快表

  局部性原理支撑快表的高命中率：
  · 时间局部性：刚执行的指令很可能再次执行（循环）
  · 空间局部性：访问某单元后，附近的单元很可能也被访问（顺序执行）

【两级页表】—— 解决大页表需要连续存储的问题
  逻辑地址 = [一级页号 | 二级页号 | 页内偏移量]
  · N 级页表访存次数 = N + 1（无快表时）
  · 各级页表大小不能超过一个页面
```

# 第二部分：基本分段与段页式

### 分页 vs 分段对比

| 维度 | 分页 | 分段 |
|------|------|------|
| 划分依据 | 物理单位（大小由系统固定） | 逻辑单位（大小由程序决定） |
| 对用户可见 | ❌ 不可见（系统行为） | ✅ 可见（程序员显式给段名） |
| 地址空间 | 一维（只需给出一个记忆符） | 二维（需给段名+段内地址） |
| 共享保护 | 不方便 | 方便（段=逻辑模块） |
| 碎片 | 内部碎片 | 外部碎片 |

### 段页式管理

```
逻辑地址 = [段号 | 页号 | 页内偏移量]

段表 → 页表 → 物理地址
┌──────┬────────┬──────────┐
│ 段号 │页表长度│页表起始块号│  ← 段表项
└──────┴────────┴──────────┘
    ↓
┌──────┬──────────┐
│ 页号 │ 内存块号  │  ← 页表项
└──────┴──────────┘

访存次数：3 次（查段表 → 查页表 → 访问内存单元）
引入快表后：仅需 1 次
```

# 第三部分：虚拟内存

## 概述（Overview）
> 虚拟内存：基于局部性原理，程序装入时只装入即将用到的部分，运行中按需从外存调入缺失部分；内存不够时换出暂时不用的部分。在用户看来，似乎有一个比实际物理内存大得多的内存。

**三大特征**：多次性（分多次调入）、对换性（可换入换出）、虚拟性（逻辑上扩充内存）。

## 实现（Implementation）

### 请求分页管理的关键机制

#### 缺页中断机构
```
缺页中断流程：
  访问页面不在内存 → 缺页中断（内中断）
  → 进程阻塞
  → OS 处理：
      内存有空闲块 → 直接调入
      内存无空闲块 → 页面置换算法选一页换出
        → 若被修改过 → 写回外存；否则直接覆盖
  → 更新页表 → 唤醒进程
```

#### 请求页表的增强字段

| 字段 | 作用 |
|------|------|
| 状态位 | 页面是否已调入内存 |
| 访问字段 | 最近被访问次数/时间，供置换算法参考 |
| 修改位 | 调入后是否被修改过（决定换出时是否写回） |
| 外存地址 | 页面在外存中的存放位置 |

### 五种页面置换算法

| 算法 | 淘汰策略 | 特点 |
|------|----------|------|
| **OPT**（最佳） | 淘汰最长时间内不再访问的页面 | 缺页率最低，但无法实现（理论下限） |
| **FIFO**（先进先出） | 淘汰最早进入内存的页面 | 实现简单，性能差，**唯一有 Belady 异常** |
| **LRU**（最近最久未用） | 淘汰最久未访问的页面 | 性能好，需硬件支持，开销大 |
| **CLOCK**（NRU） | 循环扫描，淘汰访问位=0 的 | 性能开销均衡，最多两轮扫描 |
| **改进型 CLOCK** | 优先淘汰未修改页 (0,0)→(0,1)→(1,0)→(1,1) | 减少 IO 写回，最多四轮扫描 |

> ⚠️ **Belady 异常**：FIFO 算法特有的异常——分配的物理块数增多但缺页次数反而增加。

### 页面分配策略

| 策略 | 置换范围 | 驻留集 | 特点 |
|------|----------|--------|------|
| 固定分配局部置换 | 仅自己 | 不变 | 难以确定合理物理块数 |
| 可变分配全局置换 | 全局 | 可变 | 简单，但可能影响其他进程 |
| 可变分配局部置换 | 仅自己 | 可变 | 更合理，根据缺页率动态调整 |

### 抖动（颠簸）
> 刚刚换出的页面马上又要换入，刚刚换入的页面马上又要换出。产生原因：进程频繁访问的页面数 > 可用的物理块数。解决方案：增加物理块分配。
