# 内存管理基础

## 📍 知识体系定位
- **所属技术栈**：计算机基础 / 操作系统
- **所在层级**：XD-2 操作系统 → 内存管理 → 基础概念
- **上游依赖**：<a href="obsidian://open?file=存储系统">计算机组成原理-存储系统</a> — 内存物理结构、地址总线、存储单元是理解 OS 内存管理的前提
- **下游延伸**：<a href="obsidian://open?file=非连续分配与虚拟内存">非连续分配与虚拟内存</a> — 分页/分段/虚拟内存是连续分配的进化
- **同级技术**：磁盘管理（都是存储管理，一层管内存一层管外存）

## 概述（Overview）
> 内存管理：OS 负责内存空间的分配与回收、逻辑地址到物理地址的转换、内存空间的扩充（虚拟技术）以及内存保护。

### 程序从编写到运行的完整流程

```
源代码(.c) ──编译──→ 目标模块(.o) ──链接──→ 装入模块(.exe) ──装入──→ 内存
          (编译器)           (链接程序)           (装入程序)
 高级语言→机器语言      多个.o+库→完整程序     exe→内存中运行

形成的地址：
  逻辑地址（相对地址）→ 编译链接后生成的指令地址
  物理地址（绝对地址）→ 数据在内存中实际存放的地址
```

## 设计初衷（Motivation）

### 三种装入方式（地址转换时机）

| 装入方式 | 地址转换时机 | 特点 | 适用场景 |
|----------|-------------|------|----------|
| **绝对装入** | 编译时 | 编译时已知内存位置，灵活性低 | 单道程序环境 |
| **静态重定位** | 装入时（一次完成） | 装入后不能移动，不能申请新空间 | 早期多道批处理 |
| **动态重定位** | 运行时（每次访问） | 需要重定位寄存器；可移动、可离散分配、可部分装入 | **现代 OS** |

### 三种链接方式

| 链接方式 | 时机 | 特点 |
|----------|------|------|
| 静态链接 | 运行前 | 各模块+库链接成完整 exe，不再拆开 |
| 装入时动态链接 | 装入时 | 边装入边链接 |
| 运行时动态链接 | 执行中 | 需要时再链接，便于修改更新和共享 |

### 内存保护机制

```
方式一：上下限寄存器
┌─────────────┐
│ 上限寄存器   │ ← 进程可访问的最高地址
├─────────────┤
│   进程空间   │
├─────────────┤
│ 下限寄存器   │ ← 进程可访问的最低地址
└─────────────┘
CPU 每次访问地址时检查是否在 [下限, 上限] 范围内

方式二：基址 + 限长寄存器
  物理地址 = 基址寄存器值 + 逻辑地址
  限长检查：逻辑地址 ≤ 限长寄存器值
```

## 实现（Implementation）

### 覆盖技术 vs 交换技术

| 维度 | 覆盖技术 | 交换技术 |
|------|----------|----------|
| 作用域 | 同一个程序/进程内部 | 不同进程之间 |
| 思想 | 区分"常驻段"和"覆盖段"，按需调入 | 内存紧张时把整个进程换出到外存 |
| 对用户透明 | ❌ 不透明（需程序员声明覆盖结构） | ✅ 透明（OS 负责） |
| 当前状态 | 只用于早期 OS | 现代 OS 仍在用（中级调度） |

### 交换技术的实现细节
```
磁盘空间划分：
  文件区 — 追求存储利用率（离散分配）
  对换区 — 追求换入换出速度（连续分配），IO 速度更快

交换策略：
  · 许多进程运行且内存吃紧时启动交换
  · 优先换出阻塞进程、低优先级进程
  · PCB 常驻内存，不会被换出
```

### 连续分配的三种方式

| 分配方式 | 思想 | 外部碎片 | 内部碎片 | 适用场景 |
|----------|------|----------|----------|----------|
| **单一连续分配** | 内存分系统区+用户区，仅一道用户进程 | 无 | 有 | 单用户单任务 |
| **固定分区分配** | 用户空间分为若干个固定大小分区 | 无 | 有 | 早期多道批处理 |
| **动态分区分配** | 进程装入时动态建立分区，大小正合适 | 有 | 无 | 现代 OS 基础 |

### 动态分区分配的四种算法

| 算法 | 查找策略 | 空闲分区排序 | 优点 | 缺点 |
|------|----------|-------------|------|------|
| **首次适应**（First Fit） | 从低地址找第一个满足的 | 地址递增 | 综合性能最好，开销小 | — |
| **最佳适应**（Best Fit） | 选最小的满足需求的分区 | 容量递增 | 保留大分区给大进程 | 产生很多难以利用的小碎片 |
| **最坏适应**（Worst Fit） | 选最大的分区 | 容量递减 | 减少小碎片 | 大分区被快速用完 |
| **邻近适应**（Next Fit） | 从上次结束位置继续找 | 地址递增（循环链表） | 减少查找开销 | 高地址大分区被用完 |
