# 词法分析

## 📍 知识体系定位
- **所在层级**：XD-4 编程语言与编译 → 编译器前端
- **上游依赖**：<a href="obsidian://open?file=编译器概述与文法">编译原理-编译器概述与文法</a>（3 型正则文法是理论基础）
- **下游延伸**：正则表达式引擎（grep/awk）、语法高亮

## 概述（Overview）
> 词法分析器扫描源码字符流，按词法规则（正则表达式描述）切分出 **Token（单词）** 序列。核心算法链路：**正则表达式 → NFA（Thompson 构造法）→ DFA（子集构造法）→ 最小化 DFA（Hopcroft 等价类划分）**。

## 设计初衷（Motivation）

### 设计思想
为什么不用上下文无关文法直接做词法分析？因为正则表达式比 CFG 简单得多——正则表达式对应有限自动机（无需栈），而 CFG 需要下推自动机（需要栈）。用最简单的工具做最简单的事——将"识别标识符/数字/运算符"这种局部模式交给正则表达式，将"嵌套括号/语句结构"这种全局递归结构交给 CFG。

### 核心算法

```
正规式 → NFA → DFA → 最小化DFA → 驱动程序
  ①         ②        ③           ④
```

| 步骤 | 算法 | 说明 |
|------|------|------|
| ① RE → NFA | Thompson 构造法 | 递归组合基本 NFA 单元 |
| ② NFA → DFA | 子集构造法 | ε-闭包消除不确定性，状态集合映射为 DFA 单状态 |
| ③ DFA 最小化 | Hopcroft 等价类划分 | 合并等价状态，消除冗余，得到最优状态图 |
| ④ 驱动 | switch-case/跳转表 | DFA 可直接翻译为代码 |

### 跨学科溯源
- NFA → DFA 子集构造 → XD-5（幂集构造：NFA 的 n 个状态对应 DFA 的 2^n 个状态——最坏情况下的状态爆炸）
- DFA 最小化 → XD-5（等价类划分：Myhill-Nerode 定理，状态可区分当且仅当存在后缀串使两者接受性不同）

## 实现（Implementation）

### Token 示例

```
输入：int x = 10 + y;
输出 Token 流：
[int] [id:x] [=] [num:10] [+] [id:y] [;]
```

### Lex/Flex 规则格式

```lex
%%
[0-9]+      { return NUMBER; }
[a-zA-Z_]+  { return IDENTIFIER; }
"if"        { return IF; }
"+"         { return PLUS; }
[ \t\n]     { /* skip whitespace */ }
%%
```
