# 编译器概述与文法基础

## 📍 知识体系定位
- **所属技术栈**：跨学科纵深
- **所在层级**：XD-4 编程语言与编译
- **上游依赖**：XD-1（指令集 ISA——目标代码生成的底层基础）
- **下游延伸**：V8 JIT 引擎、Webpack/Lint 底层原理
- **同级技术**：解释器设计、虚拟机（JVM/CLR）

## 概述（Overview）
> **编译器**采用"先翻译后执行"模式，将高级语言一次性翻译为机器码（生成独立可执行文件）。**解释器**采用"边翻译边执行"模式，不生成独立目标程序。现代编译器采用**前端（源语言相关）+ 优化器（平台无关）+ 后端（目标机器相关）** 的三段式流水线架构。Chomsky 的四类文法体系定义了语言的表达能力——3 型（正则文法）做词法分析，2 型（上下文无关文法 CFG）做语法分析。

## 设计初衷（Motivation）

### 编译器的三段式架构

```
源程序 → [前端] → 中间表示(IR) → [优化器] → 优化后 IR → [后端] → 目标机器码
         词法/语法/语义          数据流/循环/内联          指令选择/寄存器分配
```

三段式架构的核心优势：**M × N 问题变为 M + N**。M 种源语言 + N 种目标机器，如果每种组合做一个编译器 = M×N 个编译器。有了统一的 IR，只需 M 个前端 + N 个后端 = M + N 个模块。

### Chomsky 文法体系

| 类型 | 名称 | 规则限制 | 对应自动机 | 在编译中 |
|------|------|---------|-----------|---------|
| 0型 | 短语结构 | 无限制 | 图灵机 | - |
| 1型 | 上下文有关 | `αAβ → αγβ` | 线性有界自动机 | - |
| **2型** | 上下文无关(CFG) | `A → γ`（左部单非终结符） | 下推自动机 | **语法分析** |
| **3型** | 正则 | `A → aB` 或 `A → a` | 有限自动机 | **词法分析** |

### 跨学科溯源
- 编译三段式 → XD-6（分层架构：M×N → M+N 是软件工程的经典化解耦合策略）
- Chomsky 文法体系 → XD-5（形式语言理论：文法生成能力严格递减的层次结构）

## 实现（Implementation）

### 编译 vs 解释

| 维度 | 编译 (Compiler) | 解释 (Interpreter) |
|------|----------------|-------------------|
| 模式 | 先翻译后执行 | 边翻译边执行 |
| 产物 | 独立目标程序 | 无 |
| 执行效率 | **高** | 低 |
| 跨平台 | 需重新编译 | **天然跨平台** |
| 调试 | 较难 | **易**（逐行执行） |
| 代表 | C/C++, Rust, Go | Python, JS(传统), Ruby |

### 推导与二义性

```
给定文法：E → E + E | E * E | (E) | id
句子：id + id * id

最左推导：每次替换最左边的非终结符
最右推导（规范推导）：每次替换最右边的非终结符

二义性：同一句子存在两棵不同语法树
→ 程序设计语言的文法必须消除二义性！
```
