# 代码优化与目标代码生成

## 📍 知识体系定位
- **所在层级**：XD-4 编程语言与编译 → 编译器后端
- **上游依赖**：<a href="obsidian://open?file=语法制导翻译与中间代码">编译原理-语法制导翻译与中间代码</a>、<a href="obsidian://open?file=指令系统">计算机组成原理-指令系统</a>
- **下游延伸**：LLVM 优化 Pass、GPU 着色器编译器
- **同级技术**：数据库查询优化器（也基于"等价变换"原则）

## 概述（Overview）
> **代码优化**在保持语义等价的前提下，通过数据流分析和控制流分析变换 IR，目标是"跑得更快"和"占得更少"。**目标代码生成**是编译器的最后一公里——**指令选择**（IR → 机器指令）、**寄存器分配**（图着色算法决定哪些变量留在寄存器中）、**指令调度**（重排指令避免流水线停顿）。

## 设计初衷（Motivation）

### 优化原则
> "等价转换"——绝对不能改变程序的输出结果。这是优化的铁律，任何违反此原则的变换都是错误的。

### 常见优化手段

| 类别 | 技术 | 说明 |
|------|------|------|
| **局部优化** | 常量折叠 | `x = 2*3` → 编译时计算为 6 |
| | 公共子表达式消除 | `a=b+c; d=b+c` → `t=b+c; a=t; d=t` |
| **循环优化** | 代码外提 | 将循环不变计算移出循环体 |
| | 强度削弱 | 循环内 `i*4` → `i++`（乘法变加法） |
| **全局优化** | 死代码删除 | 删除永远无法到达的代码 |
| | 内联展开 | 小函数体直接嵌入调用点（免去调用开销） |

### 寄存器分配——图着色问题

```
变量 → 图节点
两个变量同时活跃 → 节点间有边
寄存器 = 颜色
用 K 种颜色给图着色，相邻节点不同色
→ K 个寄存器足够时着色成功；不足时 spill 到内存
```

### 跨学科溯源
- 控制流图 CFG → XD-5（有向图遍历：支配树 Dominator Tree、循环检测 Natural Loop）
- 寄存器分配 → XD-5（图着色是 NP 完全问题；Chaitin 算法用启发式贪心 + spill 处理）

## 实现（Implementation）

### 优化示例

```
优化前：                      优化后：
i = 0                         i = 0
while (i < n) {              t1 = n * 4
    x = x + arr[i]          while (i < n) {
    i = i + 1                   x = x + arr[i]
}                               i = i + 1
                            }
// 编译器的视角远比你丰富——它能看到所有上下文
```

> **💡 补充**：现代 C/C++ 的 `-O2` 优化竟能执行数百个 Pass（分析→变换→再分析）。很多你认为的"优化"在编译器看来只是"基本操作"——比如 `x / 2` 编译为 `x >> 1`（位移代替除法），这是指令选择阶段自动完成的。
