# 语法制导翻译与中间代码生成

## 📍 知识体系定位
- **所在层级**：XD-4 编程语言与编译 → 语义分析 + IR
- **上游依赖**：<a href="obsidian://open?file=语法分析-自下而上(LR)">编译原理-语法分析-自下而上(LR)</a>
- **下游延伸**：LLVM IR、Java Bytecode、WebAssembly

## 概述（Overview）
> **语法制导翻译（SDT）** 在语法分析的同时触发语义规则——不用单独遍历 AST。**属性文法**为文法符号挂载属性：**综合属性**（子→父，自下而上）和**继承属性**（父/兄→子，自上而下）。**中间代码（IR）** 是平台无关的内部表示，经典的**三地址码**（四元式）形式如 `t1 = a + b`。控制流翻译用**回填（Backpatching）** 处理前向跳转。

## 设计初衷（Motivation）

### 综合属性 vs 继承属性

| 属性类型 | 数据流向 | 典型用途 | 适用分析 |
|---------|---------|---------|---------|
| 综合属性 | 子节点 → 父节点 | 表达式求值（`E.val = E1.val + T.val`） | LR（自下而上） |
| 继承属性 | 父/兄 → 子节点 | 类型信息传递、作用域 | LL（自上而下） |

### S-属性 vs L-属性

- **S-属性文法**：仅含综合属性 → 完美契合 LR 归约时机（归约时子节点属性已经算出）
- **L-属性文法**：允许继承属性按"从左到右"顺序计算 → 适合 LL 自上而下分析

### 中间代码的设计目标
1. **平台无关**：解耦前端（语言）与后端（目标机器）
2. **易于优化**：三地址码形式简单，方便数据流分析和变换
3. **易于翻译**：每条三地址码指令可直观映射为 1-3 条机器指令

### 跨学科溯源
- 属性文法 → XD-5（树上的动态规划：子节点属性 = f(子节点属性) + g(继承属性)）
- 回填技术 → XD-5（延迟绑定：用单向链表记录待填地址，到达目标后遍历回填）

## 实现（Implementation）

### 中间代码形式

```
三地址码（四元式）：(op, arg1, arg2, result)
  t1 = a + b       → (+, a, b, t1)
  if x > y goto L  → (j>, x, y, L)

逆波兰式（后缀式）：a b + c *   ← 无需括号，适合栈式求值

三元式：(op, arg1, arg2)  ← 用序号引用临时结果

DAG（有向无环图）：识别公共子表达式，避免重复计算
```

### 回填技术示例

```
if (a > b)         // 翻译为：
    x = 1;         // 1. if a > b goto ? (跳哪里还不知道)
else               // 2. goto ? (else 跳哪里也不知道)
    x = 2;         // 回填: 1 → 标号L1; 2 → 标号L2
```

> **💡 补充**：LLVM IR 是现代最著名的中间表示——Clang 将 C/C++ → LLVM IR，再由 LLVM 优化器处理后生成 x86/ARM/WASM 等目标码。LLVM IR 本质是一种 SSA（静态单赋值）形式的三地址码。
