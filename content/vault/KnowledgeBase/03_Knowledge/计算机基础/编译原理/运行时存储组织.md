# 运行时存储组织

## 📍 知识体系定位
- **所在层级**：XD-4 编程语言与编译 → 运行时系统
- **上游依赖**：<a href="obsidian://open?file=语法制导翻译与中间代码">编译原理-语法制导翻译与中间代码</a>（IR 中的变量需要存储分配）
- **下游延伸**：C 调用约定（calling convention）、GC 垃圾回收
- **同级技术**：操作系统内存管理（虚拟内存/分页）

## 概述（Overview）
> 编译器需要为程序中的变量和数据结构分配存储空间，有三种策略：**静态分配**（编译时确定地址，不支持递归）、**栈式动态分配**（函数调用时在栈上创建/销毁活动记录，支持递归）、**堆式动态分配**（运行时按需分配，支持动态数据结构）。每个函数调用创建一个**活动记录（栈帧）**，包含返回地址、参数、局部变量。**静态链**实现词法作用域（闭包的基础），**动态链**实现函数返回。

## 设计初衷（Motivation）

### 三种分配策略

| 策略 | 时机 | 特点 | 支持递归 | 典型语言 |
|------|------|------|---------|---------|
| 静态分配 | 编译时 | 无运行时开销 | ❌ | Fortran 77 |
| 栈式分配 | 函数调用时 | LIFO，自动回收 | ✅ | C/C++ 局部变量 |
| 堆式分配 | 运行时按需 | 灵活，需手动/GC回收 | ✅ | `malloc` / `new` |

### 静态链 vs 动态链

```
函数调用嵌套：
  A() 调用 B() 调用 C()
  动态链：C → B → A（调用者链，用于返回）
  
词法嵌套：
  outer() {           ← 外层
    inner() {         ← 内层（可访问 outer 的变量！）
      访问 outer 的变量 → 通过静态链找到 outer 的活动记录
    }
  }
```

**闭包（Closure）的底层机制**：当一个嵌套函数被当作值返回时，它需要携带其静态链指向的外层活动记录。这就是为什么 JavaScript 的闭包能让内层函数"记住"外层的变量——实际上是静态链在运行时保持了对已返回活动记录的引用。

### 跨学科溯源
- 栈式分配 → XD-1（CPU 的 SP/BP 寄存器维护栈帧边界，Call/Ret 指令操作栈）
- 静态链 → XD-5（链表结构：每个活动记录存一个指针，沿链向上查找非局部变量）

## 实现（Implementation）

### 活动记录结构

```
栈顶（低地址）
┌──────────────┐
│  临时变量    │ ← SP
├──────────────┤
│  局部数据    │
├──────────────┤
│  静态链(访问)│ ← 指向词法外层活动记录
├──────────────┤
│  动态链(控制)│ ← 指向调用者活动记录
├──────────────┤
│  返回地址    │
├──────────────┤
│  参数        │
└──────────────┘ ← BP
栈底（高地址）
```
