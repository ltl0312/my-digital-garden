# Git 远程仓库与团队协作

## 📍 知识体系定位
- **所属技术栈**：DevOps / 运维
- **所在层级**：Git 版本控制 → 远程协作层
- **上游依赖**：<a href="obsidian://open?file=分支管理与合并策略">Git 分支管理与合并策略</a> — 远程协作是分支策略在多人环境中的延伸
- **下游延伸**：<a href="obsidian://open?file=Compose全栈部署与网络拓扑">Docker-Compose 全栈部署</a> — 远程仓库是 CI/CD 的代码源
- **同级技术**：SVN 集中式协作，GitHub/GitLab/Gitee 托管平台

## 概述（Overview）
> 一句话定义：Git 远程仓库是托管在网络上的仓库副本，通过 `push`/`pull`/`fetch` 实现多人协作。配合 Pull Request 和 Code Review，构成现代软件开发协作的标准工作流。

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：SVN 中所有操作依赖中央服务器，离线无法工作。
- **本技术的核心突破**：Git 将"保存进度"（commit）和"分享进度"（push）分离。commit 本地执行，push 联网分享——开发者在代码准备好后才推送。
- **为什么是它活下来了**：GitHub 构建了 Pull Request 机制（2008），引入代码审查、CI 检查、讨论等社会协作层，Git 从工具变成了协作平台。

### 设计思想
**push/pull 的不对称性**：`pull = fetch + merge`，先获取再合并。理解这个组合关系是关键。

**远程跟踪分支**：`origin/main` 是 Git 在本地维护的远程状态镜像。`git status` 显示的"ahead/behind"就是本地与远程跟踪分支的对比。

## 实现（Implementation）

### 关联与查看远程仓库

```bash
git remote add origin git@github.com:username/repo.git   # 关联远程仓库
git remote -v                                             # 查看远程仓库
git remote rename origin upstream                         # 重命名
git remote remove origin                                  # 删除关联
```

### 克隆与拉取

```bash
git clone git@github.com:username/repo.git                # SSH 方式（推荐）
git clone git@github.com:username/repo.git custom-folder  # 指定目录名

git fetch origin            # 获取远程信息（不自动合并！安全操作）
git pull origin main        # = fetch + merge
git fetch --all             # 拉取所有远程分支信息
```

### 推送分支

```bash
git push -u origin feature-login    # 首次推送 + 设置上游跟踪
git push                            # 之后直接推送
git push --force-with-lease         # 安全强制推送（防覆盖他人工作）
git push origin --delete old-branch # 删除远程分支
```

### Pull Request 工作流

```text
1. git checkout -b feature/new-feature main    # 创建功能分支
2. git add . && git commit -m "feat: ..."      # 开发并提交
3. git push -u origin feature/new-feature      # 推送
4. 在 GitHub/GitLab 创建 Pull Request           # 请求合并
5. Code Review → CI 检查 → 讨论修改            # 审查迭代
6. 合并到主分支                                  # Merge/Squash/Rebase
7. git branch -d feature/new-feature            # 清理本地
   git push origin --delete feature/new-feature # 清理远程
```

### Code Review 最佳实践

**提交者**：保持 PR 小范围专注、写好提交信息、通过测试再推送、及时处理 Review 意见。

**审查者**：24h 内响应、提供具体建设性反馈、检查代码风格一致性、验证功能完整性。

### 多人协作要点
1. 使用分支，主分支保护，通过 PR 合并
2. Conventional Commits 规范提交信息
3. 定期 `git rebase main` 保持同步，避免巨大冲突
4. 通过 PR 和 Code Review 保障质量
5. 团队保持及时有效沟通
