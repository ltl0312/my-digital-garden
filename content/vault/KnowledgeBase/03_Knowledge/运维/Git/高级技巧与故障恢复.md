## 一、暂存未完成工作：`git stash`

```bash
# ① 场景：正在开发功能，突然需要切分支修 bug
git stash                           # 保存工作区和暂存区到"储藏栈"
git stash save "WIP: 描述信息"       # 带描述的储藏（推荐！）
git stash list                      # 查看所有储藏
git stash pop                       # 恢复最近储藏 + 删除记录（最常用）
git stash apply stash@{0}           # 恢复但不删除
git stash drop stash@{0}            # 删除某个储藏
git stash clear                     # 清空所有储藏
```

## 二、找回"丢失"的提交

### `git reflog` — Git 的操作历史

```bash
# ① 场景：reset --hard 后想找回提交
git reflog
# ③ 输出：a1b2c3d HEAD@{0}: commit: feat: 完成用户模块
#         d4e5f6g HEAD@{1}: reset: moving to HEAD~1     ← "丢失"的提交
#         h7i8j9k HEAD@{2}: commit: feat: 添加支付功能  ← 目标！

git checkout h7i8j9k                  # 恢复
git branch recovered-branch h7i8j9k   # 或创建新分支指向它
```

> **💡 补充**：reflog 默认保留 90 天（可达提交）和 30 天（不可达提交）。只要在 reflog 中就没有真正的"永久丢失"。

### 恢复误删的文件

```bash
git log --diff-filter=D --summary             # 找删除文件的提交
git checkout <commit-hash>^ -- <file-path>    # 恢复（^ 指向父提交）
```

### 提交到错误分支后的修复

```bash
# 记录要移植的提交 SHA，切换到正确分支
git checkout correct-branch
git cherry-pick <commit-hash>       # 将指定提交"复制"到当前分支
# 回退错误分支
git checkout wrong-branch
git reset --hard HEAD~1
```

## 三、自动化：Git Hooks

存放在 `.git/hooks/` 目录，在特定事件前后自动执行。

```bash
#!/bin/sh
# .git/hooks/pre-commit — 提交前运行 lint + 测试
npm run lint
if [ $? -ne 0 ]; then
    echo "❌ Lint 检查未通过，提交已中止"
    exit 1
fi
npm test
```

```bash
#!/bin/sh
# .git/hooks/commit-msg — 检查提交信息是否符合 Conventional Commits
MSG=$(cat $1)
PATTERN="^(feat|fix|docs|style|refactor|test|chore)(\(.+\))?: .{1,}"
if ! echo "$MSG" | grep -qE "$PATTERN"; then
    echo "❌ 提交信息格式错误！期望格式: <type>: <subject>"
    exit 1
fi
```

> **💡 补充**：推荐使用 **Husky** 框架自动化管理 hooks。

## 四、子模块管理：`git submodule`

```bash
git submodule add <url> <path>                    # 添加子模块
git clone --recurse-submodules <url>              # 克隆含子模块的项目
git submodule update --init --recursive           # 更新所有子模块
```

## 五、仓库性能优化

```bash
git gc --prune=now --aggressive          # 垃圾回收，清理不可达对象
git repack -a -d --depth=250 --window=250  # 重新打包减少碎片

# 大文件误提交后清理
bfg --delete-files 大文件名.psd          # 使用 BFG Repo Cleaner
git reflog expire --expire=now --all
git gc --prune=now --aggressive
# ③ ⚠️ 改写历史，所有协作者需要重新 clone
```
