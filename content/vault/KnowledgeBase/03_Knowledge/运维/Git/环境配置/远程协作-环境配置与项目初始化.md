# Git — 远程协作环境配置

> 本指南聚焦于 Git 远程仓库认证和协作配置。基础安装请参考 <a href="obsidian://open?file=环境配置与项目初始化">Git 环境配置与项目初始化</a>。

## 信息来源
- **官方文档**：https://docs.github.com/en/authentication/connecting-to-github-with-ssh （✅ 可访问）

## Step 1: SSH 多账号配置

```bash
# 1. 生成多个密钥
ssh-keygen -t ed25519 -C "personal@email.com" -f ~/.ssh/id_ed25519_personal
ssh-keygen -t ed25519 -C "work@company.com" -f ~/.ssh/id_ed25519_work

# 2. 编辑 ~/.ssh/config
```

```text
# 个人 GitHub
Host github.com-personal
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_personal
    IdentitiesOnly yes

# 公司 GitLab
Host gitlab.com-work
    HostName gitlab.com
    User git
    IdentityFile ~/.ssh/id_ed25519_work
    IdentitiesOnly yes
```

```bash
# 3. 克隆时使用自定义 Host
git clone git@github.com-personal:username/personal-project.git
git clone git@gitlab.com-work:company/work-project.git

# 4. 修改已有仓库的 remote URL
git remote set-url origin git@github.com-personal:username/repo.git
```

## Step 2: HTTPS 凭据缓存

```bash
# macOS
git config --global credential.helper osxkeychain

# Windows
git config --global credential.helper manager

# Linux（缓存一周）
git config --global credential.helper 'cache --timeout=604800'
```

## Step 3: Push 默认行为

```bash
git config --global push.default simple
# simple：只推送当前分支到同名远程分支（推荐，最安全）
```

## Step 4: 安全强制推送别名

```bash
git config --global alias.pushf "push --force-with-lease"
# 使用 git pushf 代替 git push --force
# --force-with-lease：远程有新提交时拒绝强制推送
```

## 常见远程协作问题

### 问题 1：push 被拒绝，远程有新提交
```bash
git pull --rebase origin main    # 先拉取并 rebase
git push                         # 再推送
```

### 问题 2：SSH 连接超时
```bash
ssh -vT git@github.com           # 测试连接
# 如 22 端口被防火墙阻止，改用 HTTPS：
git remote set-url origin https://github.com/username/repo.git
```

### 问题 3：误 force push 覆盖了团队提交
```bash
git reflog                       # 查看操作历史，联系被覆盖提交的作者
```
