# Git 分支管理与合并策略

## 📍 知识体系定位
- **所属技术栈**：DevOps / 运维
- **所在层级**：Git 版本控制 → 分支管理层
- **上游依赖**：<a href="obsidian://open?file=基本操作与历史管理">Git 基本操作与历史管理</a> — 分支操作的原子单位是 commit
- **下游延伸**：<a href="obsidian://open?file=远程仓库与团队协作">Git 远程仓库与团队协作</a> — 本地分支通过 push/pull 与团队同步
- **同级技术**：SVN 分支（重量级、目录拷贝式），Mercurial 分支

## 概述（Overview）
> 一句话定义：Git 分支是**指向某个提交对象的可变指针**。创建分支几乎零成本（仅 41 字节），这让并行开发、功能隔离、版本发布等复杂工作流成为可能。

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：SVN 的分支本质是**拷贝整个目录**，创建分支需要数分钟，合并时逐文件比对。
- **为什么前身被淘汰**：笨重的分支操作限制了并行开发。开发者倾向于直接在主干修改，冲突频繁。
- **本技术的核心突破**：Git 将分支设计为**轻量级指针**（41 字节文件）。创建、切换、合并几乎瞬间完成。"一个功能一个分支"成为可能。
- **为什么是它活下来了**：轻量级分支是 GitHub Flow / Git Flow 的基础。分支的"低成本试错"彻底改变了团队协作——自由尝试，不合适就删除，零风险。
- **当前版本**：Git 2.23 引入 `git switch`（分支切换）和 `git restore`（文件恢复）。

### 设计思想
**分支即指针**：`master` 和 `feature/user-auth` 都只是指向某次提交的指针（`.git/refs/heads/分支名`）。提交时当前分支指针自动前移。Git 使用**有向无环图（DAG）**组织提交历史——每次提交记录父提交 SHA，分支和合并自然形成图结构。

## 实现（Implementation）

### 基础分支操作

```bash
git branch                    # 查看所有本地分支
git branch -a                 # 查看所有分支（含远程跟踪）
git branch -v                 # 查看每个分支的最后一次提交

git branch feature-login      # 在当前提交上创建新分支（不切换）
git checkout -b feature-login # 创建并切换（旧语法）
git switch -c feature-login   # 创建并切换（新语法，推荐）

git checkout main             # 切换到已有分支（旧语法）
git switch main               # 切换到已有分支（新语法，推荐）

git branch -d feature-login   # 安全删除已合并分支
git branch -D abandoned       # 强制删除（丢弃未合并的修改）
```

### 合并与变基

```bash
# ① 场景：将 feature-login 合并到 main
git checkout main
git merge feature-login
# ② 自动选择策略：Fast-forward（main 无新提交）或 3-way merge

# ① 场景：禁用快进合并，保留分支历史痕迹（推荐！）
git merge --no-ff feature-login

# ① 场景：变基——让历史变成一条直线
git checkout feature-login
git rebase main
# ③ ⚠️ 改写 SHA，不要在已推送的分支上使用

# ① 场景：交互式变基（推送前整理本地提交）
git rebase -i HEAD~3
# ② 可选操作：pick(保留) / squash(合并) / reword(改信息) / drop(删除)
```

### 处理合并冲突

```bash
# 冲突标记格式：
<<<<<<< HEAD
当前分支的代码
=======
被合并分支的代码
>>>>>>> feature-login

# 手动解决后：
git add <resolved-file>
git commit -m "merge: 解决登录页面冲突"

# 放弃合并：
git merge --abort
```

### 主流分支策略

**Git Flow（固定发布周期）：**
```text
main (生产代码)
└── develop (开发主线)
    ├── feature/* (功能分支 → develop)
    ├── release/* (发布分支 → main + develop)
    └── hotfix/* (热修复 → main + develop)
```

**GitHub Flow（持续部署）：**
```text
main (始终可部署)
└── feature/* (功能分支 → PR → main)
```

**简化版（推荐大多数团队）：**

| 分支类型 | 命名示例 | 用途 | 合并到 |
|---------|---------|------|--------|
| 主分支 | `main` | 生产代码 | — |
| 开发分支 | `develop` | 日常集成 | `main` |
| 功能分支 | `feature/user-auth` | 新功能 | `develop` |
| Bug 修复 | `bugfix/login-error` | 非紧急修复 | `develop` |
| 热修复 | `hotfix/critical-bug` | 紧急修复 | `main` + `develop` |
| 发布分支 | `release/v1.2.0` | 版本发布 | `main` + `develop` |
