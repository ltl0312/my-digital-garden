# Nginx 反向代理与负载均衡

## 📍 知识体系定位
- **所属技术栈**：DevOps / 运维
- **所在层级**：Nginx → 代理与调度层
- **上游依赖**：<a href="obsidian://open?file=核心概念与安装配置">Nginx 核心概念与安装配置</a> — 先理解 nginx.conf 结构和 server/location 块
- **下游延伸**：<a href="obsidian://open?file=HTTPS性能优化与运维">Nginx HTTPS、性能优化与运维</a> — 代理 + HTTPS + 性能调优 = 生产级网关
- **同级技术**：HAProxy（专注负载均衡）、Traefik（云原生网关）

## 概述（Overview）
> 反向代理是 Nginx 最核心的能力——客户端请求 Nginx，Nginx 依据规则将请求转发到后端服务器，再将响应回传给客户端。客户端不知道后端真实服务器的存在。配合 `upstream` 模块，Nginx 还能在多个后端服务器之间做**负载均衡**。

---

## 正向代理 vs 反向代理

| 维度 | 正向代理 | 反向代理 |
|------|---------|---------|
| **代理对象** | 代理**客户端** | 代理**服务端** |
| **客户端感知** | 客户端知道代理存在（需配置代理地址） | 客户端以为在访问目标服务器（透明） |
| **典型场景** | 访问境外网站、隐藏客户端 IP | 负载均衡、SSL 终端、隐藏后端架构 |
| **一句话** | "客户端主动找代理帮忙上网" | "后端偷偷用代理对外提供服务" |

## 实现（Implementation）

### 反向代理基础配置

```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        # ② proxy_pass：将请求转发到后端服务器
        proxy_pass http://192.168.1.100:8080;

        # ② 传递客户端真实信息给后端（否则后端只能看到 Nginx 的 IP）
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

> ⚠️ `proxy_pass` 末尾 `/` 的规则：`http://backend:8080/`（有斜杠）→ 去掉 location 前缀转发；`http://backend:8080`（无斜杠）→ 保留 location 前缀。

### 负载均衡（upstream）

```nginx
# ② upstream 定义后端服务器集群
upstream backend_servers {
    # 轮询（默认）：逐一分配到各服务器
    server 192.168.1.101:8080;
    server 192.168.1.102:8080;
}

server {
    listen 80;
    location / {
        proxy_pass http://backend_servers;  # ② 指向 upstream 名称
    }
}
```

### 三种负载均衡算法

| 算法 | 配置 | 说明 | 适用场景 |
|------|------|------|---------|
| **轮询（默认）** | 不额外配置 | 请求按时间顺序逐一分配，故障服务器自动剔除 | 后端服务器性能相同 |
| **权重** | `server ip:port weight=3;` | 权重越高分配越多请求 | 服务器性能不均 |
| **IP 哈希** | `ip_hash;` | 同一客户端 IP 始终分配到同一台服务器 | 需要会话保持（Session） |

```nginx
upstream backend_servers {
    # ② 权重轮询：101 收到 3 倍于 102 的请求
    server 192.168.1.101:8080 weight=3;
    server 192.168.1.102:8080 weight=1;
}

upstream sticky_servers {
    # ② IP 哈希：同一用户始终命中同一台服务器
    ip_hash;
    server 192.168.1.101:8080;
    server 192.168.1.102:8080;
}
```

### 通过反向代理解决跨域（CORS）

核心思路：**将跨域请求转为同域请求**。前端请求 Nginx（同域），Nginx 转发到真实后端，绕过浏览器的同源策略。

```nginx
server {
    listen 80;
    server_name frontend.com;

    # ② 前端静态资源（同域）
    location / {
        root /path/to/frontend/dist;
        index index.html;
    }

    # ② 反向代理 API 请求到真实后端
    location /api/ {
        proxy_pass http://backend.com:8080/;

        # ② 设置 CORS 响应头（可选，代理后通常不需要）
        add_header Access-Control-Allow-Origin $http_origin;
        add_header Access-Control-Allow-Methods GET,POST,PUT,DELETE,OPTIONS;
        add_header Access-Control-Allow-Headers Content-Type,Authorization;
        add_header Access-Control-Allow-Credentials true;
    }
}
```

> 效果：前端只需请求同域的 `http://frontend.com/api/xxx`，Nginx 自动转发到后端，浏览器认为同域请求，不再拦截。

### 路径转发（多服务调度）

```nginx
server {
    listen 80;
    server_name api.example.com;

    # ② 按 URL 路径分发到不同后端服务
    location /user/  { proxy_pass http://127.0.0.1:5001/; }   # 用户服务
    location /order/ { proxy_pass http://127.0.0.1:5002/; }   # 订单服务
    location /pay/   { proxy_pass http://127.0.0.1:5003/; }   # 支付服务
}
```

### WebSocket 反向代理

```nginx
location /ws/ {
    proxy_pass http://127.0.0.1:4000/;
    proxy_http_version 1.1;                        # ② 必须 HTTP/1.1
    proxy_set_header Upgrade $http_upgrade;         # ② 升级为 WebSocket
    proxy_set_header Connection "Upgrade";
    proxy_read_timeout 86400;                       # ② 长连接超时（24h）
}
```
