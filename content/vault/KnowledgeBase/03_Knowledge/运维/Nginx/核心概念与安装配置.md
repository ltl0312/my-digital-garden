# Nginx 核心概念与安装配置

## 📍 知识体系定位
- **所属技术栈**：DevOps / 运维
- **所在层级**：L3 编排与网关 → Nginx（反向代理 / 负载均衡 / 静态服务）
- **上游依赖**：<a href="obsidian://open?file=XD-3 计算机网络">XD-3 计算机网络</a> — HTTP 协议、TCP/IP、DNS 解析是理解 Nginx 的前置条件
- **下游延伸**：<a href="obsidian://open?file=Compose全栈部署与网络拓扑">Docker-Compose 全栈部署</a> — Nginx 作为前端网关，Docker 管理后端服务
- **同级技术**：Apache HTTP Server（传统多进程模型）、Caddy（自动 HTTPS）、HAProxy（专注负载均衡）

## 概述（Overview）
> 一句话定义：Nginx 是一款**轻量级、高性能的 HTTP 和反向代理服务器**，采用事件驱动的异步非阻塞模型，能够高效处理大量并发连接。在高并发场景下，Nginx 保持较低资源消耗的同时提供更快的响应速度。

Nginx（发音：engine-x）由俄罗斯开发者 Igor Sysoev 于 2004 年创建。它可以同时充当：Web 服务器（托管静态网站）、反向代理（转发请求到后端）、负载均衡器（分流到多台服务器）、缓存加速器和 HTTPS 终端。

## 设计初衷（Motivation）

### 历史演进
- **前身技术**：Apache HTTP Server（1995）是 Nginx 之前最主流的 Web 服务器，采用**多进程/多线程模型**（prefork/worker MPM），每个连接占用一个线程。
- **为什么前身被淘汰**：Apache 在高并发（C10K 问题）下表现不佳——每个连接消耗独立线程，内存和 CPU 资源随并发量线性增长，无法高效应对现代互联网的千万级并发。
- **本技术的核心突破**：Nginx 采用**事件驱动 + 异步非阻塞 I/O** 架构，一个 worker 进程通过 epoll/kqueue 同时处理数千个连接，资源消耗与并发数**解耦**——从"一个连接一个线程"变为"一个进程处理所有连接"。
- **为什么是它活下来了**：Apache 仍然是市场份额最高的 Web 服务器（存量老项目），但 Nginx 在现代架构中已成为事实标准——几乎所有云原生架构、微服务网关、Kubernetes Ingress 都以 Nginx（或基于 Nginx 的 OpenResty/APISIX）为基础。其轻量、高性能、配置简洁的特点完美契合云原生时代。
- **当前版本**：Nginx 1.24.x（稳定版），Nginx 1.25.x（主线版）。

> ⚠️ **版本兼容性**：本文配置基于 Nginx 1.24.x。`listen 443 ssl` 在较新版本中改为 `listen 443 ssl http2`。

### 设计思想

**事件驱动模型**：Nginx 的核心是一个 master 进程 + 多个 worker 进程。Master 负责读取配置和管理 worker，每个 worker 是单线程的事件循环（类似 Node.js），通过 epoll（Linux）/ kqueue（macOS）监听大量连接的事件。当请求到达时——"有活就干，没活就歇"——而不是为每个请求创建新线程。

## Nginx vs Apache

| 对比项 | Nginx | Apache |
|--------|-------|--------|
| **架构** | 异步非阻塞（event-driven） | 多进程/多线程（传统） |
| **并发性能** | 更优秀，"吃得少干得多" | 高并发时容易"吃不消" |
| **配置难度** | 简洁、模块化 | 功能强但略复杂 |
| **资源占用** | 少 | 相对高 |
| **热更新模块** | 不支持（需重新编译） | 支持（可动态加载） |
| **使用场景** | 静态服务、代理、微服务 | 动态网站、老项目 |

> Apache 是"老派绅士"，Nginx 是"新锐干将"。

## 实现（Implementation）

### 安装方式

| 方式 | 特点 | 适用场景 |
|------|------|---------|
| **yum/apt** | 自动解决依赖，可用 systemctl 管理 | 快速部署、生产基础版本 |
| **源码编译** | 可定制模块，需手动 configure + make | 需要自定义功能/特定版本 |
| **Docker** | 一键启动，隔离环境 | 开发测试、微服务架构 |
| **二进制包** | 解压即用，无需编译 | 离线部署 |

### 源码编译安装（CentOS）

```bash
# ② 安装编译依赖
yum -y install gcc pcre-devel zlib-devel openssl openssl-devel
# gcc: C编译器, pcre: 正则表达式支持, zlib: 压缩, openssl: SSL/TLS

# ② 下载并解压
wget https://nginx.org/download/nginx-1.24.0.tar.gz
tar -zxvf nginx-1.24.0.tar.gz
cd nginx-1.24.0

# ② 配置编译参数（--prefix 指定安装目录）
./configure --prefix=/usr/local/nginx

# ② 编译并安装
make && make install
```

### Docker 安装

```bash
docker run -d --name my-nginx -p 8080:80 \
  -v $(pwd)/html:/usr/share/nginx/html \
  nginx
# ② -p 8080:80: 宿主机 8080 → 容器 80
# ② -v: 挂载本地 html 目录到 Nginx 默认站点目录
```

### 启动与基本管理

```bash
nginx -v              # ② 查看版本
nginx -t              # ② 检查配置文件语法（修改配置后必做！）
nginx                 # ② 启动
nginx -s stop         # ② 快速停止
nginx -s reload       # ② 热重载配置（不中断服务）
nginx -s quit         # ② 优雅停止（等待请求处理完毕）
```

### nginx.conf 结构概览

```nginx
# 全局块 — 影响 Nginx 整体运行
worker_processes 1;        # ② worker 进程数（建议设为 CPU 核数）

# 事件块 — 连接处理模型
events {
    worker_connections 1024; # ② 每个 worker 最大连接数
}

# HTTP 块 — 核心配置区
http {
    include       mime.types;
    default_type  application/octet-stream;
    sendfile      on;
    keepalive_timeout 65;

    # ② server 块 = 一个网站（虚拟主机）
    server {
        listen       80;              # 监听端口
        server_name  example.com;     # 域名

        # ② location 块 = URL 路由规则
        location / {
            root   /usr/share/nginx/html;
            index  index.html;
        }
    }
}
```

> 记忆口诀：**全局设定定天下，事件监听稳如狗，http 块中藏乾坤**。
