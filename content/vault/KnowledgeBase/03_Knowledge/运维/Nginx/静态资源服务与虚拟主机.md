# Nginx 静态资源服务与虚拟主机

## 📍 知识体系定位
- **所属技术栈**：DevOps / 运维
- **所在层级**：Nginx → 静态服务层
- **上游依赖**：<a href="obsidian://open?file=核心概念与安装配置">Nginx 核心概念与安装配置</a> — 理解 server/location 块
- **下游延伸**：<a href="obsidian://open?file=反向代理与负载均衡">Nginx 反向代理与负载均衡</a> — 静态+动态分离后，动态请求走代理
- **同级技术**：Apache 静态文件服务、Caddy 自动静态站点

## 概述（Overview）
> Nginx 处理静态资源的效率远高于应用服务器（底层基于异步非阻塞 I/O，适合高并发静态文件读取）。通过在 `server` 块中配置 `root`/`alias` 指令，Nginx 可以直接将 HTML/CSS/JS/图片等文件返回给客户端，无需经过后端应用。

## 实现（Implementation）

### root 指令：路径拼接

```nginx
location /img/ {
    root /var/www/static;      # ② 根目录设为 /var/www/static
}
# ② 客户端请求 /img/logo.png → Nginx 查找 /var/www/static/img/logo.png
# ② 拼接规则：root路径 + location匹配路径 + 请求文件名
```

### alias 指令：路径替换

```nginx
location /img/ {
    alias /var/www/static/image/;  # ② ⚠️ 必须以 / 结尾
}
# ② 客户端请求 /img/logo.png → Nginx 查找 /var/www/static/image/logo.png
# ② 替换规则：alias路径 + (请求路径去掉location部分)
```

| 场景 | root | alias |
|------|------|-------|
| 作用 | 设定根目录，**路径叠加** | **替换** location 路径 |
| 路径要求 | 无特殊要求 | 目录必须以 `/` 结尾 |
| 适用 | 大多数静态资源映射 | 需重命名目录（URL 显示 /img/，实际用 /image/） |

> 简单记：`root` 是"在指定目录下追加路径"，`alias` 是"直接替换路径"。

### 虚拟主机（多站点）

**按端口区分**：

```nginx
server { listen 8081; root /var/www/blog; }
server { listen 8082; root /var/www/shop; }
# ② 访问 :8081 → blog 站点，:8082 → shop 站点
```

**按域名区分（推荐）**：

```nginx
server {
    listen 80;
    server_name blog.test;
    root /var/www/blog;
    index index.html;
}
server {
    listen 80;
    server_name shop.test;
    root /var/www/shop;
    index index.html;
}
# ② 同一 80 端口，不同域名访问不同站点
```

### 动静态资源分离

核心思路：**静态资源由 Nginx 直接返回，动态请求转发到后端应用服务器**。

```nginx
server {
    listen 80;
    server_name example.com;

    # ② 静态资源：Nginx 直接读取本地文件
    location /static/ {
        root /usr/share/nginx;
        try_files $uri =404;        # 文件不存在 → 404
    }

    # ② 动态资源：转发到后端应用服务器
    location / {
        proxy_pass http://192.168.1.101:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

> 为什么需要动静态分离？① 减轻应用服务器压力（Nginx 处理静态文件效率远高于 Tomcat/Node）；② 静态资源可配合浏览器缓存 + CDN 进一步加速。

### 前端 SPA 部署（try_files）

> 详细配置参考 <a href="obsidian://open?file=Nginx网关配置与SPA刷新问题">Nginx 网关配置与 SPA 刷新问题</a>。核心要点：

```nginx
location / {
    root /var/www/dist;
    index index.html;
    try_files $uri $uri/ /index.html;  # ② 解决 Vue/React Router History 模式刷新 404
}
# ② 逻辑：先找文件 → 再找目录 → 都没有则返回 index.html，由前端路由接管
```

### SpringBoot + Vue 全栈部署实例

```nginx
server {
    listen 81;
    server_name 124.220.90.82;

    # ② 前端静态文件
    location / {
        root /usr/local/nginx/html/staticResource;
        index index.html;
        try_files $uri $uri/ /index.html;
    }

    # ② 后端 API 代理
    location /prod-api/ {
        proxy_pass http://124.220.90.82:8081/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # ② 自定义 404/50x 错误页
    error_page 404 /404.html;
    error_page 500 502 503 504 /50x.html;
}
```
