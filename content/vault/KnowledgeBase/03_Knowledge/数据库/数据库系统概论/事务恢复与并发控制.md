## 核心概念
> 事务 ACID 是数据库可靠性的基石。恢复技术通过日志（WAL 原则）和备份应对三类故障；并发控制通过封锁机制（S 锁/X 锁）和三级封锁协议解决丢失修改、不可重复读、读脏数据三大问题。

## 一、事务 ACID 特性

| 特性 | 定义 | 破坏后果 |
|------|------|----------|
| **原子性（A）** | 事务要么全做、要么全不做 | 转账：A 扣了钱 B 没收到 → 数据不一致 |
| **一致性（C）** | 事务前后数据总额不变 | 转账前后总金额对不上 |
| **隔离性（I）** | 并发事务互不干扰，中间状态不可见 | 读到其他事务未提交的数据 |
| **持续性（D）** | 提交后数据永久保存，崩溃不丢失 | 断电后数据回退 |

> 事务是数据库**恢复**和**并发控制**的基本单位。

---

## 二、三类故障与恢复策略

| 故障类型 | 原因 | 影响范围 | 恢复策略 |
|----------|------|----------|----------|
| **事务故障** | 运算溢出、死循环、违反约束 | 单个事务 | **UNDO**（由系统自动完成）|
| **系统故障** | 断电、OS 崩溃、DBMS 崩溃 | 所有未提交事务 | **UNDO 未提交 + REDO 已提交** |
| **介质故障** | 硬盘损坏 | 整个数据库 | **重装备份 + REDO 日志**（需 DBA 介入）|

### 恢复步骤（以介质故障为例）
```
1. 装新硬盘
2. 恢复最近全量备份
3. 恢复增量/差异备份
4. 用日志 REDO 所有已提交事务
```

## 三、日志文件（WAL 原则）

> **Write-Ahead Logging（先写日志后写数据库）**

```
事务 T 修改 Grade: 80 → 90

执行顺序：
  ① 写日志：<T, UPDATE, SC, Grade, 80, 90>
  ② 写数据库：将 SC 表中对应记录的 Grade 改为 90

原因：
  - 若写数据库失败 → 日志中可 UNDO
  - 若写日志失败 → 事务直接中止，无风险
```

### 备份类型对比

| 备份类型 | 定义 | 优点 | 适用场景 |
|----------|------|------|----------|
| **全量备份** | 备份整个数据库 | 恢复最简单 | 夜间非高峰 |
| **增量备份** | 备份上次备份后修改的数据 | 备份快、体积小 | 白天频繁更新 |
| **差异备份** | 备份上次全量备份后修改的数据 | 恢复比增量快 | 更新频率中等 |

## 四、并发三大问题

| 问题 | 定义 | 实例 |
|------|------|------|
| **丢失修改** | 两事务同时修改，后提交的覆盖先提交的 | T1 改 A 为 90，T2 改 A 为 80，T1 提交 → T2 的修改丢失 |
| **不可重复读** | 同一事务内两次读同一数据，结果不同 | T1 第一次读 A=100，T2 改 A=200 并提交，T1 第二次读 A=200 |
| **读"脏"数据** | 读到其他事务未提交的修改，后该修改被回滚 | T1 改 A=200（未提交），T2 读 A=200，T1 回滚 |

## 五、封锁机制

### S 锁 vs X 锁

| 锁类型 | 作用 | 兼容规则 |
|--------|------|----------|
| **S 锁（共享锁）** | 允许读，禁止其他事务写 | 与 S 兼容，与 X 冲突 |
| **X 锁（排他锁）** | 允许写，禁止其他事务读写 | 与 S、X 都冲突 |

```
兼容矩阵：      请求 S 锁 | 请求 X 锁
持有 S 锁         ✅          ❌
持有 X 锁         ❌          ❌
```

### 三级封锁协议

| 级别 | 规则 | 解决 | 未解决 |
|------|------|------|--------|
| **一级** | 写操作加 X 锁，事务结束释放 | 丢失修改 | 不可重复读、读脏数据 |
| **二级** | 一级 + 读操作加 S 锁，读完立即释放 | 丢失修改、读脏数据 | 不可重复读 |
| **三级** | 一级 + 读操作加 S 锁，事务结束释放 | **全部三类问题** | 无 |

## 六、两段锁协议

> 保证并发调度可串行化的充分条件

**规则**：事务分为"加锁阶段"（只加不解）和"解锁阶段"（只解不加）。

```
✅ 合规：加 S 锁读 A → 加 X 锁改 A → 解锁 S 锁 → 解锁 X 锁
❌ 违规：加 S 锁读 A → 解锁 S 锁 → 加 X 锁改 A（加锁阶段解锁了！）
```

## 七、死锁

### 产生四条件（缺一不可）
1. **互斥**：锁资源不可共享
2. **持有并等待**：持有锁的同时等待其他锁
3. **不可剥夺**：不能强制抢锁
4. **循环等待**：T1 等 T2，T2 等 T1

### 处理策略
| 策略 | 做法 |
|------|------|
| **预防** | 破坏四条件之一（如"一次封锁法"：一次申请全部所需锁） |
| **诊断** | **等待图法**：节点=事务，边=等待关系，有环→死锁 |
| **解除** | 选代价最小的事务撤销（执行时间最短/修改最少的事务）|

---

## 八、检查点技术

| 方面 | 说明 |
|------|------|
| **概念** | 将内存脏数据强制写回磁盘并记录系统状态，类似数据库"快照" |
| **优点** | 恢复时只需从最近检查点处理事务，大幅缩短恢复时间 |
| **缺点** | 建立检查点涉及磁盘 I/O，影响正常性能；增大日志文件 |
| **适用** | 高可用性系统（银行交易、电商订单）、大数据量系统 |
