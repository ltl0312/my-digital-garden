## 核心概念
> 数据库设计遵循"需求分析→概念设计→逻辑设计→物理设计→实施→维护"的六阶段流程。E-R 图是概念设计的核心工具，通过实体/属性/联系三大要素精确描述现实世界的数据语义。

## 一、数据库设计六阶段

| 阶段 | 核心任务 | 输出物 |
|------|----------|--------|
| 1. 需求分析 | 收集用户需求（数据/功能/安全） | 需求规格说明书 + 数据字典 |
| 2. 概念结构设计 | 将需求转化为 E-R 图 | E-R 图（标注主码、联系类型） |
| 3. 逻辑结构设计 | E-R 图转关系模式（适配 DBMS） | 关系模式集（含完整性约束） |
| 4. 物理结构设计 | 确定存储结构、索引、存取路径 | 物理设计说明书 |
| 5. 数据库实施 | 建库、建表、导数据、编程序 | 可运行的数据库系统 |
| 6. 数据库维护 | 备份、优化、故障修复 | 维护日志、优化报告 |

## 二、E-R 图绘制规范

### 核心元素

| 元素 | 绘制符号 | 说明 |
|------|----------|------|
| **实体** | 矩形框 | 强实体用单矩形，弱实体用双矩形 |
| **属性** | 椭圆形框 | 主码加下划线，多值属性用双椭圆，派生属性用虚线椭圆 |
| **联系** | 菱形框 | 标注联系类型（1:1 / 1:N / M:N） |

### 示例：学生选课系统 E-R 图
```
  ┌─────────┐                     ┌─────────┐
  │  学生   │                     │  课程   │
  │ Sno(主) │──M────────◇────────N──│ Cno(主) │
  │ Sname   │    ┌──选课──┐      │ Cname   │
  │ Sdept   │    │ Grade  │      │ Credit  │
  └─────────┘    └────────┘      └─────────┘
                                      │
                                      │ N
                                      ◇
                                   ┌─授课─┐
                                      │ 1
                                   ┌─────┐
                                   │ 教师 │
                                   └─────┘
```

## 三、E-R 图转关系模式（5 大核心规则）

| 元素 | 转换规则 | 示例 |
|------|----------|------|
| **非弱实体** | 实体 → 表，属性 → 列，主码 → 表主码 | 学生实体 → `Student(Sno, Sname, Sdept, Sage)` |
| **M:N 联系** | 联系 → **独立表**，含双方主码 + 联系属性，双方主码组合为主码 | 选课 → `SC(Sno, Cno, Grade)`，`(Sno, Cno)` 为主码 |
| **1:N 联系** | 合并到 **N 端表**，加 1 端主码为外码 | 教师-课程(1:N) → Course 表加 `Tno` 外码 |
| **1:1 联系** | 合并到**任一表**，加对方主码为外码（优先选属性少的表） | 学生-学生证(1:1) → Student 表加 `CardNo` 外码 |
| **弱实体** | 弱实体 → 表，含自身属性 + 强实体主码，组合为主码 | 成绩单 → `Score(Sno, ReportNo, IssueTime)` |

## 四、isa 联系转换（继承关系）

isa 联系表示"继承关系"（如学生 isa 本科生/研究生），有三种策略：

| 策略 | 做法 | 说明 |
|------|------|------|
| **E-R 方式** | 每个实体建表，子表含父主码 + 自身属性 | 学生表 + 本科生表(Sno, Grade) + 研究生表(Sno, Thesis) |
| **面向对象方式** | 子类树建一张表，含所有属性 | 学生表含 Grade, Thesis 字段，用 NULL 区分 |
| **空值法** | 父类表含所有子类属性 | 本科生 Thesis=NULL，研究生 Grade=NULL |

## 五、物理结构设计关键决策

| 决策点 | 参考因素 |
|--------|----------|
| 聚簇索引选哪列 | 主码、频繁范围查询列 |
| 非聚簇索引建哪些列 | 外码、WHERE 高频过滤列 |
| 禁止建索引的情况 | 低选择性列（<20%）、频繁更新列、小表 |
| 分区策略 | 按时间/地区/业务线拆分大数据表 |

---

## 六、易错点总结

| 易错点 | 正确做法 |
|--------|----------|
| E-R 图联系类型误判 | 1:N 和 M:N 关键看业务规则（如"1 课程仅 1 教师教"→ 教师-课程是 1:N） |
| 转关系时遗漏联系属性 | M:N 联系的独立表中必须包含联系属性（如选课的 Grade） |
| 优化漏用范式 | 转出的模式用范式检查，消除冗余和异常 |
