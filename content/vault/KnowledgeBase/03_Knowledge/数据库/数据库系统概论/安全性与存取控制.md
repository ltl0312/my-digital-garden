## 核心概念
> 数据库安全是分层防护体系（物理→系统→网络→数据库→应用）。DBMS 层通过"身份鉴别→存取控制→审计→加密"四重机制保障数据安全，其中自主存取控制（DAC）和强制存取控制（MAC）是两大核心手段。

---

## 一、安全控制层次

| 层次 | 手段 |
|------|------|
| 物理层 | 服务器机房门禁、硬件防护 |
| 系统层 | 操作系统用户权限管理 |
| 网络层 | 防火墙、VPN（防网络监听） |
| 数据库层 | DBMS 安全机制（授权、审计、加密） |
| 应用层 | 密码哈希存储、输入校验 |

---

## 二、安全控制模型

```
事前控制 → 身份鉴别 + 入侵检测
事中控制 → SQL 处理层多层访问控制
事后控制 → 配置审计规则，对用户行为和关键操作审计
存储保护 → 敏感数据加密存储
传输保护 → SSL/TLS 传输加密
```

## 三、用户身份鉴别

| 方式 | 说明 | 安全级别 |
|------|------|----------|
| 静态口令 | 固定密码（如 MySQL root 密码） | 低 |
| 动态口令 | 每次登录生成不同口令（如手机验证码） | 中 |
| 生物特征 | 指纹、人脸识别 | 高 |
| 智能卡 | 硬件卡 + 密码（银行系统常用） | 高 |

## 四、存取控制：DAC vs MAC

### 自主存取控制（DAC）—— C2 级
- 用户对不同数据对象有不同的存取权限
- 不同用户对同一对象也有不同权限
- **用户可将其拥有的权限转授给其他用户**

### 强制存取控制（MAC）—— B1 级
- 每个数据对象被标以一定**密级**
- 每个用户被授予一定级别的**许可证**
- 只有合法许可证的用户才能存取对应密级的数据
- **真正意义上的安全产品**

## 五、授权与回收（DCL）

### 创建用户
```sql
-- 超级用户
CREATE USER system2 WITH SUPERUSER PASSWORD '88888888';

-- 具有创建数据库权限的用户
CREATE USER U1 WITH CREATEDB PASSWORD '密码';

-- 普通用户
CREATE USER U2 PASSWORD '密码';
```

### 权限速查表

| 权限类型 | 权限名                                    | 作用范围  |
| ---- | -------------------------------------- | ----- |
| 数据访问 | `SELECT`, `INSERT`, `UPDATE`, `DELETE` | 表/列   |
| 结构修改 | `CREATE`, `ALTER`, `DROP`              | 数据库/表 |
| 管理   | `GRANT OPTION`, `ALL PRIVILEGES`       | 全局    |

### GRANT（授权）
```sql
-- 授予查询和插入权限，并允许转授权
GRANT SELECT ON Student, INSERT ON SC TO U1 WITH GRANT OPTION;

-- 列级授权（仅允许更新自己的成绩，结合视图）
GRANT UPDATE(Grade) ON U2_SCGrade TO U2;
```

### REVOKE（回收）
```sql
-- 回收插入权限，级联回收 U1 授予他人的权限
REVOKE INSERT ON SC FROM U1 CASCADE;

-- 回收所有用户对 Course 表的查询权限
REVOKE SELECT ON Course FROM PUBLIC;
```

> **CASCADE**：级联收回授予的权限；**RESTRICT**（默认）：如果权限已被转授则拒绝收回。

## 六、数据库角色

> 角色是权限的集合，为一组相同权限的用户创建角色，可以简化授权过程。

```sql
CREATE ROLE <角色名>;
GRANT SELECT, INSERT ON Student TO <角色>;
GRANT <角色> TO <用户> [WITH ADMIN OPTION];    -- 将角色授予其他角色或用户
REVOKE <权限> ON <对象> FROM <角色>;          -- 回收角色权限
```

## 七、审计

**定义**：记录用户对数据库的所有操作，便于追溯安全事件。

| 审计要点 | 说明 |
|----------|------|
| 审计事件 | 登录、数据操作、结构修改、权限变更 |
| 功能要求 | **C2 以上安全级别必须支持审计** |
| 性能影响 | 很耗费时间和空间 |
| 日志保护 | 先转储后删除，只允许审计员查阅和转储 |

```sql
-- MySQL 开启审计
SET global general_log = ON;
SET global general_log_file = '/var/log/mysql/audit.log';
```

## 八、TCSEC/TDI 安全级别标准

```
D级（最低）
C1级（DAC）
C2级（DAC + 审计） ← MySQL、SQL Server 在此级别（安全产品最低档）
B1级（MAC）       ← Oracle Label Security 在此级别（真正安全产品）
B2级（DAC + MAC）
B3级
A1级（最高）
```

## 九、数据加密

| 加密类型 | 说明 |
|----------|------|
| 存储加密 | 磁盘数据加密（如 InnoDB 表空间加密） |
| 传输加密 | SSL/TLS 协议防中间人攻击 |
| 密码存储 | 不存明文，用 SHA256 等哈希算法 |

```sql
-- 密码哈希存储
INSERT INTO User(UserName, Password) VALUES('zhangsan', SHA2('123456', 256));

-- 登录验证
SELECT * FROM User WHERE UserName = 'zhangsan' AND Password = SHA2('123456', 256);
```
